# GeneLoop PPT 运行规则 v1

以下规则适用于工具列表包含 `prepare_ppt` 和 `finalize_ppt` 的 GeneLoop Generate 任务。其他场景调用此 Skill 时沿官方流程执行。官方 ppt-master 6.6.0 仍提供设计、原生对象与导出实现。此运行规则覆盖上游的整页手写、逐个导出命令和额外诊断安排。

- 完成内容规划和 `spec_lock.md`、`design_spec.md` 后调用 `prepare_ppt(project)`。宿主按当前角色、计划文字与实际字体环境完成常规/粗体校准，返回可复用的测量表。默认采用 Noto Sans CJK SC，标题约32pt、正文22pt、次级18pt、来源12pt。用户指定的字体与模板优先。字体不可用时根据工具的具体诊断处理。
- 已认证页面程序允许直接生成完整 SVG。目录中的适用程序通过 `create_ppt_page` 调用，可同时传入项目和页面文件名，由宿主安装到 `svg_output`。接口与容量覆盖当前页面时，按其约束填入内容，跳过手写 SVG 和原生形状绘制资料的重复阅读。内容规划、来源核对与成品检查照常执行。备注与科学解释仍由你编写。参数或版式不适用时使用普通制作路径。
- 组件页面出现明确的文字容量问题时，优先缩短当前内容参数并再次调用 `create_ppt_page`，同时传入当前项目页的 `expected_page_sha256`。工具按版本替换该页并保留来源。初次安装回执及后续交付回执提供页面SHA，手动修改后须读取当前版本。确定版式不适用再进入普通制作路径。
- 制作阶段使用校准表估算文本容量。字体清单、逐字测量、DPI/字符框相交推测、导出器源码调试由宿主诊断处理。普通任务中禁止重复执行这些诊断。新内容超出容量时先调整布局或分页。
- Generate 完稿调用 `finalize_ppt(project)`。宿主生成页面清单，执行官方门禁、PPTX、Office PDF 和逐页 PNG。直接 Bash 导出由宿主管理。需要原生 PPTX 往返编辑时继续相应官方路线。
- 项目页面的预览沿 `finalize_ppt` 的 Office PNG 检查。页面制作后直接准备备注并导出，独立 CairoSVG/rsvg 栅格化与反复更换 DPI 的预览交给宿主处理。原论文图件提取仍按来源处理。
- 使用 `read_image` 查看实际导出页面。只有明确可见缺陷、工具报告的具体错误或用户新反馈才启动修订。记录页面、对象与问题。PDF 字符框相交、字体 ascent/descent 和 DPI 差异不单独构成缺陷。warning 只在影响当前交付时处理。
- 相同文件与环境版本复用已完成的校准和检查。通过后直接交付；修订后检查改变的页面。同一缺陷未改善时按具体回执处理，避免重复猜测坐标、字体与缩放。
- 最终下载必须来自当前项目有效的 `finalize_ppt` 回执。内容、原图、数值、单位和引用仍须按来源核对，机械通过不代替事实与视觉评审。
