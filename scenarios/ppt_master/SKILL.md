# GeneLoop Presentations

Scope: create and edit PPT, then inspect PDF/page-image previews before delivery. Do not start narration/audio generation, TTS, presentation-video export, soundtrack mixing or video subtitles. Upstream references may mention those optional stages; they are outside this scene. Speaker notes are optional text inside the PPT, not an audio-production step. Standalone speechwriting belongs to ordinary chat.

Use the user's audience, purpose, content, template and visual preferences to plan the presentation. A topic and desired outcome are sufficient to start. Choose reasonable defaults for unspecified presentation details and state significant assumptions at delivery. Ask together for missing facts that determine the content.

Prioritize a complete usable deck before optional decoration. Use uploaded and already available sources first. External asset retrieval is bounded to eight attempts and 90 seconds of asset phase; do not write crawlers, background image-search scripts or retry loops. If optional web images are unavailable, use supplied/local assets or accurate text/diagrams and finish the deck. Never fabricate a mandatory scientific figure or claim an unmet requirement is complete. Use prepare_ppt_asset for local image crop/resize/copy. A valid current host export is automatically available to delivery; optional searching, subjective polishing, Judge and learning must not delay it.

Use `read_ppt_design` to browse compact theme cards or inspect a theme or certified component contract. Select a suitable design once. For build_ppt, choose the theme ID from compact cards; the native_json section lists its layouts and languages. The top-level layouts/content_limits describe compose_ppt_page only. Do not read full colors or typography to fill a content-only plan. When `build_ppt` is offered and the content fits its supported layouts, submit the complete structured plan once: title, slides, sources, optional notes and theme. Its execution layer creates editable objects and the current PDF/PNG previews without separate start/prepare/finalize calls. Table continuation counts toward the requested slide count; use strict_slide_count when the count is mandatory. Preserve original values and literal formulas; no silent truncation or invented sources. This is shared engineering, not a learned Motif.

An adopted `native_json` project stays on `patch_ppt(project,expected_revision,edits)` with stable slide IDs. Revision 0 is valid. Submit only changed fields; other pages and notes remain. Empty edits read the current version and reuse or retry its export after a rendering failure. Keep the current project instead of trying a component and then recreating the deck. External Office edits are preserved and use the native-PPTX route; JSON does not import them. Read only unseen current preview pages, then present the returned artifacts. Judge and learning stay in the background. For unsupported detailed layouts or scientific diagrams, choose the SVG path before committing: `start_ppt` creates that project. User templates and existing decks follow the original-PPTX route below. Tools absent from a desktop host are not available; do not install packages or start MCP services to emulate them.

For the `managed_svg` route, write the content outline into `design_spec.md`, then call `prepare_ppt(project)` for actual regular/bold font measurements. Compose SVG pages in the returned project directory. Reuse an applicable certified page with `create_ppt_page`, supplying current content parameters and a page filename. The host installs the page and records its version. Keep requested speaker-note text under `notes/` without converting it to audio.

Use `compose_ppt_page` for ordinary covers, sections, bullet pages, two-column comparisons, image/text pages, bar charts and closing pages. Supply current content and notes. Once a native page is adopted, keep this authoring path: revise that page with its current SHA, and complete the other pages without rebuilding successful pages in scripts. Bash cannot bulk-rewrite adopted pages. The host measures text with the installed font and rejects capacity overflow; shorten the reported paragraph or choose a wider layout. Do not solve it by importing font-measurement libraries or rewriting the deck. This shared foundation applies in both comparison modes. For a supplied template or detailed visual choices, read the compact guide with `read_ppt_design(guide=true)`.

When this task exposes a certified continuous program, use its exact mode and page scope. Once the current page contents and components are decided, pass the complete supported batch to `execute_ppt_program` using `pages`; the PPT execution layer writes those pages and notes, exports once and returns the current previews. Do not first try each component and then rebuild the same pages. A single-page program does not authorize an unseen multi-page loop. Keep content/design decisions outside the compiled span; supply missing content before execution. If no program applies, use the ordinary tools. Repair only a reported defect or an explicit user change, preserving successful pages and notes; return control for unsupported requirements.

For an already delivered deck, a matching certified single-page `compose_ppt_page` or `create_ppt_page` revision is continued automatically by the host. Its result contains `continued_by`, `execution_status`, delivery and previews. Review the returned images and present those files; do not export again. This uses the certified observed span, not a new hard-coded authoring recipe. Multi-page programs still require the complete batch explicitly; they are not silently treated as single-page certificates.

For a simple labelled numerical bar chart, use the built-in `bar_chart` layout with the current source values. It computes a common baseline, bar heights and tick positions together. Do not independently hand-code those three quantities. For unsupported charts, use one shared numerical scale function and verify ticks and bars against that function. A visually tidy chart with inconsistent scales fails factual acceptance.

For `managed_svg`, call `finalize_ppt(project)` for font and format checks, editable PPTX export, Office PDF and page PNGs. Assess images already included in the tool result directly; call `read_image` only for review pages not yet supplied. An unchanged image reference reuses the same pixels, not a quality verdict. Component scratch PNGs are not Office previews: finish the initial pages and review their Office output together. Repair concrete findings on affected pages. Reuse unchanged checks. Present the returned artifact paths directly; copying, renaming and repeating native-object diagnostics are unnecessary.

`finalize_ppt` registers the checked manuscript and exported bytes once. `present` checks that content version and the selected files; it does not repeat project/runtime certification or quality review. A source, source-asset, notes or page-list change requires a new export; timestamps, scratch files and diagnostic reports do not. If an optional PNG is missing or not current, the host omits it with a notice and delivers the valid requested PPTX/PDF. Do not re-export the deck to recover an optional enlargement. An invalid or stale main deck remains an error.

For a specific region that needs closer visual inspection, call `inspect_ppt_region` with the current exported PNG path and a pixel crop. It returns the cropped/enlarged image directly without changing the deck. Do not write Python image scripts. Literal image copies from `/work/outputs` into the conversation's `/tmp` are allowed when needed; they do not authorize project edits. A started or modified deck is incomplete until a current successful export supplies PPTX, PDF and page PNGs; a verbal plan or component execution alone is insufficient. Pure discussion or a speech draft does not require a new deck.

This loaded skill already contains the integrated workflow. Do not load `read_skill_entry` again just to repeat it. Reuse the source-reading index for orientation; read the original source where a specific fact or figure needs verification. Do not re-extract the whole paper after every page change.

The host handles font resolution, calibration, file installation, export and mechanical diagnostics. Content interpretation, visual communication and factual accuracy remain model decisions. Treat warnings according to their visible effect and the user's requirements. A stalled repair requires a different effective method or the ordinary authoring fallback.

When the user has authorized autonomous completion, continue a reversible layout repair within that task. Ask for missing scientific facts or a consequential user preference when needed. Choose ordinary technical recovery steps such as correcting paragraph placement directly.

Use the prepared role rates for manual SVG text placement. If text is too dense, shorten it or choose another page structure. Direct text_measure imports, module inspection, per-string font experiments and repeated font diagnostics duplicate the host work. Reference documents provide drawing syntax and design examples. Their older operational calibration or export instructions are superseded by prepare_ppt and finalize_ppt.

## References for specific work

The integrated engine uses the pinned modules under `/opt/geneloop/ppt-master`. Read only the reference required by the current operation.

- For a genuinely unsupported shape, table or formula, use the compact SVG guidance returned by `read_ppt_design(guide=true)` and directly write a new independent SVG page. Keep already adopted native pages. Do not reload upstream `executor-base.md` or `executor-notes.md` as an operational workflow: their font checks, width experiments and stepwise export do not apply to this integrated host.
- For text replacement, title capitalization, paragraph alignment or font-size changes in an existing PPTX, use `edit_ppt_native`: inspect once, then apply a batch to exact page/shape IDs with current text and source SHA. It preserves unselected OOXML parts and notes, and returns PPTX/PDF/page previews. Do not reimport or rebuild a successfully edited deck to repeat these checks. Use the original SVG roundtrip reference only for unsupported complex visual restructuring. Treat input files as immutable.
- For a reusable template workspace, read `workflows/create-template.md` when needed.
- For original document conversion, use the source tools and the pinned converter. Source figures, numbers and citations retain their provenance.

GeneLoop owns the task lifecycle, execution permissions, review policy and recovery. Optional design review is a separately metered background activity. Record source-supported facts and clearly label illustrative data or proposed plans. PPT reuse and learning concern authoring, editing, export and preview operations within the scope above; do not extend them into media-production workflows.

Normal users receive one optimized Agent result and continue editing it in chat. Baseline comparisons and scoring are internal evaluation features. Model scoring is explicitly enabled by the internal review policy, never a requirement for downloading a deck. Host file operations handle recognized output-only copying and listing sequences without executing shell code; present current artifacts directly whenever possible.
