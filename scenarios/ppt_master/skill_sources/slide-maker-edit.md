# Template-derived pages and local edits — GeneLoop adaptation

Source: slide-maker, commit 98d5eb294dfeca841475af86248831ede8f551fc.
This reference contributes editing and reuse guidance, not a prescribed Motif.

Identify the template's typography, geometry, palette and repeated content
roles once. Distinguish reusable layout from the previous author's text/data.
Use the same visual system for current content, without copying example claims.
Choose layouts to express the message rather than filling every available box.

For a supplied SVG page, preserve its shape geometry and edit the requested
text/data; for an existing native PPTX, use its object-aware editing route.
Record the version actually read. A feedback turn names the affected pages and
fields; keep unrelated pages/notes and reuse their existing previews.

read_ppt_design exposes available theme/component contracts. compose_ppt_page
and create_ppt_page are the supported native/learned page tools where suitable;
they do not prove arbitrary PowerPoint template compatibility. finalize_ppt
performs the supported shared delivery checks. Inspect returned images directly
and use read_image only for images not supplied. Repair a concrete defect on its
affected page and stop after the requested change is delivered.

Adaptation: the source's independent critic, arbiter, design interviews, mandatory
image backgrounds and signature effects are not imported as production gates.
GeneLoop keeps optional background Judge/learning separate from production.
Do not require a second authoring backend, install another Agent stack, rewrite
successful pages, or attach generated raster plates to an editable template.
An unsupported request is reported honestly, with its failure evidence retained.
