## 新增链路的验收要求

1. **真实来源**：保存原任务、原生调用、代码源码、参数、结果及摘要。必须核验源码确实由该次普通任务产生并实际成功执行。源码编译器或手写模板本身不是自主发现的证据；没有执行见证的候选保留未激活。
2. **参数化**：绑定当前文件清单、目录、范围和规则；验证文件增减、路径变化和内容变化。训练路径、临时ID和旧结果不得作为新任务默认答案。已学脚本允许组合，但来源与依赖分别记录。
3. **独立认证**：候选和验收先冻结，使用训练之外的新材料，包含新普通原生见证与至少两次候选实际执行，再加有关版本、输入、权限、空／损坏内容和中断的负例。原最终评测材料不进入学习或认证。
4. **统一入库**：与局部图纳入同一账号的长期经验管理，记录类型、来源、父版本、环境、工具schema、读写效果、证书及失效状态。不可变版本与原子激活沿用，进行中的任务冻结自己的库版本。
5. **自动复用**：根据新任务目标、实际工具、权限及当前文件状态检索与绑定；不能按题号或 `profile_id` 指定正确脚本。材料或契约不匹配时保留原因并普通执行。
6. **执行隔离**：复用项目已有受控执行器和工具权限，源码不在宿主在线解释器中任意求值。写操作仍经相同计划、确认及恢复收据；脚本不取得模型凭证，也不扩大用户授权。
7. **实际开销**：分别计量模型HTTP、结构步数、工具调用、解析次数、读取字节／分块、重复读取、上下文输入及端到端时间。包装脚本、减少事件数或少读未完成，均不能单独作为收益证明。
8. **输出与证据**：读取脚本提供新结果、来源位置和实际覆盖记录。检索可返回必要命中及证据引用；全文分析仍需足够内容。摘要不能代替未读取的正文，缓存须校验当前版本。
9. **失效与恢复**：检查当前工具契约、执行环境、输入版本与权限；效果不符交回普通 Harness。恢复前核对代码／文件已有效果和认证回执，避免重复写入、重复认证付费或重置预算。
10. **持续升级**：第一版脚本实际参与新任务，普通残余／回退轨迹可产生第二版候选，经新材料认证后激活，再在新任务中实际命中。脚本数量或版本号增加不是闭环完成的证明。
11. **完整保留**：旧库、源码、候选拒绝、执行失败、修复、恢复、认证和逐请求费用均保留。公共发布只包含允许公开的脱敏内容，不自动上传私有源码或轨迹。
