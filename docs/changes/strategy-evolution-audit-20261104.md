# GeneLoop 演化机制全链审计与后续设计

审计日期为 2026-11-04。本次交付是代码审计与设计建议。下文的“建议”与“验收条件”属于待实施方案。

## 1. 结论

GeneLoop 已有可复用的递归图学习、编译、认证、版本管理、成本计量与反馈组件。当前最重要的工作是接通这些组件之间的数据流，让后继任务和 Builder 真正使用演化成果，再把实际结果送回下一轮演化。

当前有八组关键缺口。

1. 普通任务与构造过程尚未自动成为可用的演化证据。
2. Evolution 的紧凑上下文会丢失部分构造错误、费用范围与上一代策略内容。
3. 独立策略评价仍依赖宿主回调，缺少可直接运行的通用评价宿主。
4. 已准入策略需要人工复制配置，才能进入后继任务或 Builder。
5. 任务看到的 Capability 引用尚缺通用可调用映射，使用证据也需补齐。
6. 任务与 Builder 的使用、质量、成本尚未完整回到同一轮反馈。
7. 策略产生的稳定执行片段尚未自动送回原 Motif 学习器。
8. Builder 自应用已有受限接线，真实自主学习与后继使用证据仍不足。

优先顺序应是接通一次完整的演化与继承，再接稳定片段的再抽象，最后扩大 Builder 自应用范围。任务场景扩展、复杂奖励和自动再投资可以后置。

## 3. 方法需要形成的闭环

目标循环为 `Experience → Pressure → Evolve → Verify → Inherit`，其中执行能力继续遵循 `Separation → Abstraction → Recomposition → Evolution`。

演化成果有三种形式。

| 成果 | 改变的内容 | 后继采用方式 |
| --- | --- | --- |
| 新的可执行能力 D | 将真实轨迹中的稳定局部工作封装起来 | 作为普通 Capability 进入执行图及后续学习 |
| 新边界或表示 C′ | 拆分、合并或重新表达旧抽象，改善接口与组合方式 | 经原 learner、编译与认证成为新版本 |
| 条件化决策策略 S | 改变任务分解、能力选择、组合、核验或修复方式 | 经宿主准入进入任务或 Builder 的有限上下文 |

开放判断由模型完成。Runtime 接管有明确输入、适用条件和有效证据的局部工作，返回结果及回执。模型默认只需看到能力的语义接口、适用条件、结果和必要限制。内部图、叶实现与完整历史按审计需求展开。

策略的作用是改变下一次实际决策。仅保存建议文本、增加谱系指针或提高分数，均不足以完成这条链。

```text
普通任务与真实 Builder 构造
    ↓ 原事件、请求、回执、质量与费用引用
有界跨任务证据与剩余求解负担
    ↓ 原 Evolution 提案入口
能力 / 边界 / 条件化策略候选
    ↓ 原 Builder、learner、认证与独立评价
研究范围内可继承的新版本
    ↓ 宿主选择交接，任务开始时冻结版本
后继任务与后继 Builder 的实际行为
    ├── 结果、反例、完整成本 → 同一反馈与下一轮证据
    └── 可学习的稳定执行片段 → 原 learner → 新能力
```

新能力可能帮助未来出现的新需求，也可能降低已有任务的构造负担。压力发现应覆盖成功、失败和反例。过去失败只是一类证据，候选与评价任务之间的可解决性仍须独立判断。

## 5. 八组核心缺口及最小设计

### G1 自动形成真实 Experience

**现状。** 论文任务依靠 `scripts/observe-capability-paper-tasks.py` 显式观察。`record_web_decision`、`record_construction_decision` 已有记录接口，普通任务结束后缺自动调用链。策略研究 CLI 仍依赖手工准备 observations。构造反馈在开关启用时能够采集，尚未统一进入后续演化输入。

**建议设计。**

- 在原任务终态与原构造终态写入轻量索引，只引用原 task、events、effective、result、request ledger 与质量证据。
- 沿原学习队列或研究入口处理这些引用，建立 Evidence Packet。任务结束时只做持久化交接，模型演化由后续显式研究轮次调度。
- 使用 owner、原始决定身份、来源哈希和原任务关系去重。同一任务的重试、续写和重新命名保留为同一来源的经历。
- 每次处理保存输入引用与处理状态，重复扫描能够恢复，避免重复收费、重复入池或把重复样本视为独立任务。
- 用户修订、独立评审和反例引用通过原结果体系追加，任务终态与质量结论分别保存。

**验收。** 完成一批普通任务及 Builder 构造后，通过原研究入口能找到对应证据。无需手写新的观察清单。失败、取消、质量未知和同源重试均可重建。

### G2 有语义、可追溯且有限的 Pressure 上下文

**现状。** `capability_evolution_agent.py` 的 `model_view` 保留图与类型，默认去除描述等语义。PR135 增加宿主批准的语义投影，但批准来源、构造诊断和历史策略仍未完整贯通。`_construction` 生成的顶层 `construction_outcomes` 未进入模型视图，`cost_attribution` 也未随费用传入。

**建议设计。** 每轮只处理一个局部问题，输入包含以下内容。

| 内容 | 生成方式 | 约束 |
| --- | --- | --- |
| 当前能力卡 | 原认证能力接口与宿主批准的语义描述 | 给模型足够的功能信息，内部实现按需读取 |
| 支持与反例 | 不同来源的代表性成功、失败与独立评审 | 同时保留各类记录数量和省略信息 |
| 构造诊断 | 从原检查结果确定性投影阶段、位置、错误与已通过检查 | 模型解释单独标注 |
| 剩余工作 | 可观测的重复决策、接口工作及未解决需求 | 推断原因标为假设 |
| 成本范围 | 已知数值、覆盖阶段、未知项及账本引用 | 局部请求费保持其局部口径 |
| 上一代策略 | 当前研究选择的有限策略内容及采用结果 | 指针与策略正文共同进入上下文 |

聚合先使用确定性身份、能力与阶段事实，再让模型提出共同原因。优先考虑有多个独立任务支持的问题。单例保留为待积累假设。已知负担、质量影响和证据可靠性参与排序，未知费用保留探索资格。

默认投影设置明确总量上限，并记录被省略的引用。按需读取也进入原调用与费用记录。语义投影的生成者、版本和允许发送范围须可追溯。具体 Token 上限通过首轮真实记录确定。

另需修复当前引用整个 `comparisons.json` 的方式。应冻结单个决定的来源关系证据，避免无关追加使旧证据失效。

**验收。** 原始构造错误、费用范围和旧策略都出现在模型实际输入中。超量输入确定性选择代表记录。反例可进入视图，完整原始记录始终可追溯。

### G3 候选真实独立评价

**现状。** `scripts/run-strategy-evolution.py` 调用宿主 `evaluate_strategy`。协议能够检查评价结果与引用，但仓库缺少可直接用于真实后继任务的统一评价宿主。当前成功回调测试说明协议可运行。

**建议设计。**

1. 宿主冻结评价目标、输入版本、权限、质量标准和比较条件。
2. 原 Task 或 Builder 在隔离研究配置中分别执行原方案与候选方案，记录候选实际暴露和采用证据。
3. 原检查器或独立评审评价质量，失败与修复保留。
4. 原账本汇总提案、检索、学习、验证、修复、失败及后继运行费用，分别报告一次性投入与运行成本。
5. 质量合格但收益未知的成果保留研究试用状态。取得可比较收益证据后，宿主才允许其成为对应研究范围的默认选择。

发现用经历与评价任务应区分来源身份。首次冒烟可以重放发现样本检查实现，对外效果评价使用独立任务。实际账单、人工修订和维护未知时逐项保留未知。

**验收。** 一个真实候选进入原执行器，独立质量结果可重建，评价记录可证明候选确实进入该次任务或构造。对照费用包含失败尝试，评价标准由宿主控制。

### G4 验收结果自动交接到后继选择

**现状。** Evolution 返回策略 selection。Builder 从 `source_catalog.inherited_strategy` 读取，任务草稿也读取显式研究配置。两者之间仍需人工复制。上一代策略引用已支持，模型输入未完整提供其内容和反馈。

**建议设计。**

- 在原研究计划或现有 catalog 中保存当前选择引用，沿已有 owner、target、scope 区分采用范围。
- 独立评价通过后，由宿主执行一次持久化交接，保留旧选择、新选择、评价引用及父代关系。
- 更新使用原有锁或等价的条件更新机制，校验预期父版本。并发演化冲突时保留候选等待重审。
- 下一个任务或 Builder 开始时冻结该选择。策略摘要与精确版本进入原有效配置，完整内容留在原 sidecar。
- 被撤回版本作为历史仍可用于诊断，后继修复产生新版本并重新评价。历史读取与使用准入采用各自的检查。

首版建议每个研究范围只采用一个策略，后续有冲突证据时再增加多策略选择。

**验收。** 演化得到的准入结果能自动进入下一次真实任务或 Builder。人工无需搬运 selection 或 parent 指针，关闭开关和回退均可复现。

### G5 后继任务可调用能力，并记录实际采用

**现状。** 未提交的 TypeScript 草稿可以读取和冻结策略、准备 Prompt、记录部分事件。策略带有 Capability ID，任务工具集合仍来自场景配置。已有 Builder 别名映射尚未成为通用任务调用接口。

**建议设计。**

- 将策略引用的已认证能力映射到原 Runtime 或已有受控工具入口，向模型提供功能、输入输出、适用条件、效果权限和版本。
- Runtime 继续执行参数、版本、证据和权限守卫，返回局部结果及原回执。
- 主任务默认接收有限结果摘要，稳定内部操作由 Runtime 执行。遇到信息缺口、条件变化或冲突时交回模型。
- 任务冻结版本身份，同时在实际使用前查询原 Store/library 与 Feedback 的当前有效性。无关的新能力入池不应使旧任务整体失效。
- 在原模型请求门和真实派发记录中绑定 task、owner、策略、上下文和 request 摘要。终态使用记录引用这些原始证据。

需要分别记录五类事实。

1. 策略已装配到上下文。
2. 原模型请求入口接收了该上下文。
3. Provider 请求实际派发，或被原 Runtime 安全跳过。
4. 模型声明采用某种做法，以及真实工具与能力调用情况。
5. 独立质量与对照效果。

当前草稿只凭使用记录中的枚举状态，尚不足以证明原请求链收到策略。后续应绑定原请求证据，并覆盖任务恢复、压缩、委派、取消、晚到事件与插件清理。

**验收。** 后继任务能够通过原入口调用策略引用的精确能力版本。有真实 binding 和 receipt。请求证据缺失、串任务、被篡改时，使用记录核验失败。

### G6 Task 与 Builder 的反馈进入下一轮行为

**现状。** 构造历史保存 `inherited_strategy` 和 `strategy_observation`，但决策证据投影主要保留状态、错误和核验结果。未提交 CLI 的使用导入主要覆盖 Web。两条反馈尚未完整汇合。

**建议设计。**

- Task 使用记录来自原请求、工具事件、结果和质量证据。Builder 使用记录来自原 effective、提案、编译依赖、验证执行和费用账本。
- 同一反馈视图明确区分上下文暴露、模型声明、编译依赖、实际调用、后继构造贡献和已测因果收益。
- 下一轮 Evidence Packet 提供上一代策略的实际行为与结果，允许模型保留、撤销或修订策略。
- 若候选改变能力边界或表示，必须进入已有 `capability_evolution.py` 路径，产出有差异的新候选并独立认证。
- 若候选改变构造方式，下一次 Builder 的实际输入或选择过程必须可观察地改变，并按相同质量条件评价。

**验收。** 从一次 Task 和一次 Builder 的真实使用出发，都能沿原始记录进入下轮模型输入。新提案能改变候选图、接口边界、表示或后继构造行为，并保留对应差异证据。

### G7 将新策略产生的稳定片段送回原 learner

**现状。** 语义决策记录的 `steps=[]`，用于保存判断经历。原 `capability_motif_learning.py` 学习需要真实 Capability 节点、绑定和执行引用。当前缺少从策略采用后的实际调用子轨迹到原 learner 的自动交接。

**建议设计。**

- 从真实运行中捕获原 Runtime 支持的子轨迹，附上采用策略的来源关系。
- 原 discovery 决定是否有可复用的稳定区域，原 compiler 处理绑定与类型，原 Store 和独立检查器完成认证。
- 学到的新能力进入现有能力池，供普通任务与 Builder 同等使用。
- 只有语义判断、缺少可支持调用结构或样本不足时，保留轨迹等待后续数据。记录无候选的真实结果。
- 后继能力是否调用上一代能力由真实需求与构造决定，保留直接实现与重组的选择自由。

目前学习范围包括只读效果、受支持的对象输入和绑定形式，组合回执恢复主要覆盖 Script。Source、Artifact、任意 MCP 的完整回执恢复仍需适配。第一轮验收应明确列出受支持子集。

**验收。** 策略被真实采用后产生受支持的调用轨迹，原 learner 实际消费该轨迹并形成认证能力，后继任务能使用它。自然无可学习片段时保留 pending。

### G8 Builder 自应用与 Creation Value

**现状。** 原训练输入准备子过程支持已学习前缀复用，要求展开后的行为与原前缀一致。已有 BuilderConstructionSession 的部分实例属于诊断宿主。真实记录尚未观察到完整自然自应用链。Creation Value 有计量基础，策略选择尚未完整消费独立收益结果。

**建议设计。**

1. 先让 Builder 的策略采用、材料准备、接口修复、构造与认证经历进入 G1/G6。
2. 用 G7 的同一学习入口发现真实重复子过程，在已支持的训练输入准备范围完成首次自应用。
3. 独立认证后的构造原语通过原 catalog 进入后继 Builder，并记录实际采用。
4. 对相同质量目标比较完整构造成本，区分一次性习得投入、每次构造成本和失败损失。
5. 将独立效果反馈给原研究选择与下一轮提案。直接调用少但确有构造贡献的材料可继续保留，收益未知的材料保持未知。

无需预先开发完整 Strategy Library 或通用策略执行器。先观察实际重复过程，再扩展原后端支持。

**验收。** Builder 的真实经历经原学习流程产生新成果，该成果实际影响另一次独立构造。禁用后恢复原流程，旧检查器保持宿主控制。完整成本与质量一起报告。

## 6. 如何衡量反馈真正驱动了演化

每轮同时保存“反馈依据”“候选差异”“后继行为”三者的关联。

| 演化方向 | 应看到的变化 | 对应评价 |
| --- | --- | --- |
| 边界变化 | 新候选选择了不同的节点区域或输入输出边界 | 原编译认证与后继组合费用 |
| 表示变化 | 稳定过程的参数化、结果契约或中间表示发生变化 | 兼容性、质量与修复负担 |
| 构造方式变化 | Builder 实际使用不同材料、分解或修复方法 | 完整构造费用与首成功成本 |
| 执行方式变化 | 任务实际选择了不同的交接、核验或调用路径 | 同质量交付总成本 |

模型提出的因果解释属于假设。使用日志证明行为，匹配对照估计效果。二者分别记录。候选可以失败、无净收益或选择 `no_change`。

成本使用原账本口径。全程研究支出、首个质量合格结果前的获取成本、后继运行成本分别展示。未知成本保留未知，共享发现成本单独记录。Creation Value 的测量可复用原计量组件，但策略比较需提供实际 Task/Builder 对照适配。

## 8. 既有真实结果支持什么

- 视频历史复用实验观察到模型请求减少和前向估算费用降低，冷启动学习投入尚未摊销。已有局部效率收益保留原结论。
- 历史真实 C→D 个例在新论文项目中完成检查，但接口修复使该轮构造费用高于扁平路径，不能直接推为正的 Creation Value。
- 后续真实模型曾选择完整扁平程序，C 调用为零，尚未自然出现 Builder 前缀自应用。
- 基础 Evolution 真实运行先提出冗余包装，修正上下文后得到 `no_change`，尚未取得可用自主策略的收益结果。

以上证据分别对应能力复用、递归个例与演化提案。后续重点是观察完整链的实际行为，再定位任务需求、抽象接口、上下文信息或候选质量的问题。

详细历史记录见 [RAE 连续研发记录](../experiments/rae-followup-20261104.md)、[基础 Evolution 记录](../experiments/evidence-evolution-20261104.md)与[策略演化记录](../experiments/strategy-evolution-20261104.md)。

## 9. 树状依赖与并行边界

```text
D0 确认候选、评价、研究继承和语义投影规则
├── A 证据链
│   ├── G1 普通任务与Builder终态引用
│   └── G2 语义、诊断、费用范围与上一代内容
├── B 实际采用链
│   └── G5 能力映射、实际请求证据、生命周期
└── C 独立评价链
    └── G3 原执行器上的Task/Builder评价宿主

A + C → 原Evolution入口产生并独立评价候选
B + C → G4 宿主交接选择 → 后继实际运行
A + B + G4 → G6 Task/Builder使用与结果回流
G6 → G7 稳定执行片段进入原learner → 后继能力
G6 + G7 → G8 Builder真实自应用与构造收益比较
各链汇合 → 全量回归、失败审计、真实端到端记录
```

建议先做四个可审阅纵切。

| 纵切 | 交付 | 完成门槛 |
| --- | --- | --- |
| 1 证据可用 | G1/G2 | 普通任务和构造事实自动进入有界模型视图 |
| 2 演化可继承 | G3/G4/G5 | 自主候选、独立评价、后继采用无需手搬配置 |
| 3 反馈可改变方法 | G6/G7 | 后继反馈引起可观察差异，稳定片段回到原学习器 |
| 4 Builder自应用 | G8 | 原学习流程产物实际改变独立后继构造 |

并行文件边界建议如下。

- A 负责 `capability_decision_evidence.py`、构造历史投影与原观察入口。
- B 负责 TypeScript 策略读取、任务插件、Runtime 映射与请求证据。
- C 负责原场景执行器的评价适配、质量与原账本对接。
- 汇合负责人修改 `capability_evolution_agent.py`、研究 CLI、selection 交接与公共文档。共享字段先确定，再交接集成。

这份分工属于后续计划。每个纵切都保留失败记录，先通过确定性守卫与原回归，再进行真实模型行为验收。

## 10. 实施前需要讨论的五项决定

以下是建议，尚未作为新实现承诺。

| 决定 | 推荐方案 | 原因 |
| --- | --- | --- |
| 首轮自主作用范围 | 优先构造策略，保留同协议的任务接入 | 直接评价下一次改进过程，并复用已有Builder接线 |
| 策略何时适用 | 宿主限定owner、scope和权限，模型判断语义适用性 | 保留开放判断及真实的拒用情况 |
| 语义证据如何生成 | 已授权研究范围内确定性事实投影，加单独标注的模型解释 | 减少人工摘要，同时保留隐私与事实来源 |
| 候选何时默认继承 | 质量通过可进入显式研究试用，有效果证据后成为该范围默认 | 让早期数据可积累，并保留采用状态的含义 |
| 失效策略如何修复 | 历史版本保留，新版本独立评价后替换选择 | 谱系与失败可追溯，恢复过程清楚 |

研究调度建议先采用显式单轮入口，复用原控制器、队列、Feedback 和 Store。每轮保存提案、构造、评价和选择交接的引用。中断恢复先核对原请求账本与产物，再续跑。常驻自动运行和生产接管另设后续门槛。

## 12. 总体验收与交接

完整演化闭环验收需同时看见以下事实。

- 多个独立真实决定的证据自动进入同一研究轮次，重试与续写保留来源关系。
- 模型在有限上下文内自主提出能力、边界或策略候选，也能输出 `no_change`。
- 候选通过原构造与独立评价，所有失败与未知费用保留。
- 宿主完成研究选择交接，后继Task或Builder实际采用精确版本。
- 实际请求、调用、质量与费用可追溯，后继反馈进入下轮输入。
- 反馈驱动的修订产生可观察的图、边界、表示或构造行为差异。
- 受支持的真实稳定片段由原learner学习，认证后可继续参与执行或构造。
- Builder自应用由真实经历产生，并在独立后继构造中得到采用证据。
- 关闭、撤回、失效、权限拒绝、取消、恢复、旧库及跨语言协议通过回归。

本轮形成一份新的审计设计文档。暂停中的源代码改动另行保留。恢复开发时先确认第10节的选择，再按第9节依赖推进，并在每个纵切结束时更新原交接记录。
