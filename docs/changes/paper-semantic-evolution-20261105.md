# 论文语义反馈驱动演化实施计划

## 关键判断

本次从`6499d32c351f78dd1c0a82945972cc9185d7084e`及当前未提交研究改动继续。保留既有R13修复及全部历史成果，不重新运行已停止的18格论文构造实验。

已核对的11月4日Evolution原输入主要是已封装能力的内部执行关系，缺少语义失败、反例与已评审质量。第一轮重复建议封装已有图，补充运行层级后第二轮空候选。旧逐论断实验已有否定、范围和证据支持错误，但这些质量反馈尚未进入那两轮Evolution输入。详见[历史复核](../experiments/evidence-evolution-20261104.md#2026-11-05-历史轨迹复核与瓶颈定位)。

新目标是让Evolution能够调查真实的未解决判断，提出改变后继取证、判断或处理方式的候选。LLM judge提供独立的质量反馈，实际候选继续交原策略、能力、Builder与Feedback机制处理。效率和性能可交替改善，原执行效率成果继续作为起点。

## 最小数据流

```text
真实任务、来源材料与原模型判断
        ↓ 原语义经历与可追溯引用
独立质量评价及错误定位
        ↓ 原分层调查接口按需读取
Evolution自主提出能力或条件策略候选
        ↓ 原构造、独立验收与版本机制
后继任务实际采用及新质量、完整费用反馈
```

默认概览保留短的任务、结果和未知项。原文、逐项评价与执行判断通过已有按需读取接口访问。完整轨迹不自动注入Prompt。已封装的Runtime步骤保留运行层级，不能计为模型重新求解。

## 实施顺序与验收

1. 恢复旧语义实验的原始来源、判断、运行身份与费用引用，分清原生输出、后续恢复与外部修订。缺失的原件记录为pending，不能从报告编造原始轨迹。
2. 审计原语义经历、调查工具、策略入口与质量评价宿主，复用已有表示和读取机制。最小修改应让质量问题、关联判断和证据可查询，并保留训练与独立评价的角色。
3. 为独立评价补最小宿主接缝。评价绑定真实输入、回答和来源，冻结标准，隐藏方法和费用。支持来源不足、未知和拒绝评价；裁判输出不授予能力认证。
4. 离线重放旧记录并定向测试，核对事实级失败能进入调查、按需读取可定位到原件、旧数据缺质量时保留未知、评价材料不进入候选发现输入。确定性夹具只标记机制诊断。
5. 原始材料齐备后，先用已知错误及正确对照校准真实LLM judge。校准样本不充当最终留出。通过后再运行最小真实演化与后继采用检验，不预定D或E。

本轮首个检查点是语义质量反馈进入同一个Evolution调查流程，并能定位到实际判断与来源。候选发布、后继采用及性能收益分别记录，接线测试通过不写成效果提升。

## 范围与停止条件

不新增Registry、IR、Meta-Agent或第二套演化循环。沿用原调用账本、模型入口、策略准入与成本协议，研究开关默认关闭。候选不能修改独立评价标准。

已有语义失败仅有旧报告、缺原件时，先完成可验证的公共接缝和测试，并将真实端到端验收保持pending。裁判不能区分已知错误与正确对照时，先定位评价问题；任务没有可操作的剩余判断时保留no_change。禁止将人工构造的正确答案或理想轨迹写成自主改进。

本轮首阶段新增模型调用0。后续真实API仍在Linux服务器执行，实际模型、模式、输出容量及费用配置在启动前说明，沿原累计账本不清零。原始论文与轨迹留在私有目录；本轮不合并、不部署。
