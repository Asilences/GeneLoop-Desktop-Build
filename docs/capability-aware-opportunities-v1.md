# 能力变化驱动的机会重新评价：PR 1

- 起点：远程 main `eea8c5584e55f22d3a4d3b2eb00e2e4414ac7e99`，当前工作区短期分支 `codex/capability-aware-opportunities-20261103`。
- 本轮只实现机会发现与接线，不实现节余账户、边际收益策略，不恢复Paper对照或部署生产。

## 已有机制与缺口

`capability_discovery.py`已有按真实轨迹、失败和重复结构生成任务的发现器。`capability_improvement.py`已有同一队列、能力池变化后的暂缓重试和构造/验证/发布循环。`capability_feedback.py`已有执行/构造贡献和排序；`efficiency_rsi_measurement.py`保留全尝试费用及未知结果。以上不重写。

缺的是：认证发布新增能力以后，结合仍未满足的真实需求，提出此前没有进入队列的改进目标，并保存提出、宿主筛选、构造及独立验收之间的关系。

## 最小接线

1. 宿主计划可选 `opportunity_discovery`，默认缺失即关闭。配置包含需求上下文原字节引用、私有账本目录及每次运行允许的重新评价次数。
2. 只在现有控制器独立发布成功、可用能力池出现新增根，并且上下文仍有未解决需求时触发。普通暂缓重试保留原规则，不要求每次更新都调用模型。
3. 同一owner/需求证据/前后能力池变化只提出一次。先持久化认领，再调用宿主的单次提案方法；中断不自动重发付费请求。
4. 提案引用需求ID、目标、预期依赖及理由。目标稳定身份不依赖运行目录；保存提出时完整snapshot、需求原证据、原始提案和所有筛选结果。
5. 宿主 `review_opportunity` 提供冻结任务契约、现有publication plan和独立筛选证据。模型不能指定执行适配器或验收器；无可信验收条件则pending。通过的job进入原队列。
6. 构造结果保留原费用和独立验证引用。预期依赖、编译依赖、执行回执观察到的依赖分开记录；没有回执就保持未知，不能据模型描述记递归。

单次真实模型提案复用Harness和原累计gate。研究宿主须提供有限预算gate及请求归属；没有该授权就暂缓，不从平台null额度推导研究授权。PR 1以诊断输入检查机制，不自动调用模型；不将其宣称为自主行为效果。

宿主可用`opportunity_gate_factory(request,output)`仅在提案期间打开有限gate，避免长期占用与正常构造共用的账本锁；已经在同一研究gate内运行的适配器也可提供`opportunity_gate`。默认两者均不存在，模型提案不会自行启用。`review_opportunity`默认pending，只有场景提供可信验证条件才生成Builder任务。

## 验收与停止条件

- 已有暂缓机会在新池后仍按原控制器重新评价；新目标同时可以进入原Builder。
- 同一能力更新、无新增能力、无未解决需求不重复探索。
- 所有候选，包括拒绝、未选中和中断记录均保留；范围、证据、快照及预期依赖可追溯。
- 预期C未被实际执行时不记录实际递归；质量失败、版本失效、权限不足沿原发布器拒绝。
- 未配置此功能时原有行为不变。
- 提供隔离真实任务证据的事件重放示例；固定提案属于零模型诊断，不代表模型已自主发现目标或效率提高。
