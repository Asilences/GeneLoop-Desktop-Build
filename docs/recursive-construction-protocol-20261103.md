## 要观察的闭环

1. 已认证的 C 来自 A/B 及模型学习的新关系材料。
2. 模型自主选择已有 C，生成新增关系逻辑和数据流，构造、独立验证并发布 D；在不同输入上真实调用 C，不能用宿主强制组合替代。
3. 同条件保留普通 Python，移除 C 或仅保留扁平材料，比较完整获取成本、质量和可达性。C 初始获取成本另列；只有嵌套没有成本或可达性收益，不能叫效率 RSI 已验证。
4. 合格 D 自动进入后继 Builder 的可见材料，质量与成本反馈实际参与后续选择；后继自主使用 D 是进一步证据。给定研究目标的构造与正常任务自动产生研究机会分别报告。

## 目前证据与待区分原因

- C 的接口真实可见，强制组合在原验证和 Mamba 上通过，排除“执行器根本不能调用 C”。
- 原 H0 首次自主生成正确 JSON 比较器；认证入池后旧控制器丢失用途/续接信息，模型转向完整重写。续接修复已实现，行为效果未验收。
- 原 H1 首次就重写完整程序，说明续接缺口不能解释所有路径。
- 完整 paths 程序可自动包装为候选；部分 JSON 程序须再用另一种格式组织组合。普通 Python 中不能调用 C。同答“新关系逻辑+组合意图”尚不能表达，这是接口不对称。
- Frontier 自定义作者遗漏公共 construction selection 排序。修复后必须另开条件，不能与纯续接信息消融混为一谈。
- Direct 曾一次请求就完成合格 D，因此当前 D 不自动构成预算能力边界；禁止靠降低预算或禁止重写制造 C 优势。

冻结 H0 第一次比较程序认证完成后的真实能力池，所有组已有同一个 C 和同一份比较器。以 main 的不可变代码快照复用公共控制器、原生认证及发布；两组仅差是否提供已完成材料的 `material_continuation`。

- 4 对、8 个完整续接回合；顺序为 on0/off0/off1/on1/on2/off2/off3/on3，全部预登记，不能首个成功即停。
- 每格研究额度 USD0.80，计划上界 USD6.40，原检查点获取成本和 C 成本另外列明，不能虚构为免费。
- 相同任务、输入、模型、工具顺序、种子材料、权限、独立检查与修复规则。无最终测试反馈进入构造。
- 首要观察：是否自主选择 C；是否独立发布；是否再次请求材料或重写；所有费用。全部构造后再运行 Mamba 回归。Mamba 已被查看，只作为定位/回归，不称新盲测。
- 所有结果保留。两组都成功则不能说续接是唯一原因；两组都重写则优先处理接口；带续接组较好仅为有限定位证据，不估稳定成功率。
- 本阶段是历史真实检查点的自主续接，不能冒充从原始能力池开始的新端到端构造。

## 第二阶段：消除已确认的接口不对称

最小改动允许模型同一回答给出新程序以及显式组合意图。提出时固定已有能力的精确版本；新材料仅用专用占位引用，待原生认证后替换为真实版本，再走原 IR、独立检查与发布。宿主不能代选 C、补算法或补参数关系。修复共同选择排序，不改质量或权限。

新条件从初始池完整运行 Direct、Flat、WithC；普通 Python 在各组同样可用，全部构造后再验收。新论文项目与代码/任务/评价器/预算必须在首请求前冻结，旧 Mamba 只作开发回归。若仍失败，按真实源码、选择、绑定、认证和质量定位，不反复加“请复用 C”的提示。
