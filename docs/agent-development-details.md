# GeneLoop 开发与实验细则

本文件保存从原 `AGENTS.md` 迁出的操作细节。项目方法与优先级以仓库根目录的 `AGENTS.md` 及[方法北极星](research/rsi/method-north-star.md)为准；按任务查阅对应章节。新用户要求和已核实的代码现状优先。

## 目标与研发责任

GeneLoop 要让研究者配置自己的 MCP 场景，可靠完成真实任务、审阅交付，并在资料变化后正确更新。研究方向是从正常经历中积累经过验证的局部抽象，减少重复模型工作，并检验这些改进能否帮助后继能力的发现、构造与验证。产品以同等质量下的完整成本、可追溯性、易用性和可维护性证明价值。效率和性能都可驱动自我改进；只有后续改进能力也得到实证提升，才声称 Recursive Self-Improvement。

完整成本包括模型费用、失败重试与恢复、人工修订以及开发维护。一次演示、模拟工具覆盖或局部 token 降低不能证明产品收益。每项机制先明确服务哪个真实任务和反例，再用相同质量门槛的端到端对照评价；简单脚本、缓存或既有工具更合适时如实采用。当前任务优先级由交接和 Issue Board 决定，历史实验计划不自动成为新任务。

- 接到目标后理解实际数据流和最近一次真实结果，主动找出最重要的 1–3 个阻断。用户的实现想法也要与代码和证据核对，发现矛盾时提出并实施最小有效方案。
- 区分阻止真实任务或验收的错误、影响研究结论的错误与后续增强。先解决前两类，不因发现潜在问题就扩张框架、协议或守卫。
- 失败后读取执行证据，重新判断假设，修改方法并复验原问题。同一内容或策略的重复运行只能算复测；允许报告失败、`no_change` 或结论不充分，不为正面结果改动冻结评价标准。
- 正常可逆、已授权的开发与测试自主完成。有实质歧义时先推进不受影响的部分。外部写入、正式部署、实际投稿及超出已有授权的行动遵守相应确认流程；不要重复索取已给出的编码联调授权。
- 每项重要修改回答：解决了什么真实问题、实际行为是否变化、质量是否成立、完整成本或后继能力是否改善，以及证据和反例。代码量、测试数、候选数和文档量本身不是成果。
- 默认中文沟通、提交和写文档；代码标识符、协议字段、命令及上游原文保持原样。明确区分已完成、已验证、推测和未验证。

## 多人协作与代码所有权

项目由多名成员并行推进。当前分工：刘沛林负责后端系统与集成测试；夏泽负责 Coding 场景与 RSI；俊杰负责桌面端与数据脱敏；杨逸晖负责前端 UI 与产品体验；项目负责人负责研究路线、总体架构、协调及最终验收。分工是协作边界，不是绝对所有权；具体任务、DDL 和进度以最新 GitHub Issue Board 与 PR 为准。

- 不因当前分支缺少功能就认定无人开发。先查相关 Issue、PR 和交接，再决定实现或集成；共享接口和他人正在修改的代码优先采用兼容修改并协调。
- 不覆盖他人的未提交工作，不重置共享分支、强制推送或擅自合并 PR。并行修改使用隔离分支或工作树，提交只包含本任务文件。
- 主动指出集成冲突与接口不一致，附证据和最小修复建议。无协作冲突的可逆修复可直接推进；责任或路线变更由项目负责人协调。
- 未交付的依赖可用隔离的最小测试替身推进，但不能将替身冒充真实集成。场景专属要求写入场景文档或目录级 `AGENTS.md`。

## 架构与 Evolution 边界

- 结构层负责经过验证的可执行节点、依赖、参数流与证据守卫；语义层处理相关性、冲突和新的研究判断。旧成功路径只是候选；新反证、权限或版本变化、工具失败及问题变化须触发核验、失效或语义交接。不能用关键词、固定路线、手写场景 DAG 或 Prompt Skill 冒充 Motif。
- Motif 从正常工具轨迹和 schema 学习，经独立认证及后继任务验证。保留版本化 IR/library、来源证据、摘要与修订差异。先验证安全跳过整次模型请求与正确恢复，再和脚本、缓存等简单方案比较；不强迫 Agent 使用 Motif。
- 结构抽象的训练决定、认证与后继验证必须区分；同一研究决定的续写不是独立任务。认证过的能力仍要核对当前输入、来源与依赖，旧频率和旧结论不授权跳过模型或维持科研判断。撤回和回退是正常执行结果，应保留可复查证据。
- Python 负责离线挖掘、编译、认证和研究实验；新增在线执行逻辑以 TypeScript Runtime 为目标。现有 `.mjs` 和 Python 兼容实现渐进迁移，不为统一语言大规模重写。跨语言共享 IR/Schema 及运行时校验，协议变更时验证编译输出与在线执行一致；不能让两套在线规则长期独立演进。
- 产品路径保留预算约束。现有纯代码节点的能力应迁移为受限且可验证的执行协议，不能改成任意代码求值，也不能在迁移中悄悄丢弃。
- DeepSeek Harness 是现有宿主和语义环境，场景经自定义 MCP 扩展。优先使用公开插件和 MCP 接口，不修改上游 Harness 核心。原冻结 MotifAgent 仓库只读；迁移保留 `src/motif_core/LICENSE`、`PROVENANCE.md` 与来源 commit。独立插件分发及无 Python 在线依赖尚未完成，不能提前宣称达成。
- `harness_runtime.py` 的固定 SDK 私有启动接缝是已记录的兼容边界；升级 Harness 时核对该接缝、事件和工具生命周期。现有 `run-scenario.py`、预算代理与部分在线纯代码节点仍依赖 Python，不把离线／在线分工误写成已经完成的产品状态。
- Evolution 的调查、候选路由、评价接收、后继反馈和经历累积应复用 GeneLoop 公共流程。Paper、Coding、Builder 提供经历、原件读取、评价和实际接收器；Builder 经历可参与，但不是普通任务的强制前提。先核对主线与相关 PR 的实际实现，不另建 Registry、IR、存储或 Agent 循环。
- Evolution 可以调查重复推理、接口摩擦和多余成本，也可以调查无法完成的任务及新能力机会。候选可改变抽象、抽象边界、任务或构造策略，不必都编译成 Tool。后继调查保留已有能力、相关历史经历和新反馈；不能把封装能力内部调用误记为模型重新决策。自主发现、实质不同的方案、独立评价、真实采用、质量／成本与下一轮能力构造分别报告。

## 真实 API、预算与运行环境

- 模型行为的端到端联调、场景验收和效果／成本对照使用用户持续授权的真实 API，在已配置 Linux 服务器运行；现有入口为 `npm run web:real` 和 `npm run scenario:real`。默认 `reasoning_effort="off"`，实际模式按任务选择并记录。模拟 Provider、单元测试、错误注入和无模型 smoke 只证明相应工程机制，不能代替模型行为验收。
- 运行前说明实际生效的模型、模式、费用预算和输出上限。沿用原累计账本与已用请求数，不清零。当前共享平台 Web 每任务、对照各侧、累计费用及请求次数按用户授权不限；File 独立 SDK 继承同一平台 policy。实验者明确指定的有限诊断配置仍有效，不得以默认值、取最小值或隐式转换恢复旧限制。
- File 独立 SDK 的费用、请求／步骤及修复额度同样遵守 `null` 全程不限，不得写入 `min(5, ...)`、`?? 5` 等旧上限。新只读配置沿用原账号 pool、library 和累计费用／次数，不重写旧任务。平台授权不取消服务端费用统计，也不取消实验者显式设置的有限预算。
- 上述平台 policy 的 `null` 表示不限；CLI `0` 仅在该入口定义为不限时才如此解释，数值预算 `0` 仍可能表示禁止付费。以具体入口有效配置为准，不把 `null` 算成 `0`，不重写旧任务或账本。预算代理估费与供应商账单实付须区分。
- 不额外截断用户输入。正式请求的 `max_tokens` 按当前模型官方能力与有效配置明确设置，普通与文件转发路径一致；不能省略参数而恢复默认 8K，也不能把历史 DeepSeek 的 393216 当成所有模型的通用上限。保留文件容量、HTTP 安全、取消及权限检查。
- Web 不额外限制用户文字长度或截断提示词，`max_output_tokens: null` 表示没有应用层输出额度；这不等于模型拥有无限上下文或无限输出。请求必须遵守所选模型实际窗口和 API 约束，记录有效值及超限失败。
- 云模型对照保留稳定的会话提示前缀、工具 schema 集合与顺序，新增事实尽量追加并用来源 ID 找回。压缩只在真实窗口压力、上下文溢出或用户显式请求时触发，记录来源、用量和缓存影响；不裁剪原始日志或借压缩清空账本。
- 本地用于编辑与审阅；服务器项目环境先加载 `source .local/remote-env.sh`。正式服务由私有 `GENELOOP_SERVICE_HOME` 和 `GENELOOP_SERVICE_CONFIG` 定位，不写死旧机器路径。同步代码和输入时核对版本，两端有改动先比对合并；交付物和必要结果按需同步回本地。
- 密钥只由服务器私有 `.env`、环境或凭证存储提供，不读取展示其值。缺失时如实报告，不退回固定回复冒充真实验收。测试授权不包含写外部应用、修改私人原件或实际投稿。有副作用的 MCP 必须有权限和操作确认；产品原生聊天按服务端预算策略直接执行，任务 API 保留预览／提交。
- 通用 `npm run scenario` 默认只预览；真实模型联调使用显式 `scenario:real`／`web:real`。已授权的编码联调不再追加产品聊天预算确认。

## 验证、实验与交付

- 先运行与改动相关的定向检查。公共 Runtime、依赖或 Harness/MCP 接口变化运行 `npm test`；场景连通性变化运行相关 `npm run smoke`；Motif 样例可用 `npm run motif:check`。保留安全失败、权限拒绝、版本失效和回退测试，不能删有效检查求绿。纯文档变更核对链接、事实和 diff 即可。
- 实验保存代码版本与未提交改动、任务和来源版本、有效模型与工具配置及顺序、模式、预算／输出上限、library 摘要、真实请求与 token 用量、缓存、重试／恢复、费用、耗时、质量评审和人工修订。记录实际生效值，缺失项写明；配置改变使用新实验 ID，不覆盖旧快照。
- 配置快照还应能定位操作系统、Node／Python／DSH／SDK 版本、场景与题面哈希、工具 schema、匹配阈值、embedding 模型、压缩和重试策略。公共路径用仓库相对路径及哈希，私有来源用匿名标识与版本定位方式；不能只写“默认配置”或仅给本机绝对路径，也不能假称现有工具已自动采全。
- 学习、认证、历史回放、开发验证与独立未见评价分开报告。先确认质量再比较完整成本；无用量不记作零，未评审写未评审。失败及反例保留，不因结论变化追改历史证据。实验至少说明假设、任务与对照、复现配置、结果、成本和结论边界。
- 对照应说明两侧相同的任务、来源、模型、工具集合和评价条件，以及唯一希望检验的差异。记录任务是否真正完成、来源是否可追溯、更新是否正确、人工修订和端到端耗时；代理估费、预算上限与账单实付分别呈现。独立盲评未做时，不据此声称质量等价或稳定降本。
- 公共配置、场景契约和依赖版本进 Git；密钥、私人论文、用户数据和原始轨迹留受保护环境或 `.local/`，不得提交，也不得批量清空 `.local/`。公共文件用环境变量名引用私有配置，不记录凭证值。
- 正式实验结论放 `docs/experiments/`；调试、故障、配置审计与工程联调摘要放 `docs/debug/`；私人原始材料放 `.local/debug/<issue-id>/`。同一问题追加原记录，关联来源 ID，避免复制多份日志。长期文档分类见 [文档导航](README.md)。
- 主线与场景当前状态分别维护在 `docs/handoffs/main.md` 和对应场景交接。重要变更、实验结论及交接前更新目标、分支／未提交改动、已完成与验证、配置、阻断、权限预算、回退风险和下一步；简单修复不写长篇流水账。关键接口变更同步 `docs/interfaces.md`，启动与依赖变更同步 `README.md`。
- 交接应让下一位同学不依赖聊天记录就能复现：给最短命令、代码与配置位置、失败摘要、已尝试方法及下一步 1–3 项验收标准。多人避免同时修改同一份场景交接；历史通过 Git 追溯，不每天新增一份重复文档。
- 提交前检查 diff/status、敏感信息、他人工作与最新 CI。最后简述解决了什么、证明了什么、尚有哪 1–3 个限制及下一步；写清本地提交、推送、PR、合并与部署的真实状态。

## 正式服务与副作用

- 正式服务的启动、重启、发布切换和回退统一走 `npm run service -- <start|restart|status|check|rollback>`；公网恢复也走同一入口，细节见 [服务生命周期](operations/service-lifecycle.md)。运维先 `status`／`check`，健康服务不为验证而重启；公网链路故障只恢复相应链路，不停止正常任务。
- 公网配置独立由 `GENELOOP_PUBLIC_CONFIG` 或 `--public-config` 指定，核验／恢复使用统一入口的 `public-check`、`public-prepare`、`public-confirm`。不能为单个修复恢复退役的 `.local/deploy*.py` 启动部分；若统一流程确有缺陷，修改该入口并做回归。
- 不另写 `Popen`、`nohup`、批量 kill 或平行 owner/gateway 启动器。候选版本在独立代码、配置与库路径准备，保留上一版本及原账号、Home、输出和预算账本。遇到活跃或未知任务停止发布并安排窗口，不通过篡改任务状态放行。
- 研究候选默认隔离，不静默改变运行中的用户任务。修改用户文件或外部应用前展示影响和预览并取得所需确认；发布与回退均核对认证及公网状态。`npm run web`／`web:real` 是开发与真实测试入口，不等于正式多用户发布。
- 服务生命周期目前只验证 Linux，不宣称 Windows 托管支持。影响生产的修复先在独立环境验证，再按统一入口发布和回退。
