# GeneLoop：RAE 递归闭包完成后的连续研发任务（Codex）

> 补充于 `GeneLoop_Recursive_Abstraction_Evolution_Codex_Spec.md`。本文件不是替代规格。以本地最新 `main` / 当前研发分支、`AGENTS.md` 和真实代码为准。不得把合成机制检查说成真实模型 RSI 结果。

## 研究目标

上一轮规格 T0–T8 解决“已认证能力 C 能否成为后代轨迹的一等原语，再从这些轨迹学出 D，并让能力构造过程使用相同学习机制”。完成后，下一阶段要解决：**反馈能否自主改变抽象的边界或构造方式，且改变后的方案在后继任务中真的更有效？**

不要再造一套 Meta-Agent、Registry、StrategyManager 或第二种 IR。将任务分成可独立审阅的提交/PR，门禁顺序执行；若前一项未完成，不为追求进度标记后一项成功。保留 production default off，不能改变认证规则、权限与预算上限。

## Gate 0：核对前一轮是否真的闭合

- 以本地 HEAD、测试和原始执行回执审计 T0–T8。人工注入的 C/D 与模拟数据只能证明 wiring。
- 逐一验证：`publish(C) → C in trace G1 → existing learner consumes G1 → publish(D) → D in G2`，不能只由 builder 的文字描述或 JSON 引用凑出嵌套。
- 验证 `Builder trace → candidate → certify → used in later Builder attempt`，不是仅记录 builder 日志。
- 记录仍缺的机制、无法运行的外部依赖、工具用量来源和未完成测试。

## Gate 1：真实失败驱动的抽象候选演化（最优先扩展）

目标：让**一次真正的复用或构造失败**驱动新的抽象表示或边界，而不是人为给出必须 split/merge 的答案。

1. 从已存的真实论文/视频或 coding 构造日志中选取 1–2 类可复现的失败：例如跨能力参数绑定错误、过粗的抽象无法组合、重复验证开销。保留原始完整日志，不能改写为理想轨迹。
2. 复用现有 Discovery / Builder 生成多个候选（可为缩小适用范围、重新定义输入输出、拆分、组合、新实现，或放弃复用）；不强制哪个候选获胜。
3. 对候选冻结独立验证依据，并记录候选生成成本、验证成本、失败次数、覆盖范围、版本和来源。候选只能新增版本，不能覆盖原版。
4. 至少产生一个**实际不同**且通过独立验证的候选，并在后继任务中真实使用；若无合格候选，则保留所有失败，报告未达标。
5. 新旧版比较完整成本、质量、接口适配情况；不能靠只减少检查项宣称收益。

**验收**：反馈不仅改变排序分数，而是导致下一轮真正采用不同的能力边界/表示/构造路径；保留行为前后的原始轨迹、证据和成本。

## Gate 2：能力创造方式的反馈学习（RSI 的关键）

目标：不要求 C 运行时包含于 D，而是让真实能力构造经历**改变下一次能力构造决策**。

1. 让 Builder 的目标、候选方案、已可用能力、实际引用、失败修复和验收结果成为标准可观察的构造状态（优先复用现有 trace/schema）。
2. 基于 Gate 1 的真实反馈，由现有学习/作者路径生成一个可执行的候选“构造方式”产物。它接收构造状态，输出可进入已有 Builder 的下一步方案/候选变换；如果只是经验文本，没有可观察的后继动作，则不得计为完成。
3. 在后继独立构造任务中比较：A 原 Builder；B 原 Builder + 相同历史经验文本；C 原 Builder + 被实际采用的新构造方式。三组固定模型、可用抽象、任务要求、评估和总预算。记录新产物实际导致了何种不同选择。
4. 新方式未提高成功率或完整成本时，不得晋升默认；通过与否都保存真实证据及失败案例。
5. 候选不能修改验收器、绕过工具权限或改变定额；旧 Builder 必须一键恢复。

**验收**：至少一次系统从构造反馈中自主产生的方式，被后继 Builder 实际调用，并导致可核对的行为变化。若收益未证实，完成状态为 `self_application_wired` 而非 `RSI_proven`。

## Gate 3：自主多代研究轨迹（基于 Gate 1/2 的小样本）

- 选一个真正包含新约束关系的连续任务环境。任务需求由环境给定，但**不预先写死 D、E 的实现或强制依赖 C**。
- 从真实需求和新认证能力触发 Goal Discovery，记录 proposed / attempted / verified 的区别。不要强制每轮一定新增能力。
- 追踪执行依赖、构造依赖、验证证据和控制方式来源，分开记录 `material_read`、`compile_ref`、`runtime_call` 和反事实收益。
- 尝试产生 `C → 新高层轨迹 → D → 后继轨迹`；有条件时继续下一代，但不把简单 wrapping 或工具嵌套深度当作策略增长。
- 对失败、止步、额外开销、无法认证的目标保持全量记录；统计全链路实际费用，包括学习、搜索、验证、恢复、维护。

**验收**：至少一条可独立复现的真实模型构造轨迹（若环境及研究预算明确授权）；否则提供确定性机制轨迹，清楚标注其证据等级。不得私自花费预算。

## Gate 4：反例与长期正确性审计

- Guard 失效、权限变化、跨版本引用、能力依赖环、失败后回退、取消与中断恢复、缺失用量、执行副作用、不同租户隔离、恶意/错误能力描述等反例。
- 关注嵌套级别提高后，检索/绑定/验证成本是否超过节省的模型工作（utility problem）。
- 检查可复用抽象的验证证据是否被错误扩大到新组合约束；不能通过弱化 verifier 得到虚假成功。
- 生产路径回归、Feature Flag off 下行为一致；新机制全部在隔离环境。

## 输出要求

按顺序输出独立可审阅的提交/PR，不要为了“整夜写满”形成一个巨型 PR。每个阶段包含：

- HEAD SHA 与当前代码缺口审计；
- 实际代码改动与复用的旧接口；
- 测试、原始轨迹、独立验收依据、成本来源；
- `Implemented / Wiring Verified / Autonomous Observed / Measured Net Benefit / Research Pending` 分级报告；
- 无需部署的回退步骤与待审阅问题。

**停止原则**：如果任何 Gate 不能通过，则完成可审计的失败归因和最小修复，不得跳过以制造成功案例。不要将“明天完成”的工作描述为已自动启动。PR 不应自行合并 main 或部署生产。
