## 这次修什么

1. 单一`capability_source`可同时声明普通新函数和静态`build(value)`调用图。已有能力成为当前目录里的函数；模型选择全部调用与参数，宿主编译到原IR。新函数算法原文保留，参数包装由宿主处理。`build`不作为Python执行，不增加任意宿主调用权限。
2. 精确Script JSON ABI的输入/返回包装在源语言中由宿主投影。JSON对象入参显示真实领域字段；标量/数组保持单值接口。旧JSON提案和普通完整paths程序继续可用，不改旧证书/执行含义。
3. 新helper的认证数据由模型明确选择的已认证调用前缀在两份训练任务上真实执行得到；不拿预制C报告、最终数据或oracle答案替代。只使用原验证grant，不能伪造前缀认证。
4. worker失败保留有界异常类型、执行模块行号及调用/参数哈希，原错误回执不改。数组加层提示与声明契约违反严格分开。只有未提交、数据操作异常和绑定加层证据精确匹配时，才交给原控制器修复；未知、取消、超时不盲重试。
5. 解决已测得的重复元数据验证：仅同一次执行中复用已验证库/registry的解析结果。每次守卫仍读真实字节/哈希，权限、输入、代码及策略变化仍核验。独立记录工程提速，不能冒充抽象创造价值。
