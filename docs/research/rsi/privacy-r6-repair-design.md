# 公共隐私模块 R6：完成批次审计与修复设计

## 中文客户优先的设计修订（2026-11-11）

用户明确主要面对中国客户。本节更新下面续审中的模型比较优先级：**中文正式文本、中文口语/聊天为主验收，中英混写为必测，纯英文为兼容回归。** 不用英文成绩或跨语言平均值掩盖中文漏检。沿用原三个基准和失败证据，新增中国客户场景开发样例；不会追改旧数据或降低冻结门槛。

在现有公共模块上构建可复现的“中文任务轨迹脱敏方法”，自有部分是结构感知、按类别的检测组合、上下文判定、跨度融合和一致替换，基础识别器复用成熟工具。工程上可以称为自己的算法/方法；是否具有科研创新性和相对收益，要通过独立留出及消融证明，不能把工具包装声称为原创NER。

### 候选顺序

1. 保留Presidio的规则、实体结果、替换器与批API，Gitleaks/CredSweeper负责独立凭证路径。先修原因归因和调用成本，不为换模型重写公共契约。
2. 中文姓名/地名主识别器优先小规模比较HanLP中文NER与现有基线，Stanza中文作为成熟备选；最终按本项目效果、延迟及可维护性选择一个主后端，不默认三者并集。HanLP官方提供中文ELECTRA small等预训练NER，但通用实体F1不能当作隐私或完整地址成绩；具体模型资产许可、版本和依赖在落地前单独核验。[HanLP官方NER列表](https://hanlp.hankcs.com/docs/api/hanlp/pretrained/ner.html)、[Stanza模型表](https://stanfordnlp.github.io/stanza/ner_models.html)。
3. 中文地址和实体关系疑难样例评估PaddleNLP抽取式UIE的mini/micro/nano档，使用有限固定schema；官方另有中英UIE-M。模型输出须含可核验原文位置；不是用生成式大模型改写整段。UIE按schema执行的成本也须测量，不默认比OPF快。优先作为疑难二阶段候选，不对每个字段强制追加。[PaddleNLP信息抽取方案](https://github.com/PaddlePaddle/PaddleNLP/tree/develop/slm/applications/information_extraction)。
4. OPF保留为冻结对照及候选二阶段，不再预设为所有中文字符串必经模型。英文GLiNER不占首轮主候选名额。模型替换必须新版本冻结，不忽略旧模型阳性后继续称为同一安全策略。

### 公共算法的具体组成

- **输入与结构：** 原事件不可变，宿主协议结构与正文分离；JSON解码、Unicode对齐、原文与派生副本凭证检查继续完整覆盖。利用字段和相邻句的上下文，但不能因用户输入自称public/trusted就免检。
- **候选发现：** 电话/邮箱/证件/金融账号复用规则、格式校验和上下文；中文主NER覆盖全部可处理正文，英文片段补足识别。校验位失败不能直接认定不是隐私；没有正则命中也不能跳过NER。新增微信/QQ等账号先按明确个人账号字段/上下文纳入新策略，不把所有技术标识符当账号。
- **上下文决策：** 区分联系人、收件人、住址与研究讨论的城市/公开书目信息。姓名和具体私人地址缺乏可靠公开来源证明时保守遮盖；不得根据人名常见、疑似作者或一个关键词直接放行。具体地址定位应覆盖楼栋/单元/门牌，行政区划词典只能辅助，不能代替地址识别。
- **跨度融合：** 统一为原文start/end、类别、来源和置信信息；分类别校准后处理重叠/嵌套与地址边界，禁止无条件并集或将不同工具分数直接比较。初版复用Presidio接口和确定性策略，必要时才用合法标注开发集拟合小型校准器。判定不了的样本进入隔离/复核，不以静默放行换低拒绝率。
- **有限二阶段：** 给主识别器的冲突、疑似地址及难例调用第二个成熟识别器；主后端仍须覆盖所有正文，二阶段触发规则必须验证盲点，并对未触发样本抽样审阅。不能假设所有漏检都会带低置信信号。
- **一致替换：** 原位替换敏感跨度，同包同实体别名一致，保留动作、约束、数值、单位、公式和必要引用关系；不跨用户保存映射，不改正常执行原件。具有明确私人引用性质的路径/链接脱敏，可靠宿主来源的公开引用走独立可审计策略。
- **执行：** 按长度批处理，模型按受限worker复用；正文及结构凭证视图按来源去重，只复用同事务等价检查。长文分块必须覆盖全文并验证边界，不裁掉尾部。计入冷启动、排队、失败恢复和二阶段调用成本。

### 如何验证是方法改进

先解决24条语义控制原因缺失和现有回归失败，再冻结少量中文分层开发集。对照使用相同数据、类别和硬件：原公共基线；更换中文NER但不改融合；增加上下文/跨度融合；增加批处理/选择性二阶段。分别报告中文正式、聊天、混写的实体完整遮盖、确认误删、金标外遮盖代理、拒绝、超时、任务约束保留与端到端时延。公开人名引用/城市、中文个人姓名/昵称、完整地址、联系方式、混写代码及错误日志都要有反例。中文地址/姓名单独设门槛，不只看总F1。开发完成后完整旧基准回归与独立来源留出并行报告；真实RSI后继能力收益仍需另验。

本修订仅落设计记录，尚未安装或选择新生产模型，没有启动基准任务或修改正式服务。

### 保留的边界与仍未覆盖的范围

- 正常任务和独立认证按原权限读取原件；学习/共享只消费派生副本。Web、SDK和离线指向共同内核，TS没有另写NER。宿主生成的结构与正文分开，任意JSON不能声明自己可信。
- 同包实体别名、Unicode原文坐标、严格JSON/重复键拒绝、完整输入/输出凭证检查、原子写入及失败后不回退原文均保留。别名化不等于不可重新识别的匿名化。
- 私有本地导出与显式公开导出不同：`admit_publication`是保持认证字节的拒绝型门禁，不会自动修改并重新签发产物，也不负责用户同意或接收端授权。
- 当前检测核心是文本/JSON；二进制与不支持内容会省略。不能声称图片人脸、音视频、未提取附件、隐含身份关联已全面脱敏。正文语义本身也可能重新识别人，外部共享不能仅以NER阴性作为授权。
- 静态调用点核验不能证明将来所有新学习入口自动接入。新增入口应继续有“正常执行原件不变、学习副本被遮、拒绝不降级、导出不绕过”的契约检查。

### 下一版实施及验收设计

1. **先修可观测性和测试自身。** 给24条语义控制补固定拒绝原因、实际配置摘要及各阶段计时，单个合成样例验证错误路径后再跑小组；定位两个全量回归失败，不能标成不相关或flaky。不重启全量GPU作业。
2. **统一契约，分开识别与准入策略。** 宿主结构投影 → 凭证多视图扫描 → 明确身份字段处理 → 正文按类别识别 → 同包别名/原位替换 → 最终凭证/结构检查。凭证全覆盖，规则未命中不能作为跳过姓名NER的理由。所有正文都须由已验收识别器覆盖；疑似/超时材料隔离，不能当作安全。
3. **先优化调用，再比较少量模型。** 复用Presidio批API，按长度组批、按原始字段保留坐标/上下文，不拼接无关用户文本；请求内去重，模型常驻但不保留用户词表/跨账号预测缓存。中英混写不能按“有汉字就只跑中文”切换。保持原始输入不截断；必要分块须重叠、边界合并和完整覆盖检查。优先比较现有组合优化版、Stanza中文候选、一个英文ONNX轻量候选，而非同时堆叠所有模型。
4. **模型/策略改变要单独冻结。** 按PERSON、具体地址、联系方式、证件/金融、私有引用、凭证分别决定识别器/条件；研究URL、DOI、版本号、工具名和公式作负例。OPF疑似秘密的处置是单独策略版本，不用统一0.9渲染分数充当置信度。仅能证明公开性的引用才考虑保留，不以任意URL自称公开绕过。
5. **小开发集后才完整冻结评测。** 从三个基准固定抽取语言/类别/长度分层开发样本，额外纳入全部已知失败与24组语义控制；先完成阶段归因、质量与耗时估算。再冻结候选，在完整原基准回归，并增加独立来源留出；旧基准已经见过，不称独立测试。开发阶段可单独跑原生凭证全量与公共模块小组；发布验收仍须测整条公共管线，不能用前者替代后者。
6. **验收同时要求覆盖、保留和可用性。** 维持旧完整覆盖丢失0、额外金标外遮盖≤0.1个百分点、片段保留降幅≤0.5个百分点、120/120语义控制及入口正常准入/秘密拒绝；超时和工具错误单列。补每阶段冷/热耗时、p50/p95、字符/token吞吐、总wall time、显存及worker设备映射。速度目标等小样本测量后再冻结，不编造预计倍速。最后完整回归和真实RSI/桌面验收分开报告。

## 已定位问题与待证假设

1. **隔离环境真实路径错误，已证实。** 新目录的`regression-env-v5`是指向原隔离环境的符号链接。回归脚本把链接路径写入两个Python变量；`geneloop_shell.ts::commandArgv`核验解释器安装根目录，`fixedDirectory`要求绝对路径与真实路径相同。21项Node失败直接命中该检查。保留守卫，改调用配置；不能为测试删除真实路径检查。
2. **候选结构字段误识别，已有直接证据。** 当前`_learning_view`遍历JSON键和值并对字符串做NLP；协议词保护范围不足。此前同源候选预检将格式常量替换为私有引用、工具名替换为姓名别名。新增`_validated_learning_view`能拒绝被破坏的轨迹，却不能使正常轨迹可用。最终6个正常入口拒绝与此一致；修复前仍需留存每个拒绝的阶段归因，不把所有拒绝自动归为同一原因。
3. **候选凭证误拒不能全部归给CredSweeper。** 配对汇总的拒绝原因是凭证命中4260、策略拒绝271、scanner_timeout19、歧义JSON6、processing_failed1。凭证命中还可能来自OPF的`secret`标签，现有汇总不足以拆出每个检测器的责任。原生CLI与公共内存适配的文件上下文也不同，需要同字节、同过滤条件的配对检查。
4. **OPF成本与超时，已定位到阶段但未完全解释。** 旧CPU诊断停在原始模型前向；GPU单样例探针成功。混合批次仍有229个外层超时，不能假定全部都停在模型，也不能用加长期限掩盖问题。须记录排队、完整性核验、各检测器、渲染和冷启动的独立耗时。
5. **PPT与SDK缺产物是下游症状。** 11项PPT失败尚未读取到保留的认证失败回执；2项额外Node失败的现有断言未提供充分底层输出。SDK文件缺失也未获得明确阶段原因。实施时先留存这些失败的最小证据，再判断是配置、隐私拒绝或其他产品缺陷，不伪造缺失文件。

## 公共契约调整

复用现有投影器、JSON Schema、宿主引用映射和Presidio识别/替换，不新增NER、独立学习存储或平行规则引擎。

| 数据 | 处理设计 | 必须保留的约束 |
| --- | --- | --- |
| 宿主生成的协议常量、枚举、事件类型、节点序号 | 由已校验Schema和投影器构造，不交给通用NLP改写 | 凭证检查仍覆盖整个输入；任务JSON不能声明自己是可信元数据 |
| 自定义工具标识、私有路径、账号及证据引用 | 复用已有宿主引用机制，生成包内一致的不透明标识；无法安全绑定时拒绝派生样本 | 不能把所有`tool`字段原样放行；不能在识别后从原件偷偷恢复私有字符串 |
| 用户/模型文字、工具参数和观察正文、描述、实际default/const/enum | 原有公共PII检测及Presidio替换；保留关联字段和必要上下文 | 键中也可能有隐私；嵌套JSON、数字文本、Unicode坐标和重复键拒绝规则保留 |
| 凭证与秘密 | 输入原文、解码内容、派生结果均走统一检查；明确命中拒绝学习包 | 不允许通过结构分类、转义、别名、工具声明或任务自带跳过字段绕过 |
| 正常执行及独立认证的原件 | 仍由宿主按原权限读取 | 脱敏只改变学习/可选共享派生副本，不能降低原任务能力 |

可信类型信息只能由宿主校验后的投影过程传入；通用JSON入口默认无此信任。Web、SDK、离线导入、研究和导出调用同一实现及配置。若工具引用映射影响现有Schema或消费者，必须版本化并同步跨语言校验和宿主解析；映射表留在原账号/会话，学习材料不携带反解表。

`_validated_learning_view`继续作为最后一道不变量检查。验收目标是安全且结构正确的正常材料能够准入，不能仅靠拒绝所有材料满足不变量。

## 识别与性能调整

- **先做组件归因。** 对每个新增遮盖和拒绝记录检测器、规则/标签、结构路径类别、原文坐标、阶段及安全原因码；内容与逐条证据仅保存在私有目录。分别测原默认、默认+CredSweeper、默认+OPF、三者组合，避免同时变更后无法定位原因。
- **凭证先验证成熟扫描器适配。** 保持Gitleaks与CredSweeper现成规则、默认ML过滤和固定版本；对同一内容比较原生与内存Provider的扩展名、行上下文和过滤差异。宿主提供文档类型时只使用已校验类型，不公开私人文件名，不信任客户端路径作为排除依据。OPF的`secret`新增命中单列评测，未查清前不默认启用，也不把其阳性简单放行。
- **PII先修结构，再处理正文误删。** 复用Presidio的实体结果、上下文接口和替换器，按类别评价模型增量。OPF适配器的0.9是渲染优先级，不是可信概率，不能拿它调整置信门槛。字段标签、协议词、任务动作的反例进入开发集；不针对基准人名、固定工具名添加特例。若需要新阈值或融合规则，先在开发集决定，再冻结到新的版本，以独立来源确认；旧基准不再称未见集。
- **GPU只做显式后端。** CPU/GPU分别固定Torch构建、模型及配置摘要，保留依赖与字节守卫；不静默换设备、精度或推理实现。现有私有CUDA补丁不等于公开产品支持。先验证单worker和固定小批次，再依据实测资源设置并发；保留120秒总期限，排队计入，不跳过失败检测器。
- **减少重复而不绕过检测。** 先量化重复扫描的实际成本；只在同一派生事务、完全相同输入字节及规则/模型摘要下复用结果，不跨账号保留原文预测缓存。原文与派生结果仍各自校验，改变上下文不能复用旧结果。

复用依据：[Presidio结构化批处理实现](https://github.com/data-privacy-stack/presidio/blob/main/presidio-analyzer/presidio_analyzer/batch_analyzer_engine.py)、[Gitleaks固定版本](https://github.com/gitleaks/gitleaks/tree/v8.30.0)、[CredSweeper架构与过滤说明](https://github.com/Samsung/CredSweeper/blob/main/docs/source/overall_architecture.rst)。这些上游能力不代表GeneLoop当前适配已正确，也不授权改用上游main版本。没有计划调用收费云脱敏API。

## 实施顺序与验收

1. **配置与失败证据先闭环。** 新隔离实验使用真实Python环境路径，同时固定`SSS_PYTHON`/`SSS_PURE_CODE_PYTHON`；预检解释器、Node、沙箱、socket及子进程挂载。为缺文件和broker断言保留状态回执、退出码和安全stderr，定向重跑34个回归失败及SDK失败。11项PPT、另2项Node在复验前保持未归因。补齐Linux可安装的PDF/OCR/渲染及可选依赖，逐项说明仍跳过项，不用新增skip求绿。
2. **修通通用结构契约。** 修改`geneloop_privacy.py`、`geneloop_learning_trace.py`及宿主引用边界；复用现有Schema/版本机制。定向检查宿主常量不变、私有工具标识不泄漏、伪造元数据不能绕过、JSON/Unicode/身份键继续检测、原件可读。Paper/PPT/Coding的6项正常控制应准入，3项秘密控制应拒绝；其后补跑全部9场景接线。场景检查不是benchmark替代品。
3. **按组件冻结新候选。** 先用已有开发样例和新合成反例比较四种组合；对高误删及高误拒类别私下审阅，不改旧金标。仅在结构与组件检查通过后，冻结源码、依赖、策略、设备和配置，运行三基准。CPU/GPU同样例完整配对须单列；旧混合结果原样保留。可在已记录总额下先给小批次耗时/显存预估，不直接再启动十小时级任务。
4. **质量后再全量工程回归。** 每类报告完整/部分/零遮盖、金标外遮盖、任务约束、准入后残留、拒绝及未知；不删除不利类别或超时分母。沿用旧采用门槛：既有完整覆盖丢失0、额外金标外遮盖最多0.1个百分点、片段保留降幅最多0.5个百分点、120/120语义控制；这些仍是代理检查，不足以证明零泄漏或真实RSI质量。新增所有入口正常样例准入、秘密拒绝和结构不变量门槛。随后跑`npm test`、smoke、Motif及入口检查，审计跳过项、JUnit身份和输出。
5. **记录与交付。** 在PR162的Draft中更新聚合结果、限制和复现方式；是否推送按后续实施结果交付，本设计本身未提交。保留旧结果，不关隐私Issues，不改生产。真实RSI任务质量、桌面/Mac和正式共享接收端UAT继续单列未验证。
