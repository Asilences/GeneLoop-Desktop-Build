## 一、目标与反思

目标是让真实执行和能力构造反馈推动抽象与求解方式共同变化。质量、完整成本和后继能力获取过程分别评价。已有执行收益作为起点，新增机制的贡献通过后继行为和结果检验。

旧调查曾把已封装能力内部的`C,C,report`误作模型每次重新编排的负担。另一些任务存在真实质量问题，却没有进入那轮调查输入。因此，本协议把当前能力、实际经历和质量/费用反馈放在同一证据空间，并保留观察层级。

Evolution自主选择问题、调查反例并决定是否提交候选。具体旧错误属于可查询线索。初始目标保持为调查这批经历中的改进机会。

```text
真实任务与构造 → 来源/任务/运行及独立反馈
    → 小概览 → 经历检索 → skeleton/局部过程 → 原件
    → Evolution调查决定
        ├→ proposal → 原接收器和独立验收 → 后继实际使用 → 效果
        ├→ no_change → 保存依据
        └→ inconclusive → 保存证据缺口
    → 新执行、决定、结果和费用继续进入同一调查体系
```

## 二、来源、任务与运行身份

| 身份 | 含义与定位 |
| --- | --- |
| 来源实例 | 实际输入字节及版本，使用原source_sha256/FileRef |
| 来源家族与派生关系 | 同一论文的PDF、LaTeX、提取文本和派生片段关联到原件，保留版本及转换依据 |
| 任务 | 对资料的具体目标和条件，用原题面/契约摘要定位，概念上对应task_spec_hash |
| 方法版本 | 原代码、能力库、策略和有效配置的精确版本，概念上对应method_version |
| 运行 | 一次实际求解，用原task_id、run_id和事件引用定位 |

这些是现有记录的联合研究视图，实施先查找已有等价字段。资料字节摘要定位实例，来源家族关系约束独立性。PDF和从它提取的文本各有摘要，但共享来源；同一来源上的不同任务分别评价。来源关系不清时独立性标未知。

五篇实验为五个论文来源、一个BibTeX任务家族、三种条件和每项两次重复，共30次运行。重复和版本差异分别记录；推广范围依据资料与任务家族的独立支持确定。

## 三、完整轨迹与可展开skeleton

原始事件、输入输出、代码及回执完整保留。Skeleton是原运行的可展开投影，保留可观察的模型动作、能力/工具调用、产物、实际参数关系、失败、修复及评价位置。

| 证据强度 | 含义 | 处理方式 |
| --- | --- | --- |
| Observed | 原事件或回执直接记录的调用、参数、返回值、状态及显式绑定 | 引用原事件，维持原事实 |
| Supported interpretation | 由代码、原件、oracle或受控重放支持的解释 | 记录支持方法、范围和反例 |
| Hypothesis | 待检验的根因、可避免成本及改进方向 | 写入调查笔记和候选假设，等待评价 |

调用顺序、数据依赖与因果解释分别表示。相同值不自动生成参数依赖，读取同一中间文件的两个检查也不增加独立根因数。推测的因果边留在解释/假设层。

示例仅说明证据语义：两次检查读取同一中间结果，可以支持它们共享该数据；解析算法是否为误报根因，需要进一步比对原输入和实际处理过程。

已认证Capability默认折叠为一个节点，按需读取其内部图、接口和回执。节点保留精确版本和失败状态。该投影复用原事件、Capability图、Binding及FileRef，继续沿用原Registry和IR。

## 四、能力可用与局部问题已解决

上下文分别表达四项事实。

1. 能力存在且具有明确认证范围。
2. 当前输入满足该能力的适用条件。
3. 当前运行实际调用了该版本，产生何种状态和结果。
4. 结果具备支持当前子问题交接的证据。

具备调用接口只支持“可用”。输入被拒绝时保留调用尝试；成功回执支持实际执行；当前质量与后续用途仍按对应证据评价。折叠内部实现是展示选择，能力目录和已解决工作在概览中分别呈现。

历史完整`C,C,report`重复图在学习/编译中有拒绝记录，局部`C→report`学习、发布和后继执行已有历史证据。完整高层图闭包保持已知限制，具体范围见主线交接原记录；本轮未重跑该编译器问题。语义经历调查可以先沿原事件投影推进，完整图闭包单独追踪。

## 六、调查决定与候选范围

调查决定取proposal、no_change或inconclusive。工具、传输或程序故障另外记录机制错误及恢复位置。

- proposal表示形成了有依据的候选，进入原接收流程。
- no_change表示完成当前范围调查后决定维持方法，保留支持该决定的依据。
- inconclusive表示材料、归因或评价不足，保留尚未解决的问题。

只有proposal具有产物类型，取capability、task_strategy、construction_strategy或boundary。no_change和inconclusive属于调查决定，候选类型及候选引用留空。

每次调查的决定视图包含scope、problem、supporting_evidence、counterevidence、hypothesis和expected_behavior_change。proposal另附kind/proposal及falsification_condition，映射原burden、expected_behavior、verification、failure_conditions和note。未找到反例时记录搜索范围及未找到的事实。原接收器和Runtime协议继续使用。

| 准入范围 | 提出候选的依据 | 扩大范围的条件 |
| --- | --- | --- |
| 局部任务或限定输入 | 单例即可调查和提交，明确限制并独立局部验收 | 额外资料的评价支持 |
| BibTeX任务家族 | 跨独立来源的共同问题或局部候选向外验证 | 家族内独立评价及范围条件成立 |
| 跨任务家族策略 | 多家族支持及明确条件 | 相应跨家族评价 |

独立来源数量影响批准范围。现有至少两来源约束要定位到具体调查/提交/准入位置，仅作必要兼容调整；旧路径默认要求保留，新增局部范围明确表达。单例候选通过局部检查也只取得局部准入。

## 七、发现、开发验证与封存评价

| 角色 | 用途 | 暴露规则 |
| --- | --- | --- |
| Discovery Evidence | 调查历史经历、已公开质量和成本，提出假设 | 可被调查工具查询 |
| Development Validation | 构造、修复及筛选候选 | 反馈一旦用于修改，记录为已暴露开发材料 |
| Sealed Evaluation | 候选、标准和输入冻结后的独立结果评价 | 答案及未公开工件隔离于发现/生成工具 |

旧split和evaluation_role等字段映射这三种用途，实施以已有协议为基础。相同资料的派生物和重复运行保持同一暴露谱系。封存评价结果若用于下一轮改进，资料随之进入已暴露经历，后续封存评价需要新的合格材料。

五篇均参与旧研究，本轮切分用于历史机制检验及回放。本批没有必要字段缺失或重复键正例，评价覆盖应如实记录。真正未见泛化需另设新材料，覆盖扩充与原五篇成绩分列。

本批优先原确定性oracle。解释性质量如需LLM judge，另行冻结标准、输入范围及费用，先校准正确与错误对照。评价事实与语义解释分别保留。

## 八、产物接收、选择与采用

| 产物 | 接收位置 | 实际采用的证据 |
| --- | --- | --- |
| Capability | 原能力池、Runtime及Builder材料 | 精确版本的真实调用回执，附调用状态和使用位置 |
| Task Strategy | 任务模型上下文或可发现包 | 读取/选择之后，后继行动中可定位的策略行为 |
| Construction Strategy | Builder上下文 | 后继候选生成、分解、组合或修复行为的变化 |
| Boundary | 原学习、编译、认证及版本流程 | 新版本认证后在后继执行或构造中的实际使用 |

host_selected表示宿主指定供给的产物；model_selected表示模型在有效候选中自行选择，也可拒绝全部；executed记录实际调用或策略行动。三类事件分别保留，可在同一运行同时存在。

显式selection可以先检验接收，报告选择来源。策略自述和读取收据支持暴露/选择事实；策略实际行为另行定位。行为符合策略属于可观察采用证据，其因果归因仍需比较。

本轮优先已有接收器，未支持类型记录pending。完整路线可增加有限候选的条件Prompt选择。每个任务或构造开始时冻结版本，新成果默认进入下一任务。接口和表示变化优先落到已有能力/边界版本；真实Harness代码改动单列工程审阅。

## 九、多维研究视图

保留原事件，分别投影以下维度，禁止合并成单一线性生命周期。

| 维度 | 结果 |
| --- | --- |
| 调查决定 | proposal / no_change / inconclusive |
| 独立验收 | passed / failed / unknown，附检查对象和范围 |
| 实际交付与采用 | exposed、read、host_selected/model_selected、executed各自的证据与时间 |
| 后继效果 | positive / negative / mixed / neutral / inconclusive，附质量、完整成本、耗时及构造指标 |

neutral表示按预设比较标准未观察到差异；inconclusive表示证据不足。收益方向以预先冻结指标判断。技术错误、取消和断点独立记录；pending/rejected等旧宿主事件保留，并映射到原因和相应维度。

示例：策略验收passed、host_selected、真实executed，同时质量提高而完整成本增加，后继效果为mixed。另一候选可以验收passed、实际采用，但质量相同且成本更高，效果为negative。两种情况下，采用事实继续保留。未来撤回或归档也保留这些历史事件。

## 十、抽象贡献与归因

| 证据层次 | 支持的判断 |
| --- | --- |
| 看到或读取C | 模型获得过材料，实际使用和贡献待查 |
| 精确调用C | 该运行发生执行使用，附结果状态 |
| C进入后继构造 | 保留构造引用、编译依赖及实际执行引用，分别报告 |
| 可比较对照 | 在冻结条件下支持成本、质量或构造过程的差异 |

执行引用、构造贡献和Creation Value分别保存。把C去掉使某个既有程序无法执行，只能说明该程序的依赖；后继获得成本的贡献还需要允许重新规划或直接实现的对照。

对照先冻结目标、质量标准、材料暴露、模型、工具和资源政策，分别记录候选形成、检索、认证、失败与修复支出。可执行C、只有描述以及原基础材料等条件按待检验假设选择，第一轮不要求穷举全部消融。

历史Baseline可用于定位。跨版本、缓存和暴露差异需列出，可比性不足时效果保持inconclusive。长期因果Creation Value可pending，初期先交付可追溯贡献和限定对照结果。

SI可以体现为效率或性能改善。递归性进一步要求已有成果参与并改变下一轮能力获得或改进过程，后继成果再能进入同一机制；持续加速需要另有跨轮次结果。

## 十一、资源与终止

费用和请求上限显式null表示用户本次授权不限，0禁止新增付费；缺失配置按原宿主解析并在启动前显示有效值，不能静默转成不限。候选无权提高运行边界。

启动前须冻结有限的调查动作数、截止时间、候选及修复次数、可展开记录范围、单次读取大小、取消及续接规则。具体值由宿主运行配置给定，本稿未启动运行或指定新付费额度。调查步骤统计搜索、读取、笔记、提交等实际工具调用，复用原Harness计数，先明确各计数口径。

正常结束包括模型finish、候选流程完成、动作或时间达到边界；证据不足留下inconclusive，有依据的维持方法留下no_change。模型迟迟不finish时仍由有限步骤/期限结束。重复检索不产生新证据或同错修复达到既定次数时，保存原因和断点。

取消或失败保存已读范围、笔记、候选/修复用量、实际请求归属和执行中任务状态。恢复沿原账本与候选谱系续接，同一调查的逻辑额度继续累计。外部子过程沿既有取消和回执机制核对执行状态后再重试。

调查范围、评价器、权限与生产配置由宿主确定，读取到的论文、工具输出和模型回答作为证据处理。任务版本起点冻结，演化成果按后继任务发布。

## 十二、首轮Gate与放行结果

| Gate | 真实验收 |
| --- | --- |
| G1 自主调查 | 从中性入口自主选问题，读取所需原件、支持与反例，保留未读范围 |
| G2 自主决定 | 有依据的候选、no_change或inconclusive，明确范围与可检验条件 |
| G3 真实接收 | proposal进入原接收器，记录版本、准入范围和选择来源 |
| G4 独立验收与采用 | 分别提供评价结果、调用/行为及效果指标 |
| G5 反馈回流 | 新事实进入同一证据体系，下一轮可以按原工具查询 |
