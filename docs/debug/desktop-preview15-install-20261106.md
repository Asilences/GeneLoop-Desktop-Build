# Windows preview.15 安装提速

## 问题与依据

用户报告 preview.14 停在安装／写入阶段，约11分钟后安装成功。现场安装已结束，未取得逐阶段进程采样，因此不能将11分钟全部归因于单一环节。

实际 preview.14 载荷为40,321个文件、2,735,600,446字节。Python占17,125个文件，ppt-master占13,022个，LibreOffice占9,127个；JS运行时已封进ASAR，但这些工具仍逐文件落盘。全载荷含5,807个测试路径文件和6,672个Python缓存文件，两者重叠，不能直接相加。

锁定的electron-builder 26.18.0中，普通7z安装路径先解压至临时目录，再用NSIS `CopyFiles`复制到目标目录。覆盖安装还需移除旧文件；界面的“解压并写入”提示覆盖整段引擎执行，不能用该文字区分清理和解压的时间。

## 修改

- 仅裁剪生成后的Windows工具副本，源工具、旧安装包及用户安装均不修改。移除Python测试材料和不匹配的缓存；保留`numpy.testing`、`numpy._core.tests._natype`及匹配内置解释器的字节码。保留完整锁定ppt-master模板、图标和许可证。
- 使用公开的NSIS `customFiles_x64` 接缝调用系统.NET的Unicode ZIP解压器，直接写入目标目录。NSIS继续负责原应用ID、旧版本卸载、提权、进程检查、快捷方式、注册与用户数据保留。引导包仅包含标记，完整载荷以独立未重复压缩的资源内嵌；卸载仍使用原NSIS整目录清理逻辑。
- 写入前校验完整载荷SHA-256、文件数量和总大小，拒绝越界路径、重复目标及目录链接，保留文件时间；安装注册的大小由构建时计算，避免再遍历整套文件。旧ZIP插件的UTF-8中文文件名问题使`useZip`方案不适用于该载荷，最终未采用该配置。[构建器接缝说明](https://www.electron.build/nsis/)
- 完整离线包继续包含工具。ZIP构建默认压缩等级1，可用`ELECTRON_BUILDER_COMPRESSION_LEVEL`覆盖；不增加安装后下载或首次启动解压。

## 验证与失败

实际包中原场景MCP检查通过：80项DSH工具注册、数据与论文入口、文件副本整理、PPT／Office交付及源材料转换、来源变化拒绝。模型请求0；这是工程诊断，不是六场景真实模型质量验收。回执保留在私有`.local/preview15-windows-tools.log`。

首轮裁剪移除了NumPy运行时实际引用的`_natype.py`，检查失败，已恢复该模块。随后冷启动检查因缺少匹配版本缓存而超时，恢复原408个Python 3.12缓存后复验通过。两份失败日志分别保留`.local/preview15-windows-tools-first-prune.log`、`.local/preview15-windows-tools-cold-start.log`，不得用最终通过覆盖失败证据。

原`nsisunz`候选在解压中文品牌目录时失败并出现乱码，日志保留`.local/preview15-benchmark-legacy-zip.log`，该候选未交付。改用.NET后，中文文件名、路径越界、错误哈希及目录链接四项微型检查通过；入口为`npm run check:installer-payload`（`apps/desktop`），不安装、不写注册表。NSIS引导打包阶段曾出现重复大小定义与辅助目录缺失，已修正；失败与最终构建日志分开保留。

旧流程复用锁定的原NSIS插件，新流程调用最终.NET组件，在系统临时盘的独立目录依次执行；不写注册表、不调用旧卸载器、不操作用户安装。计时不含外层WPF提取引擎、旧版本移除和注册表步骤，不能直接等同于完整覆盖安装时间。结果与交付摘要以本轮私有回执和[桌面交接](../handoffs/desktop.md)为准。

旧流程未完成，不计算精确提速倍数。实际新包中的核心文件与预打包目录SHA一致，解压后的NumPy/Pandas/SciPy/MCP导入通过，13,016个锁定PPT文件逐项哈希一致。安装包976,437,760字节，比preview.14的779,485,184字节大；这是完整离线包的封装取舍，不代表解压后空间缩小。

本轮仅更新Windows预览包，不重建Mac、不发布Release、不上传安装包，正式服务及两个并行模块的核心逻辑不变。

## 2026-11-07 完整覆盖实测与修订2

用户报告原preview.15仍需约8–12分钟。本轮在用户授权管理员弹窗后，对现有安装顺序做同版本、相同应用载荷的完整覆盖；保留账号与AppData，不要求先卸载。原包本机复测344.98秒，不否定用户此前观测。原包的旧卸载器曾产生约2.1GB搬运读写：安装在D盘而临时目录位于C盘，NSIS的逐文件`Rename`变成跨盘复制／删除；原解压器128KiB输入缓存又在ZIP成员定位时重复读取邻近数据。

第一步改为同盘暂存、4KiB ZIP输入，完整覆盖225.58秒，安装器内部实际阶段203.52秒；解压83.42秒，旧卸载器不再复制整套数据但仍逐个移动约三万个文件。第二步由宿主先整体备份旧应用，再让原卸载器处理最小旧入口，完整覆盖198.31秒，内部阶段148.26秒，包含解压95.37秒与旧目录清理22.99秒。

最终修订2在构建时生成嵌入的工具文件SHA-256清单，覆盖时先校验旧目录的完整文件集、长度及每个文件内容，再整体保留匹配目录。Python、LibreOffice、PPT素材、OCR、Chromium、媒体工具、场景源文件和原生运行依赖分别判断；变化或文件集不符就从完整载荷重新解压。没有下载依赖，也不通过关闭防护或丢弃工具提速。共享64KiB解压缓冲避免每个小文件分配大缓冲。

| 本轮顺序覆盖 | 启动至退出，含权限等待 | 安装器内部实际阶段 |
| --- | ---: | ---: |
| 原preview.15 | 344.98秒 | 未记录 |
| 同盘暂存＋ZIP输入缓存修订 | 225.58秒 | 203.52秒 |
| 整目录事务 | 198.31秒 | 148.26秒 |

权限确认等待不同，且顺序执行可能受文件缓存、防护扫描和系统负载影响，因此不据外层总耗时计算精确加速倍数。最终解压器阶段44.66秒（含旧工具内容校验），30,687个文件／1,903,256,750字节匹配并直接保留，旧目录清理约0.075秒。剩余76个文件继续解压写入。安装器返回0，安装版本`0.3.0-preview.15`，主EXE、应用ASAR与运行时ASAR均与冻结载荷SHA一致；实际安装后的Python常用库导入通过，模型请求0。新安装包的首次完整安装未实测，复用收益仅适用于有匹配工具的覆盖安装，不承诺新装也为83秒。

`InstallTransaction.cs`保留旧目录、相关注册表和快捷方式快照；复用目录移动前写恢复意图，失败先归还复用目录再恢复旧应用。多个不同路径的用户级／全机安装并存时沿用原NSIS处理。异常恢复或跨盘更换目标目录的失败现场保留私有恢复记录，不把断电自动恢复称作已经支持。临时目录使用受限ACL，清理只针对本次生成并带标记的目录，不清用户AppData。

两项Windows夹具检查`check:installer-payload`、`check:installer-transaction`通过：含中文、路径／SHA／链接拒绝、变化和额外文件回退解压、工具复用后失败恢复及更换目标目录恢复。最终安装包使用相同原应用载荷`3a7fea00f414b96ad7e4bb0db7ba6bbddae7fcbcde1c857b05ebaa044a55d2fb`，没有把未完成的工具接线工作混入。未跑整仓回归或新增真实模型调用。

最终本地交付`.local/deliveries/GeneLoop-Desktop-0.3.0-preview.15-installfix2/Windows/`，安装包981,932,544字节，SHA256 `942fd2f36a9d416c87ea2846be179988b806e3ec6498f7c982fc6e585aeebb85`，同目录含摘要和回执。私有逐阶段证据在`.local/install-verification-preview15-toolreuse-20261107/`；中间失败／成功与原包记录各自保留。旧安装包不覆盖，Mac不重建，安装包不上传，正式服务不改。
