## 原因与最小修复

原`read_converted_source`使用无具体类型的`dict`返回。服务器MCP 2.2.0将它编码为文本，未生成`structuredContent`。DSH对长输出追加spill文件说明后，展示内容不再是单个JSON，原严格观察器不能核验版本，回退普通Harness。它表示回执不可验证，不表示PDF没有解析成功。

本次在`scenarios/ppt_master/converted_source.py:source_read_response`生成显式MCP `CallToolResult`：

- `content`保留原完整JSON、Markdown正文、文件清单与路径，不裁剪源材料。
- `structuredContent`单独保留来源版本、Markdown SHA/字节数、路径和文件数等紧凑元数据。
- 仅在`ConvertedSources.read`核验来源权限、源文件版本、派生目录和Markdown当前字节后生成回执。文件变化、权限撤销、链接和目录注入仍拒绝。
- `server.py:create_server/read_converted_source`返回该显式结果。现有`observeHarnessToolResult`已支持MCP结构化权威通道，因此没有改共享观察器、忽略尾注或降低版本守卫。

工具名称、参数、描述、输出schema及两项已学习IR均不变。`scripts/reexport-ppt-receipt-compat.py`只导出新兼容包`ppt-master-v48`，旧v47不改，Paper50不变。兼容导出不是新训练、工具生成、科研质量认证或费用收益。
