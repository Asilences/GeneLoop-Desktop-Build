# preview.24 按需工具与资源管理

基于独立桌面分支preview.23 / `24a9c62b`。保留六场景和现有界面、DSH Agent/Function Calling及MCP，不修改上游内核或正式服务，不增加模型请求。

## 实现

- `general_tools.py`发现目录改为只读登记元数据及已取得的目录提示，不再逐个连接所有提供方。实际Schema仍由选中的`describe_tool`、准备和执行校验；未知提供方不因名称筛选消失，未连接可用性明确为未知。空`tool_name`可取得单个服务的完整目录。
- 沿用原MCP会话拥有者处理队列：空闲60秒退出，正在使用的租约不回收，达到连接上限时释放空闲旧连接。桌面每个Gateway最多2个连接，其他宿主默认4个。请求绑定具体提供方连接代次；重连不自动复用旧句柄/待执行指令，已完成和未知结果回执不重放。
- 原生重命令由TypeScript共用两条排队名额，覆盖同一DSH宿主的不同作用域；取消和超时覆盖排队及实际执行。场景工作流每轮最多2个，同类替换先关闭旧进程再启动新进程。有状态场景保留到显式关闭或任务结束，避免为了回收误丢状态。

## 诊断与边界

新回归用真实stdio MCP子进程核对零启动发现、单个提供方启动、空闲退出、旧请求失效、连接上限、长工具不被回收、排队取消、关停和未知结果不重放。确定性诊断，不是模型效果或内存节省百分比。

首次真实DSH命令检查发现按服务查询对象计数会被Cordis作用域代理绕开（3条启动），已改按公开`ctx.root`统一计数；原失败日志保留。修复后实际7个子进程的重命令峰值2，排队取消/超时未启动子进程，运行中取消已回收。小型单元检查只作为排队错误诊断，不代替该真实进程检查。

`npm test`按首错停止：70通过后遇Windows创建符号链接权限`WinError 1314`，未完成全仓回归；记录`.local/preview24-npm-test.log`。普通桌面检查14项通过；受限进程中另一次组合检查的设置文件重命名报EPERM，该限制没有通过修改设置安全逻辑绕过。其余诊断日志在`.local/preview24-*`及`apps/desktop/.local/preview24-*`。
