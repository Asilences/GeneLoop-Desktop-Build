# 桌面本机 RSI、隐私投影与 HTTPS 收集设计

状态：0.4.1 已实现本机自动处理与接收接口；真实模型、实际包与部署状态以本轮交付记录为准。
原始审计日期：2026-11-17。
审计对象：桌面 0.4.0 / PR171 的 f0c85162；GitHub main 为 c4cbce6c。
本方案负责桌面宿主接线，复用隐私模块及 RSI 实现，不接管其算法开发。

产品要求（2026-11-17 修订）：学习与脱敏收集都是必经流程，不提供学习或收集开关；首次清楚说明处理范围，之后自动运行，不逐任务确认上传。


## 0.4.1 实现范围

- `local-worker` 从 DSH 原生会话事件取得当前任务经历，桌面宿主按服务器和当前登录账号隔离保存；恢复同一文件任务时保留逻辑任务身份、区分实际执行段。
- `LocalRsiHost` 在任务终态自动调用随包 Python 中的 `desktop_rsi` 适配器。复用 `geneloop_learning_trace.project`、Presidio/Gitleaks，不改隐私算法，不先上传原件再脱敏。
- 复用 `dsh_trajectory` 挖掘器、`compile_read_motif`、`certify_read_motif` 和 `run_read_motif`。当前可执行学习范围是本机受授权的只读材料获取流程；未知、写入、失败工具是屏障。两个独立会话作为训练，独立第三会话作为留出；没有真实参数传递的顺序不发布。结构认证不等于质量、费用认证。
- 通过独立结构验收的账号私有能力以 `local_motif_list/run` 提供给后继 Agent 自行选择。执行仍调用当前目录的实际读工具；旧网关不声明 `localRsiTools` 时不发送未知工具名。此兼容处理不关闭轨迹学习与收集。
- 学习或脱敏拒绝、无工具经历和收集待部署都有明确状态。数据与隐私页没有学习/收集开关或逐对象确认；首次本机任务说明固定处理范围。
- 新自动收集格式 `geneloop.rsi-collected-object/v1` 保留真实终态，仅含样本内工具编号和执行结局；旧手动共享 v1 协议保持兼容。它不包含正文、参数、路径、原工具名、账号、任务或会话 ID。
- HTTPS `POST /api/harless/rsi-collected-objects` 复用当前账号登录，严格校验对象，持久接收；GET 按新生成的对象 ID 核对回执。客户端重启/未知响应先查原编号，再重发同一对象。HTTP 仅供显式回环诊断。
- 本机学习不等于每个任务都会生成 Motif。通用语义 Builder、各场景特有的全部 Web 学习策略，以及把本机私有库加入三张总库卡片，不以本轮只读闭环冒充完成；当前进度在数据与隐私页可见。
- 服务器接收源代码随 PR171 提交；打包并不意味着 `geneloop.ai` 已部署该接口。正式服务器未更新时对象留在本机队列，界面显示等待服务器。

## 1. 结论与当前缺口

目标是：本机工作区在电脑上执行 Agent、工具、RSI 编排/学习/编译/验证和隐私投影；云端模型继续提供推理；服务器自动接收本机脱敏通过的受限对象。云端工作区维持服务器执行位置，同样需要接通自动学习与脱敏收集策略。

以下表格保留 0.4.0 审计时的缺口，不作为 0.4.1 的验收结论：

| 环节 | 当前代码 | 缺口 |
| --- | --- | --- |
| 本机 Agent、工具和恢复 | local-agent / local-worker 使用 DSH；工具和原任务在本机，模型/JEV 走网关 | 已接通本机执行，不等于完整本机 RSI |
| RSI 学习与后继复用 | 场景脚本/程序已随包；Web 宿主安装 account/Paper/PPT learning。部分本机 PPT 工作流明确 allow_rsi_update:false | 缺统一的本机学习控制、真实任务输入、认证/安装、后继调度与反馈；不能仅把该字段改成 true |
| 脱敏/结构投影 | 公共 Python/TS 投影器和 Presidio/Gitleaks worker 已有；桌面设置操作远端 API | 缺本机任务到公共投影器的宿主适配、就绪检查和本机视图管理 |
| 轨迹共享 | 面板从服务器 /tasks 选任务，服务器生成预览并发往配置的接收端 | 这条链路不覆盖本机聊天任务，不能让本机原始轨迹先上传服务器再处理 |
| 收集接收端 | 有 HTTPS endpoint 配置和发送器；项目文档明确正式认证/持久回执仍待验收 | 缺可核对的接收部署、持久化确认及重启后去重查询 |
| 本机学习库展示 | 三卡主要合并内置/服务端账号目录 | 缺本机私有学习库来源，不能把服务器开关显示成本机已学习 |

## 2. 目标数据流

~~~mermaid
flowchart LR
  subgraph PC[用户电脑：本机工作区]
    A[正常 Agent 与工具执行] --> T[本机真实任务事件与私有证据]
    T --> P[公共隐私投影器：本机运行]
    P --> L[账号内学习视图]
    L --> B[现有 RSI：发现候选与构造]
    B --> V[用私有原件独立验证与认证]
    V --> M[本机私有 Motif / Capability 库]
    M --> N[独立后继任务自然复用]
    N --> F[质量、实际采用和完整成本反馈]
    F --> B
    P --> S[受限共享对象：与私有视图分开生成]
    S --> C[本机自动收集队列]
  end
  C -->|仅 HTTPS 发送已通过本机投影的字节| I[GeneLoop 收集 API]
  I --> R[校验、去重、持久保存与确认]
  R --> G[团队研究 / 公共候选，另行验证]
  A -.正常任务模型请求.-> Q[云端模型网关]
  B -.获准的学习视图，沿用账号计量.-> Q
~~~

原始轨迹和私有认证证据留在电脑；私有学习与共享分别从同一冻结来源生成，不能把私有学习视图当成可直接上传的对象。投影样本不替代执行证据或质量证书。

“RSI 在本机”指其编排、状态、程序执行和验证在本机；不表示模型推理也在本机。JEV/模型必要输入仍可能经网关送往云端。自动收集与正常任务模型请求是两条独立数据通道，首次服务说明需要分别讲清用途和处理范围。

## 3. 正常执行到学习的接线

新增桌面 LocalRsiHost（拟议组件名），接在现有 local-worker / LocalWorkspaceConversation 生命周期上：

1. 在任务开始时固定账号、工作区、taskId、sessionId、实际工具目录和任务事件起点。
2. 复用 DSH session/event 与现有 capture_native_events，记录真实工具调用/结果。需要投影时生成有界、仅包含该任务的私有快照，不扫整台电脑或复制完整历史。
3. 原始 DSH 历史仍为执行与恢复依据；不以 UI 的 answer 文本重建轨迹，不记录媒体本体或另复制大附件。
4. 所有正常任务自动进入本机学习与脱敏收集流水线。取消/失败也保留为反例与恢复证据。现有共享 v1 只接受 completed；补齐真实终态的受限 schema 和接收能力后覆盖失败/取消，不把它们伪装成成功或绕过现有检查。
5. 恢复沿用原 taskId、会话和学习经历；区分实际新增事件与历史回放。不得把取消前后同一经历计成两个成功学习样本，也不改写原费用账本。
6. 任务完成/取消不等待后台学习。学习失败不妨碍用户收取已完成产物，不把未经处理的原件作为失败兜底上传。

现有 createAccountLearning 绑定 Web 的 32 位任务 ID、tasks 目录和 task-state.json；桌面有 UUID、会话恢复与不同目录。应增加共享的 TaskSource 适配接口，默认保留 Web 数据源，桌面提供任务描述与冻结事件读取。不要伪造一套服务器目录或复制整份 Web 任务数据库来兼容。

## 4. 本机 RSI 闭环

- 复用现有 Account/Paper/PPT learning、File 私有学习、Builder、编译器、验证器及反馈入口；不重写 DSH Agent 循环，不另建一套 RSI 框架。
- 先提供六场景共用的任务采集/隐私投影，再为各场景连接其既有学习器、实际工具契约及质量验证。工具已能本机执行，不代表该场景学习器已接通。
- 本机私有原件可供获准的确定性分析和独立验证；学习模型读取公共模块准入后的视图。中文正文学习沿用隐私模块当前关闭状态，不由桌面适配擅自启用。
- 参数流、工具绑定和真实质量证据在本机核对。工具别名/目录/源码变化后按原规则重新核验，不能复制证书或补一个“已认证”标志。
- 已验收候选进入当前账号的本机私有库；后继调度复用原 Runtime。显示“被提出、已验证、后继采用、实际效果”各自的证据。
- 学习所需模型请求复用现有账号、模型网关、任务绑定和计量；不借已过期的正常任务凭证持续后台调用。取消、失败、验证等开销纳入完整成本。
- 本机学习库按可信登录账号和服务地址隔离；账号切换立即停止旧账号的任务访问，未发对象继续保持原归属，不能借新账号发送旧账号对象。
- 学习必经不等于每次都要生成 Motif；没有新候选、验证拒绝或没有收益均是合法结果，保留实际反馈。自动模型工作沿用原账号额度与计量，额度不足进入待处理，不另造无限授权。
- 三卡默认仍是当前账号可见总库，可合并内置、服务端和本机私有来源；去重并保留来源，不能虚构层级或认证状态。

## 5. 本机隐私适配

复用现有 geneloop_privacy.ts / privacy_worker_pool.ts / geneloop_learning_trace.py：

| 用途 | 使用方式 | 能否上传 |
| --- | --- | --- |
| 账号内结构学习 | structure 操作；账号内工具代号和任务顺序/结果 | 自动执行本机学习；对外发送仍需生成专用受限对象 |
| 私有语义学习 | 现有模块和策略支持且准入成功时使用 | 原私有视图留本机，不扩大自动收集的字段范围 |
| 脱敏收集 | project 的 share 模式及已核验共享 schema | 本机检查通过后自动入队并通过 HTTPS 发送 |

结构模式与正文共享模式的依赖不同，不能把 structure 输出直接冒充已完成正文扫描的共享对象。共享链路继续运行原准入检查。

依赖探针在本机校验 Python、固定工具/模型版本、资产摘要及平台支持；Windows 与两个 Mac 架构各自验收。已打进安装包不等于能运行。工具缺失或结果未知时，暂停对应学习/共享，普通任务继续；不把原始材料发到服务器代为脱敏。

复用已有 worker 池、按需启动和回收，不为每个场景常驻一份 NLP/扫描服务。首版沿用当前受限结构投影，不为它额外塞入未启用的超大中文模型或语音组件。

## 6. 本机共享和 HTTPS 收集

新增桌面 LocalSharingHost（拟议），复用公共投影、对象摘要和发送状态管理；prepare/authorize 读取当前账号的本机任务，不向服务器上传原始轨迹再脱敏。任务符合处理条件后由宿主自动投影、入队和发送。

现有 createRsiSharing 使用逐对象预览/consent，不符合这次必经流程要求。应增加明确的自动处理策略入口，兼容旧客户端，不能只隐藏复选框、伪造 consent:true 或直接跳过原校验。首次使用说明自动学习、采集字段、接收方与留存，并记录适用的服务说明版本；后续不逐任务请求上传同意。实际接入需同步服务端策略，不仅修改界面文字。

前端显示处理状态、采集范围和内容查看入口，不接受 renderer 或 Agent 提交的任意上传字节、路径或目标地址。主进程负责读取已验证对象并自动发送。正常任务、学习与收集保持独立出口。

当前允许上传的仍是 geneloop.rsi-shared-object/v1 / tool_flow：

- 场景归一为 generic；工具为样本内 tool-0 等代号。
- 只含工具次序、重复关系、规定的结果状态；bindings 为空。
- 不含对话正文、工具参数/结果原文、源码、附件、文件路径、原件哈希、账号/会话/任务标识或反解表。
- 脱敏对象摘要仅标识这份已处理对象，不能改用原文件摘要作为跨用户标识。

这不等于完全匿名：登录和 HTTPS 连接仍可能让接收服务知道账号/IP。收集服务应把访问审计与研究样本分离，不把身份数据拼回训练对象。

收集 API 的建议接口为 POST /api/harless/rsi-shared-objects；这是待新增接口，不声称现已部署。复用原 GeneLoop 登录会话和来源校验，无需用户 SSH 或另行注册。

接收端只接受已有 schema 和大小限制内的对象，再进行独立准入；不接收 raw-events、任意文件或任意扩展字段。持久保存成功后返回 object_id、已处理对象的 sha256、receipt_id 和 accepted 状态。相同上传标识与相同内容返回同一回执，不重复计入收集或学习；相同标识而内容不同则拒绝。

本机持久发件箱只保存已处理对象与状态。preview_id 不是跨重启的稳定去重标识；另用宿主生成的稳定对象 ID 关联已处理内容和当前服务策略。断网持久排队并自动恢复；响应丢失标记 unknown，先查询回执，在确认未接收且去重机制有效时再自动重传。重启继续处理原队列，不重复入库。

正式发送只允许已核验的 HTTPS 接收地址，禁止重定向或携带原模型密钥。接收地址由已核验的部署策略提供，变更处理范围或接收方时更新服务说明；不得任意跟随重定向。未部署接收端时明确显示尚未接通，不能把本机学习成功当成已收集成功。

## 7. 共享结构对 RSI 研究的限制

当前 tool_flow 刻意没有参数和数据依赖边，工具代号也不提供跨样本语义。因此它能支持流程拓扑研究，不能单凭收集成功就声称可学习完整可执行 Motif 或证明 P0 效率收益。

如果后续确需跨用户的参数流学习，应由隐私负责人共同设计新版本：仅允许匿名节点之间的类型化端口/依赖关系，不含实际值、源码、字段原名或私人工具名；独立检查可识别性与质量影响后再启用。保持现有 v1，不静默扩大上传字段。

## 8. 用户界面与数据生命周期

“数据与隐私”改为信息与状态页面，不提供学习、收集开关，也不提供逐对象上传审批：

- 本机工作区：显示本机 RSI 学习、投影就绪状态、待处理数量和收集结果。
- 云端工作区：显示服务器执行位置与自动处理状态；后台未支持自动策略时显示尚未接通，不能仅删掉开关就显示已启用。
- 首次使用一次性明确说明：正常任务用于 RSI 学习；只将本机脱敏通过的规定字段自动发送至收集端。既有用户采用新处理方式前也要看到该说明。
- 正常发消息不反复弹共享框。用户可以查看处理范围、已处理对象和接收回执，查看功能不承担“是否上传”的审批职责。
- 工作区显示“本机执行 · 云端模型”；学习状态为处理中/无新候选/未通过/有候选，收集状态为脱敏待处理/待上传/已接收/接收待核对。

删除现有“启用账号内 RSI 结构学习”复选框和手动“确认上传”流程时，须同时接通自动执行策略；不新增替代的隐藏关闭选项。既有后台 API 可为旧客户端保持兼容，但新桌面不能把必经处理当作可选项。

用户取消正常任务、退出应用、断网、缺依赖或服务不可用是执行状态，不是开关。尚未完成的后台阶段持久记录并在条件恢复后继续；脱敏不通过的对象留本机待处理，不上传原文。注销/账号切换保持原数据归属。沿用已有留存策略，任务原件、DSH 会话历史、学习副本、上传对象各自管理，不能批量删除用户工作区。

Windows/Mac 原生日志物理删除须使用相应 SDK/文件锁能力；尚不能立即清理时显示待清理，不能以隐藏页面代替删除。远端已接收对象按回执和接收端规则处理，不能把本机取消说成已撤销远端样本。

## 9. 开发和验收顺序

1. 接本机任务事件、必经处理策略和能力探针；沿用公共投影器产出本机视图，证明任务会自动进入学习/收集流水线，界面无学习/收集开关。
2. 接已有学习器、私有库、认证与后继调度。各场景至少验证一次正常任务、独立后继采用及质量/完整成本；不以“生成了样本”代替闭环。
3. 接本机自动收集队列与只发已通过投影字节的 HTTPS 发送器，再部署/验收持久接收端、去重、断网续传和 unknown 查询。
4. 同步 Windows、Apple Silicon、Intel 的实际依赖清单；再交付新安装包。正式服务、安装包上传和 main 合并仍是独立动作。
