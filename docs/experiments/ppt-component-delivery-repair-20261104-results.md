# PPT 组件交付修复记录

实验 ID 为 `ppt-component-delivery-repair-20261104`。方案见[实施清单](ppt-component-delivery-repair-20261104-plan.md)。代码基于 `0bd1e3b` 和原工作区未提交修改，当前尚未提交或部署。

## 当前实现

- `ppt_design_preflight.py` 检查实际字体覆盖和可确定的纯色背景文字对比。使用环境已有的 fontconfig 工具，处理 CSS 字体引号与旧版 fc-query 的额外输出。复杂效果仍需看图。
- `design-profiles.json` 提供默认科研设计层级。字号和布局作为设计指导，实际页面继续由模型及官方契约确定。
- `create_ppt_page` 自动分配输出目录，绑定结构常量，按字段返回参数容量错误。原显式输出目录接口保留。
- `finalize_ppt` 为双方提供共同的 Generate 交付入口，复用官方检查、PPTX 导出、实际 Office 渲染和逐页 PNG。宿主可自动生成清单，明确使用总备注时通过官方脚本拆分。
- Harness 对已识别的标准 Generate 导出命令返回统一工具指引。原生往返、显式其他来源目录和帮助命令沿原流程。自由 Bash 的全部行为仍需另行审计。
- 检查回执保存在任务私有目录，绑定源文件、外部图片、字体/Office、profile及检查代码版本。相同版本复用结果，未改善的相同客观缺陷标记 stalled。
- 最终 present 的实际 PPTX SHA 与交付回执关联，再核对组件源 SHA。执行次数和进入交付的次数分别统计，组件弃用后手写不计成品复用。
- 后台 worker 从同内容/几何的缺字失败及实际交付成功记录中生成字体回退规则，下一任务冻结加载。只允许显式开放字体回退的项目使用，运行时重新检查当前字符和实际导出。两个不同来源的后续合格应用可晋级为该机械范围的 active，`quality_cost_promoted` 继续为 false。

## 认证范围与开发介入

保真模式保留原有文字、画布与源像素等价检查。新增字体修复模式与可读性修复模式，后者仅允许字体及 text/tspan 的 fill 改变，文字、数值和几何继续核对。XML 非显示空白与属性顺序允许变化。

真实 DeepSeek 进行了两次类型化程序生成，使用 Flash、thinking off、393216 输出容量。第一份修复字体后仍因历史页面的低对比文字被拒绝。第二份根据该失败反馈修复文字颜色，独立认证前又发现模型给出的默认换行参数与历史断行不同。开发者依据历史页面校准了断行参数，并把几何参数固定为 const，还为条目数组补充数量约束。生成的模型源码保持原样。此处属于开发介入，不能称全自主生成即通过。

修复组件只在训练原内容和一个开发者准备的 DINOv2 独立参数输入上认证。当前源认证通过尚不能代替完整 Office 交付、科学质量或费用验收。历史材料与前向测评保持隔离。

## 已确认的真实诊断

服务器进行了真实沙箱和 Office 导出诊断。字体学习链出现缺字失败、只改字体后的成功导出、生成一条规则、下一调用加载应用并成功导出。禁止字体回退的项目保持拒绝。该诊断没有模型请求，调用生命周期由诊断程序构造，不能称真实用户反馈的收益实验。

早期失败全部保留，包括缺少 fontTools、CSS 字体解析、fc-query 输出差异、SVG 命名空间序列化，以及官方检查报告写到非默认位置导致导出拒绝 stale。最终入口使用官方默认报告位置并保留原门禁。

C12最终候选在服务器完整回归通过，Python 1783通过/202跳过，Node 1484通过/4跳过，0失败。交付和原生组件工具定向检查9项通过，smoke、motif:check均0退出。实际Office字体学习诊断在C11重复通过，0模型请求。1392份本机/服务器源码与配置文件逐SHA一致，两个兼容库共10份原始Graph载荷逐字节保留。日志保存在候选的`.local/test-logs/`，原始材料不进入Git。

## 最终对照协议

前期 Adam 运行用于开发诊断。一条普通请求被旧客户端覆盖为 Baseline，发现后取消并保留费用。修正后的 Adam 预跑完成，但模型没有调用共同导出入口，因而增加 Harness 路径指引。以上运行均单列，不作为最终配对结果。

最终输入为 Layer Normalization 一页结论与 ResNet 三页汇报。两篇都未参与页面程序生成或参数校准。ResNet曾在C9开发预跑中进入材料读取阶段，随后取消，因此不能称完全未见留出。两组题面和输入一致，结论页要求三条贡献、两条边界、一句总结及四项讨论建议，使用上下分区，配色自主决定。该布局是所学组件的目标适用域。

C9的BatchNorm两组虽均completed，但均未调用finalize_ppt，优化组也未调用页面程序，不能将费用差归因于组件或RSI。调查发现带`$P`的正常导出命令漏过路径识别。C10改为识别导出调用并引导到共同入口，保留帮助、往返、Quick和其他显式来源。C9已在全部任务终态、pending为0及PID/start ticks核验后关闭独立测试Web，费用和原始证据保留。

C10的LayerNorm普通预跑实际触发统一入口，但第二次导出被来源守卫拒绝。复制真实项目在隔离沙箱复现后，发现官方生成的`validation/presentation.report.json`包含每次运行的路径变化，被误当成输入依赖。C11只将这份固定生成报告从输入依赖中排除，继续绑定SVG、备注、规格及其他校验文件。真实Office重导出通过，立即重复调用复用同一delivery_id，`reused_checks=true`，没有再次导出。C10任务取消后的112请求/$0.197906436保留为开发开销。C11最初仅预览兼容库的配置错误在付费提交前更正，初次中断的回归日志保留，最终完整回归在实际PPT59/Paper61下重跑通过。

两侧均启用同一 Graph 库并提供相同finalizer，B没有学习页面程序，O加载独立认证的历史页面程序。B是共同底座对照，包含既有Graph与共同交付工程。这次测量页面程序库的增量，不能称原始DSH对照。C11顺序为B1、O1、O2、B2，C12追加R01的B、O，全部串行。账户内结果缓存独立，云API历史提示缓存沿用并按实际用量记账。后台收集轨迹，任务准入时冻结库；本轮普通任务没有产生新字体规则或新晋级。

C11/R01/O的真实命令使用`python3 "$SKILL_DIR/scripts/svg_to_pptx.py" "$P"`，再次漏过导出指引。该次实际调用页面组件1次，但最终PPT没有共同交付回执，成品组件来源无法按本协议确认。C12在Harness守卫中识别脚本目录变量和花括号写法，加入真实命令回归，保留原有路由例外。C12两侧最终PPT均匹配共同入口的实际回执。该机制仍是已识别调用的指引，任意Python导入与自由Bash不在全面强制范围内。

模型沿用真实 Flash/off 和393216容量，费用及请求不限，原累计账本继续。学习/生成/认证与评审另计。任务内组件尝试、弃用、修稿、重试和恢复均计原组。费用为代理估计，账单实付与开发者人工分钟未知。

## 适用边界

当前自动学习的新内容为受约束的字体修复经验。页面程序的模型生成和历史导入仍通过显式离线入口，尚未接成任意正常任务结束后自动付费生成程序。现有 Graph 继续使用原读取结构。

实际渲染验收在 Linux Office 环境执行。复杂视觉、科研正确性及 Windows PowerPoint 打开效果需分别评审。机械检查和字号默认配置不构成这些项目的自动通过证据。
