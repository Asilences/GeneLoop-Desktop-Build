在隔离环境用两份新材料比较修复前后。G02 用 16 页材料生成五页汇报，要求从第 13 页图中核对数据。E02 在上传的四页可编辑原稿中替换第 3 页的两个准确值。两个版本都走相同的优化模式及同一份任务定义，采用 Kouri Flash、推理关闭、输出容量 393216、原累计账本。每侧一次提交，两个任务可以并行。结果冻结后独立评审。两份新材料不参加学习，之前的 15 题留存原结果。

明确、单页、带原文的替换先读目标页 OOXML，并提供形状 ID、原文与源文件版本。宿主仍渲染交付件。仅当请求、文本、非目标部件和实际渲染都核对通过时直接收尾。PPT 入口对超过 12 页的 PDF 先生成本地页索引，OCR 与像素延迟到指定页读取。按需预览使用已有 `inspect_ppt_region`，对同会话批准的 PDF 渲染一页紧凑 JPEG。用户可取得完整 PPTX、PDF 和逐页 PNG。图像重复引用和已有成功交付后的长度续接都在宿主处理。

## 收尾修复与验证边界

E02 的两处值实际在同一个多段落文本框，LibreOffice 会在 PDF 中插入项目符号。PPT162 因此保守走了常规预览收尾，表内 6 次含这些请求。最终候选 PPT164/Paper166 修复同一文本框内的组合替换及渲染证据识别。用 E02 实际工具参数、同一源文件和交付 PDF 做零模型回放，确认可以核对唯一文字目标、非目标部件、组合替换与渲染文字，重新生成的 PPTX 全部包内文件与真实交付逐项一致。当前没有新的在线请求数数据可归因于这次最后收尾修复。Windows 附件解析器保留查找用户安装依赖所需的 `APPDATA`，仍使用有限环境变量白名单。

Linux 隔离真实版定向 Python 52 通过、1 跳过，Node 61 通过。Windows 最终候选定向 Python 32 通过、1 跳过，Node 61 通过，宿主集成 18 通过、1 跳过。真实模型效果以冻结的隔离实例结果为准，正式站、前端及历史 15 题无变更。

## 最终候选的重启验收

PPT164/Paper166 沿用原两批历史轨迹重认证，先认证两条，再保留这两条并加入另外两条。四个程序 ID 与上一候选一致，构造及重启验收的新增模型请求均为 0。隔离实例重启后，目录接口报告两条已发布的来源读取 Motif，账号学习解析器重新读取并校验四条试用程序，Runtime 以实际注册工具参数检查全部通过。程序分别覆盖整稿后全量预览、改一页后的预览、改两页后的预览以及按变化集合读取修订预览。每次执行仍受场景、输入和匹配条件约束。账号学习程序不随 PR 分发。私有证据位于 `.local/ppt-pr163-final-20261111/` 的 `freeze.json`、`online-check.json` 和 `runtime-check.json`。
