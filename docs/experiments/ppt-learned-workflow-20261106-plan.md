# PPT连续操作学习与执行计划

## 目标与当前证据

实验ID为`ppt-learned-workflow-20261106`。在当前PPT92/Paper94候选基础上，从允许学习的正常轨迹发现连续操作及参数流，编译、认证后接入PPT Agent执行层，在新任务上检查质量、实际模型请求和完整制作费用。

现有私有审计收集到4条未显式禁止学习的普通轨迹。独立性还须按原决定、来源和续改关系核验，不能将4条记录直接当作4个独立支持。E/R留出任务排除。原始记录位于服务器私有`ppt-learned-workflow-20261106/training-trace-audit.json`。

多条轨迹有`finalize_ppt`后读取预览的重复操作，制作前段则混有Bash写页、修订和诊断。实现已从两条不同来源的正常轨迹发现单页交付后的读取操作及参数绑定，并在第三个来源的历史轨迹重放认证。四条原记录按PDF来源去重为三个决定，PPO续改不作为第四个支持；12条E/R留出记录排除。首次候选是`finalize_ppt → read_image`，没有学到整稿生成，也不自动省略视觉判断。

真实制作冻结PPT96/Paper98，最终源码PPT97/Paper99增加完整预览集合和精确图像来源守卫。通用执行层、参数/容量准入、失败输入记忆、自动发现/认证、账户内选择和原生工具续接已有代码。最终97完整Python2503通过/209跳过、Node1676通过/9跳过及smoke/Motif/RSI全过；212项代码锁一致。两项新来源六份初稿与三次限定修订结束，实际执行与后继采用通过，稳定同质降费未通过，详见[结果](ppt-learned-workflow-20261106-results.md)。人工B1对照单独标识，不给它伪造学习来源或RSI证书。

## 实施顺序

| 顺序 | 实施内容 | 验收门槛 |
| --- | --- | --- |
| 0 | 保存代码、原实验、库及成本快照，冻结学习/认证/新任务边界 | 旧结果保留，留出材料不进入学习，费用可按任务归因 |
| 1 | 补通用执行层和组件执行前准入 | 候选通过证书、参数、页型、容量、字体及样式检查；执行具有原权限、取消、父子调用、版本和恢复记录 |
| 2 | 从正常轨迹自动发现、参数化和编译连续操作 | 每个节点、顺序、参数绑定和停止点均有原调用证据，未知Bash和语义判断保留边界 |
| 3 | 认证生成的工具定义 | 历史重放、不同输入、失效版本、拒绝权限、取消和部分失败检查通过，保留原工具全部质量门槛 |
| 4 | 接入PPT Agent，让确定操作直接续接 | 后续任务实际命中、执行和消费输出；模型接收到必要的图像和缺陷证据，避免再次安排已经完成的同版本步骤 |
| 5 | 少量独立真实任务对照 | 检查合格交付、实际请求数、包含恢复的制作费与耗时，单列学习和Judge开支 |

第1步与第2步只通过稳定的工具协议衔接。通用解释器、权限与守卫属于人工实现的基础设施；学习所得的具体操作顺序、绑定和适用范围另有来源证据。

## 最小技术范围

- 离线发现沿Python路线，在线执行使用TypeScript，复用现有工具分发、Motif依赖表达、参数/版本核验和账户内学习入口。
- 优先复用`ppt_program_learning.py`、`harless_ppt_learning.ts`、`ppt_program_learning.ts`、`ppt_component_tool.ts`和`ppt_delivery_pipeline.ts`。发现与解释执行可各增加一个小模块，名称暂为`ppt_workflow_learning.py`和`ppt_workflow_runtime.ts`。
- 候选输出带参数schema、操作节点、数据绑定、前置条件、语义交接点、实现版本、来源及认证摘要的工具定义。通用执行器通过Harness公开工具接口执行，继承原权限和取消信号。
- 自动续接只覆盖已经确定的操作。原`finalize_ppt`的写操作权限如实保留，不能伪装成只读Motif来绕过原认证。图像读取可连续执行，图像质量判断和事实解释仍由模型完成。
- 实现版本变化要更新原有源码锁并重新认证；不修改上游Harness核心，不新造独立Agent循环。

## 组件采用与失败恢复

内容计划先指定页型、内容、来源、图件和备注。执行层筛选证书和参数，在临时目录检查实际字体、文本容量及样式，再安装合格页面。模型只需处理表达选择与需要补充的语义信息。

该段是制作路径的目标。当前实际完成组件前置准入、确定失败输入抑制与单页导出后读图续接；整稿内容计划自动续接未实现，目录选择仍可能被模型放弃。真实B1反复手写的负例已记录，不能把前置守卫写成杜绝弃用已完成。

不适用的组件在正式制作前退出。已有组件出现明确缺陷时，保留其余有效页面与文件，只把具体缺陷及必要内容交回模型。复用已有同版本检查和无进展判断，保留用户明确要求重新设计的入口。新增候选先在隔离任务中试用，不能把候选目录无差别提供给所有用户任务。

## 最小验证与对照

先做无模型认证和一个换输入执行诊断，再冻结候选，使用两项新来源或新需求的独立真实任务。题面、来源SHA、顺序和质量标准在首次付费执行前保存；两任务设置`learning_eligible=false`。不能从结果中挑便宜的一对作为全部结论。

| 组别 | 路径 | 用途 |
| --- | --- | --- |
| B0 | 当前共同质量底座，普通模型逐步执行 | 检查新增旁路对正常任务的实际影响 |
| B1 | 同底座下显式标记的人工确定性续接 | 区分一般工程自动化与学习结构的贡献 |
| B2 | 同执行层下使用自动发现并认证的结构 | 检查学得工具是否被采用，是否实际减少模型决策 |

首轮两任务共六次制作。若同一检查点能做匹配的局部比较，同时记录其共享前段与局部费用；局部收益与完整新任务费用分别报告。B1可以使用已有人工确定性交付能力，具体差异在冻结配置中写清，不能人为削弱普通组。

真实调用沿已授权DeepSeek Flash/off、393216输出及原null预算与请求额度，沿原累计账本。开始真实执行前说明本轮预计投入，保存SDK、工具集合与顺序、提示前缀及缓存变化。

质量检查包括题面覆盖、科学内容/条件/来源、可编辑性、备注及Office渲染。每个最终稿做逐页核查和独立计费的模型辅助Judge，使用共同十分制标准。运行失败、弃用与修复计对应制作组。

学习、候选生成、认证和Judge各自记账，不进入B/O制作对照，同时报告其独立投入。实际账单、人工作业分钟未知时保留未知。

若工具已执行但输出被弃用，或模型仍重新完成整段操作，判替代失败。若质量不合格，或完整费用没有下降，不宣称降本。若B1与B2相近，只说明学习结构达到人工自动化的运行效果。两任务通过只支持有限条件的观察，不能推出通用稳定收益。

## 本轮停止与回退

首次只推进一个有证据的连续操作候选。没有足够证据时缩小范围，不扩大昂贵评测。原PPT92与对应库保留；96在原隔离开发实例恢复同一run/Home/账本完成真实验收，97保留独立完整回归，不追改96的费用版本。最终全部任务已结束，保持原负例，不追加题目或第二轮修订；正式服务未改，无提交或推送。
