## 当前实际观察与失败定位

1. 模型分别生成 ZIP/BibTeX 与 ZIP/LaTeX 解析程序。原生沙箱认证前发现两个准入边界：ZIP `endswith('/')` 被误判为未绑定路径；纯归档路径规范化 `posixpath` 未列入准入。局部修复后重放原提案，没有为这两个宿主修复追加模型调用。模型构造来源明确标记，不冒充历史 Bash 学习轨迹。
2. 两个原生解析程序通过 ATC、LoRA 认证；其后在两个项目三个版本上累计 12 项独立深比较全部通过。该结果只支持冻结字面解析范围。
3. 为 C 的关系处理接通受认证的 JSON 值输入：前序能力实际输出由宿主物化为只读 JSON，沿用现有 Script 编译、沙箱及回执。新报告显式认证 65536 字节上限，旧程序保留 16000 字节；不修改 API 输出策略。Linux 定向 17 通过、1 平台跳过，包括跨步骤数据传递与旧输入守卫。
4. 第一轮 C 的 11 次提案包含不符合准入规则的输出写法、代码变量/JSON 错误，以及原生确定性检查失败；全部保留。最后一个关系处理程序通过原生认证并登记材料。它尚不是组合 C，更不是 D。
5. 新材料登记后，旧控制器仍用同一机会的历史失败总数拦截重试，未区分构造时的能力池版本。这是实际接线缺口。现已改为按冻结的构造快照统计，旧事实从不可变结果证据回溯；缺少版本时仍保守处理。38 项相关检查通过，待继续实际构造。

6. 统一新原语与关系程序的认证报告上限为 65536；旧库的 16000 上限不变。模型最终生成三步 C，ATC v1 验证、LoRA v1 后继及随后四份训练版本深比较通过。C 为 `cap_dc3832ee6ce8f4f6e4fa9cf7`，发布摘要 `37bc04836c3359fc9db934c163842b3e20dbdfd6323b36c1164938784ca21c6c`。包含此前全部失败和显式工程恢复，20 次获取请求估费 USD `0.075317172`。
