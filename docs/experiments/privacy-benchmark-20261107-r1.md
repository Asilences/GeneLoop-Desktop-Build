## 假设、版本与对照

问题是成熟工具接入公共边界后，能否减少个人身份/联系方式/凭证的残留，同时保留学习所需语义。比较原生 Presidio 与实际公共文本层；凭证比较原生 Gitleaks 和完整公共准入。它们分工不同，拒绝样本不算实体识别 TP，不用全拒绝获得召回率。

- 产品规则固定 `68a4e4d7d57808cefabb2d70bd9f291291caaff8`；与上次工程回归的 `bdef7b54` 之间只有文档变化。评测工具可定位到 `0472efbefa1b71913f96f827cbe23c75348415ee`，实际执行文件摘要与配置在[环境回执](artifacts/privacy-benchmark-20261107-r1/environment.json)、[核验回执](artifacts/privacy-benchmark-20261107-r1/verification.json)。配置在运行前落盘冻结，运行中未依据错误调参；方法提交用于登记相同字节的评测代码。
- 环境回执在 PII 初始化时生成，包含当时较早的凭证驱动摘要。后续仅修凭证 wrapper 失败审计和报告复用，原脚本保留；最终凭证评测文件以核验回执的 `method_source_checks` 为准，不能把较早摘要冒充最后执行版本。
- Linux/glibc 2.27、Python 3.12.15、Node v22.23.2；Presidio 2.2.365、spaCy 3.8.7、en/zh small 3.8.0、Gitleaks 8.30.0。其余实际依赖见回执。独立检出/Home/输出与评分依赖，只读复用原 NLP 环境，没有升级原运行时。
- 原生 Presidio 使用相同 NLP 模型和 0.4 阈值，原生 recognizer；有汉字时执行 en/zh 两路，邮箱用随包后缀表离线校验。GeneLoop 运行实际 `anonymize_text`。金标不交给检测器或 `learning_view`。
- `nervaluate` 1.2.1（MIT）承担 strict/exact/partial/type 与每类 P/R/F1。原拟用的 Presidio Research 0.3.2 会额外引入 Pandas 3/Transformers 5 等未冻结依赖，改用独立成熟评分器；原环境实际 NumPy 2.4.6 未变，未自写 F1。官方替换前 `_operate` 坐标只读观测，版本/签名固定，Unicode 半开坐标转评分器闭区间，不从变长输出倒推输入位置。
- 完整模块输入为 `{"text": 原文}`。Gitleaks 对整包 JSON 前后扫描，实际字段提示、嵌套 JSON、局部别名与拒绝逻辑均生效。原生 Gitleaks 在 CredData 上扫描原始文件目录；文件路径/allowlist 和 JSON 转义与公共入口有区别，因此不是单一识别算法的因果比较。
- 凭证未限时直调在大 JSON 批次上超过半小时无有序进展，因此保留原尝试，另冻结[120 s 评测预算](../../scripts/privacy-benchmark/credential-budget-r1.json)，控制代码 `11327dbe127a0590282601fa99aef2312a14191b`。使用 [Pebble 5.2.1](https://pebble.readthedocs.io/en/latest/) 的强制超时/进程恢复，LGPL，仅装在隔离评测目录。相同规则、相同数据且 110 s 内已返回的 7765 条真实记录复用；其余 3265 条（包括更慢已返回案例）按新预算执行。原模型、金标、应用依赖和内核规则未改。此预算是测试控制，不是给产品补上了总体时限。

## PII 识别层

“未完整遮盖”指金标实体还有任意字符未被官方实际操作跨度覆盖，包含部分遮盖；不要求预测类型相同。“额外遮盖”是金标外字符被覆盖的比例，可能包含未标注的其他隐私，不等于这些字符必然都应保留。strict P/R/F1 还要求类型和完整边界相同：例如多遮盖了邮箱前的标签会扣 strict 分，但不必然留下邮箱。

严格类型分数还受冻结的标签粒度影响：原生 `URL`、`ORGANIZATION`、`UUID` 等没有根据实测结果再改映射。主隐私比较采用不区分预测类型的完整覆盖，不把 F1 的涨跌直接等同于隐私漏遮变化；这些扁平类型分数不是统一层级后的上游榜单。

## CredData 凭证

当前上游旧 Gitleaks wrapper 不传 Category，而其 checker 要求非空 Category，会抛 `ValueError`。保留原 wrapper 失败审计；其零计数不是 Gitleaks 质量分。使用同一金标的明确适配：精确 `(文件, StartLine, EndLine)` 行单元及文件，含 T 为阳性、纯 F 为阴性，X 或 F/X 不确定项排除并计数；公式复用上游 `Result`。**不是官方历史榜单同口径，不宣称复现该榜单分数。**

PII 冻结配置中保留的旧 `creddata_primary` 键是最初 wrapper 计划，不是最终凭证评分定义；实际凭证控制、矩阵范围和不确定项处理以本节及 `credential-summary.json` 为准。未改写原配置来掩盖适配失败。

- 原生 Gitleaks：8,350 条报告；已标注精确行单元 TP=6,944、FP=1,103、FN=8,336、TN=44,339，P=86.29%、R=45.45%、F1=59.54%；不确定行单元 4,075，不属于已标注精确区间的命中 254，未一律当 FP。
- 文件层原生检出：含 T 文件 1,154/3,323，未检出 2,169/3,323=65.27%；纯 F 文件触发 68/6,578=1.03%；不确定文件 1,129。
- 公共模块：准入 9,120，明确拒绝 1,871/11,030=16.96%；另有评测超时 39、执行错误 0，结果未知，均不算拒绝或安全识别。已返回子集中含 T 文件拒绝 992/3,312，纯 F 文件拒绝 795/6,550=12.14%；这是拒绝行为，不是实体 TP/召回。未知结果的真值分布见聚合 JSON，分母与原生全量不同，不相减声称提升。F-only 也不能证明文件不存在其他未标注隐私。
- 准入后：1,461 个文件仍有可提取 T 标注值的字面残留，3,597/6,220=57.83%；另有 29 个准入阳性标注无法按坐标提取，不算安全。原生曾对同文件报过命中、公共模块仍准入且有残留的文件 232 个；不据此断言两者针对的是同一个秘密值。

1871 次拒绝中，797 次为 `credential_hit`、1056 次为尚未进一步归因的 `policy_or_processing_rejection`、18 次为 `scanner_error`。评测控制器的执行错误为 0 不表示扫描器从未报错。

原生扫描在旧接口审计失败前已完成，后续复用该报告并重新核对全部数据摘要，原失败和新执行目录分别保留。扫描耗时未完整留存，标为未知，未记作零。[凭证聚合结果](artifacts/privacy-benchmark-20261107-r1/credential-summary.json) 保留所有分母、拒绝原因、报告摘要及适配定义。

事后诊断：从当时已完成的差异文件中选最短 5 个，用同一个 `_scan` 分别接收原文和公共入口实际 `_encoded({"text": 原文})`。**5/5 原文命中而 JSON 输入未命中，5/5 公共模块复查准入**。这直接确认包装/转义会改变扫描信号，应先修公共扫描输入边界；该便利诊断切片不用于推算全量比例，也不证明原生命中与剩余字面值就是同一个秘密。[公开诊断计数](artifacts/privacy-benchmark-20261107-r1/transport-diagnostic.json) 不含源文件位置或秘密值。

## 结论与下一步
