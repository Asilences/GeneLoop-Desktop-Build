- 问题：Evolution 能否读取上轮策略的真实误报与正确对照，自主改变后续求解方法，并在原独立 Oracle 下交付合格结果？反证是重复原策略、继续误报、未发生预期行为，或仅有提示文字而无执行变化。

## 证据流与原始根因

输入保留原五篇论文历史任务的 22 条可查询经历、上轮两次失败候选、正确对照、原执行与验证引用。原历史任务按四个独立输入计数，同一论文的重复运行不扩充来源数。已用过的评价材料更新为开发证据；仍未暴露的 60 条引用被隔离。调查总览显示本轮可选 Capability 为 **0**，所以本实验只检验失败反馈驱动的任务方法修订，不能检验“已有 C 与新抽象之间的自主选择”。原输入、Oracle、费用账本均未修改。

从原始候选轨迹可直接定位 `title/year` 误报：`McMahan-et-al-2016` 的原文有这两个字段，但作者名 `Ag{\"{u}}` 内的 LaTeX 转义引号被候选临时扫描器当成普通引号，条目边界错位，解析结果只留下 `author`；错误中间结果进入 `answer.json` 后被 Oracle 拒绝。第二次评价的任务内修补仍报告同一缺失。详见[原实验的逐步定位](evolution-core-20261105-003.md)。Evolution 另从上轮记录提出 `@` 起点识别、字段分隔和“建议核对却未实际核对”的问题；这些是其调查所得，不能代替上述已核对的具体误报链。

真实调查工具记录表明，Evolution 先读取两次候选的质量失败、原测试命令及正确对照，再展开旧策略提交、两份配对评价及包含解析输出和原文件片段的执行记录。首次提交把旧根编号填入 `repair_of`，被宿主拒绝，没有触发评价；随后以独立候选提交。共两次提交、**只有一次实际候选评价**。本轮新增的同方法去重守卫未被触发，不把拒绝的提交算作第二种方法。

## 方法变化与独立评价

旧策略要求模型临时写 BibTeX 扫描器并“核对”计数；两次实际运行仍误报。新策略仍由模型编写任务内程序，但要求代码先独立计算标头数，再与解析出的记录数比较；不相等时以非零状态退出、不得写 `answer.json`。它还明确处理反斜杠转义、换行分隔字段，并在报告缺失字段前逐项回查原记录。`capability_refs=[]`，没有新解析器入池。

候选的真实执行不是只读了提示：隔离任务加载了新策略，生成的 `scan.py` 确有 `if len(records)!=len(n_headers): ... sys.exit(1)`，打印两类计数；遇到转义字符时跳过转义单元。该次计数一致，**不相等时的退出分支没有被实际触发**。与其配对的普通对照生成并修补了多份临时解析程序。独立动作评审接受了预期行为变化；这是单次轨迹观察，不单独证明因果。
