# R2 当前声明文本类别的范围视图

2026-11-08，对已经完成的 [R1](privacy-benchmark-20261107-r1.md)/[R2](privacy-benchmark-20261107-r2.md) 聚合结果作事后分组。没有新调用检测器、训练模型、调整阈值或修改原基准分数，产品规则仍为 `d832be12fabc76fc995b358e15a110a506ba4711`。这是同一批已见数据的另一种报告视图，不是新实验或独立评价。

主表按 R1/R2 评分前就固定的 `supported_text_tags` 展示，固定 10 类：姓名、电话、邮箱、位置、证件号码、银行卡、金融账户、IP、私有引用与凭证。配置原件为 `scripts/privacy-benchmark/protocol-r2.json`；R1/R2 的该列表逐项相同，没有按成绩选取类别。它描述当时声明的文本识别范围，**不等于最终完整隐私政策，也不意味着名单外可以披露**。例如 `PRIVATE_ID` 已有结构字段处理，不能因其不在文本列表就宣布账号标识允许公开；生日、医疗记录、生物特征等涉及具体身份时仍是待完善的敏感范围。

范围差异对英文总指标影响较大，但只看当前声明类别后，仍存在明显的未完整遮盖；因此没有新的“隐私验收通过”结论。中文正式姓名完整覆盖仍为 55.14%（R1 为 58.44%），卡号为 23.43%，这些负面结果保留。一般日期、年龄或组织名不一律删除，和可识别个人的生日、身份关联信息是不同的政策决定。没有覆盖能力的敏感类别也不能直接归为允许类别。

视图外明细、范围内准入字面残留和源聚合文件 SHA256 见[汇总](artifacts/privacy-benchmark-20261108-declared-scope/summary.json)，所有 R1/R2 原文件保持不变。完整类别的评分仍在原 R2 记录，不因主表聚焦而移除。仅有聚合结果不足以重新计算“按新政策允许保留的内容被误删”的比例，本次继续保留原全文金标外遮盖代理，不修改误删定义或 F1 映射。

复核方法：读取 R2 配置中的 `supported_text_tags`，在 R1/R2 `verification.json` 的 `pii[dataset].by_gold_type` 中，对列表内 `gold_entities` 和 `fully_covered_entities` 分别求和；未完整遮盖率为 `(gold-covered)/gold`。每套数据的三种对照分母相同，范围内加视图外等于原全类别实体总数；评分器、输入、规则和原始结果均未改变。
