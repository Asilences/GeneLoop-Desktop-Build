## 实现与触发

1. 原任务结算仍调用 `createPptLearning.schedule`。worker 导出共享 `quality_evaluation`，绑定任务、成品、rubric 和逐项证据。PPTX 可编辑文字、notes parts、PDF 页数和已登记 PNG 的真实解码分别记录；这些不代表科研或视觉质量。没有明确用户评审则相应项 `unknown`，人工分钟不填零。
2. 原稿继承仍走原账号/父对话/分支验证及不可变下载快照。PPT 场景先带入 PPTX 和 PDF，再带可选 PNG，保留新附件、原始来源和省略提示。该修复两组共有，属于普通工程，不算学到的新 Motif。
3. 默认真实 PPT 任务在私有目录保存 Bash 前后文本/向量产物证据。仅用独立正常 Baseline 轨迹提取符合已有 Artifact 参数契约的 Python 程序；不将 Runtime 重放当新模型发现。另一个独立任务的不同输入用于原样程序沙箱认证，认证器核对来源输出等价、输入依赖、重复执行一致、权限和代码版本。
4. 认证成功只进入账户/scope 内 `probation`；下一任务冻结程序目录，Baseline 不能使用。模型保留语义适用判断，Harness 提供目录并校验真实执行，失败继续走普通工具。
5. 两项后续独立配对必须真实调用新增程序、机械交付通过、包括重试的总模型费用更低，才 `active`；有明确人评时也不能增加修订分钟。负反馈、证据/代码变化、费用退化会停用，原证据保留。无新证据不重复认证已拒候选。
6. 多用户成员不嵌套 bwrap：通过原命令代理的受限 `/artifact` 路径，在宿主调用同一个认证器/执行器。宿主从本任务冻结库重新构造程序与当前参数，不接受请求中的任意源码或额外主机路径；沿用原取消、进程生命周期和无网络沙箱。
7. 程序目录只留在真实模型上下文和私有日志。公开会话投影与聊天界面按内部 producer 隐藏目录消息；用户自己讨论程序或脚本的原文保留。没有更改或截断实际模型上下文。
8. 学习独立性按 comparison 的主对话归属判断；同一主对话每轮新建的执行子会话、续改和重试不算独立学习决定。该守卫同时作用于 Graph 与程序候选及未来评测。保守地要求不同主对话，不从同一稿件的续改凑训练或晋级数。

本轮不接管科研理解、选材或全稿设计，也不实现任意程序生成、任意条件图发现或修改学习算法的 Meta RSI。

## 认证与收益边界

程序独立执行认证不等于论文解释正确。`program_reuses` 与 `verified_skips` 分开：程序选择本身仍可能调用模型，不把复用一次算作跳过请求。自动晋级比较同任务、同模型/工具配置、同输入的完整模型账单估费；不能据此单独归因新增程序的因果增益。

普通单路没有原始 Baseline 证据时等待；不偷偷购买新对照或认证任务。后台编译/认证本身零模型请求，仍消耗 CPU、磁盘与维护时间，不能声称零总成本。支持的是已有 Artifact 受限 Python 参数程序；复杂 Bash 包装、不完整快照、修改后的来源及缺少独立输入等会保留拒绝理由并回退。
