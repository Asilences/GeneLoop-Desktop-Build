# Evidence-Grounded Evolution Agent：首轮真实记录

## 问题、范围与基线

验证一个专门的离线 Evolution Agent 能否从多个真实任务中识别剩余求解负担，并交原 Builder／边界学习机制处理。不是持续 RSI 效果实验，也不是新的手写目标 D。

代码起点 `9c87126a`（PR132），实时远程 main `931d1bc5`。独立增量分支 `codex/evidence-evolution-agent-20261104`。服务器以代码文件哈希冻结无 Git 的隔离快照；没有修改生产代码、原 Store 或累计账本。

发现数据为此前真实模型组合能力在两个独立论文版本任务上的 Runtime 图；图形均为 `C,C,report`。它们是历史任务，不是两个独立项目的人群样本。另一个真实项目保留为学习留出；原论文冻结检查器的 validation/followup 输入与学习数据分开。未实际执行新的候选验收，因此不能报告这些任务本轮质量通过。

## 有界上下文与成本配置

每次只选择一个关系、至少两个不同来源指纹。相同任务重试和改名不增加支持。默认30,000 UTF-8字节上限，最多6份代表记录；统计保留所有该组失败、反例与未知费用数。原记录不删除，当前一次模型调用不提供任意检索工具；不足时应弃权。

真实 provider 为 DeepSeek，模型 `deepseek-flash`，`reasoning_effort=off`，`max_tokens=393216`，工具集合为空。每个显式批次最多1个物理模型请求、USD3研究上限、2700秒新请求准入期限；既有累计账本不清零。固定 Prompt、上下文、原答、费用归属均保存在私有目录。

最初自动审批拒绝了包含私有定位信息的待发包；没有产生请求。随后单独投影并审核匿名结构：不发送论文正文、任务名、路径、源码、结果值、字面值、描述或 Schema 示例。仅接口字段、类型、匿名调用关系、来源哈希与事实统计出域。修正后的请求获准执行。拒绝和预检记录保留。

## 定位与修正

首轮暴露的主要问题是证据层级错误：给模型看了已有组合能力内部的三个节点，却没说明整段图已经有一个可调用容器。模型因此把内部运行步骤误认为每次重新求解的工作。它的“重复编排负担”是模型假设，不是已有实测事实。

修复后，证据包明确携带运行层级、已有容器接口、未知模型决策次数。第二轮模型弃权。它说明本条件没有支持具体改进，不能据此推断模型已稳定学会识别收益，也不能把一次前后差异称为因果性能结论。

协议另有一个可复现问题：自然的验证检查列表被要求必须是单字符串。现接受非空字符串或非空字符串列表。保留第一次拒绝；从已保存模型答案做零请求重放，两候选均通过格式检查。没有把它们人工改写成边界候选或成功轨迹。

## 工程与研究结论分开

工程诊断已执行：跨任务包→单次提案协议→原边界学习器→原 Store 验证/发布→后继实际调用。此项使用明确标注的确定性提案与算术任务，只证明接线。普通能力候选经可信宿主准入后走原构造队列的路径也有诊断覆盖。两者不是这轮真实模型的演化成果。

真实模型部分：最终收到两个真实任务的匿名证据，返回 `no_change`；**本轮未达到“模型提出有效新改进并被后继采用”这一研究目标**。不自动扩大实验，也不为了成功要求模型调用 C。下一步应收集实际剩余决策/接口修复证据及其可核对成本，而不是继续让模型重新发现已经封装的图。
