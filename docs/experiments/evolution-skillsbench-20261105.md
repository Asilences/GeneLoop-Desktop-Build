# Evolution × SkillsBench：首批真实结果

**当前结论：已找到并修复阻断方法验证的公共接口问题，但尚未观察到本轮自主递归创造或同质量效率收益。** R6最有辨识力的结果是：验证题reward=1，而候选策略没有激活、没有准入；随后最终题reward=0。任务成功与改进成功必须分开。R7修复完成后，Three.js两侧真实对照仍pending。

## 研究问题与条件

问题是：正常任务产生的经验，能否推动Agent构造并采用新策略或可执行能力，继而在独立任务上保持质量、降低完整成本，并成为后继构造材料？如果没有实际采用，或独立质量不达标，就不能把成功任务或更低局部费用当作SI／RSI收益。

本批为公开SkillsBench题目的真实API执行，非真实用户前瞻试用。训练数据固定为SkillEvolver `16f3cc6392a5bb296231fc352ed0654312caab4e`，canonical数据为SkillsBench `5544ce7c2708c231099d974089e7c9e81e67ee7a`。模型为 `deepseek-flash`、`reasoning_effort=off`、`max_tokens=393216`；请求次数与费用不限，沿用原累计账本。原评分器与全质量门槛保留，未人工改分；人工交付质量尚未另评。

GeneLoop侧调查历史经历，提出候选，沿独立验证决定是否准入；Skill∞侧采用两层优化复现。当前两侧仍有接口和环境失败，尚不构成可用于计算胜率或收益的配对结果。R3、R4、R6为不同源码版本，不能合并成同条件效果对照。

## 关键定位与下一步

首先，R3提出候选并不等于能力已经入池；R6完成合格验证题也不等于策略已被使用。下一轮必须同时核对候选的准入、原生加载／调用回执及最终交付，质量门槛不放宽。

其次，跨调用的数值相同不能证明依赖。R7通过显式Binding保留真实Runtime参数传递，复用原学习器；保留失败节点及未执行尝试。诊断中的C→D只验证这条管道，模型自主构造与后继采用仍待真实轨迹。

最后，验证输入与最终评测用途必须明确。R7分开记录dataset split和evaluation role，按输入字节去重，拒绝同轮已用于验证的final输入；汇总保留所有阶段成本并标注已观察数据复用。后续Three.js结果先检查原评分、策略采用、独立性及对照条件，再决定是否扩大任务量。完整R7工程回归通过不替代这些实验结论。

R7真实失败进一步定位出两个通用数据流阻断。可用的执行前文件存在，但混在2200多条证据中，模型误把操作回执当成认证输入。R8新增分页示例文件查询，与准入共用同一选集；格式与来源预检在实际构造计数之前执行。另一个阻断是原评分器以退出码1表示质量断言失败，宿主却因此丢失官方0分，导致基线不能从失败继续优化。三份真实原CTRF离线重放均已确认应归类为`quality_rejected`，原结果未改写。后续真实运行检验这些修复是否消除了阻断，不预设候选会成功。
