## 已确认的验收与规则

- 服务器是 4 张 Tesla V100-SXM2-32GB 的原正式服务器。所有模型任务与渲染在服务器执行，模型使用正式 Flash、推理关闭；测试没有清空累计计量。
- 生产网页上传两段 6 秒合成素材，Agent 自行编写实际 Remotion 源码，交付 4 秒 MP4 与 TSX。播放器实际播放正常，下载链接字节哈希与服务端交付一致。首轮稀疏复核的13项机械检查通过，但补查2.8–2.95秒发现声音提前结束；因此首轮没有通过“前3秒有声”的完整语义要求。保留原记录，增加边界音频采样并给场景接入同一固定容器的FFmpeg分析工具，随后由Agent自行修复。该任务是合成短片功能验收，不代表真实镜头选择、所有格式或长片质量。
- 原网页的场景命令按每条消息生效。普通“你好”对照进入 Chat，仅1次模型请求、约2秒，没有把历史素材当新附件或重复剪辑。没有场景前缀的重剪对照走了普通 Chat/FFmpeg，不能算 Remotion 场景验收或 Motif 对照；该记录保留。连续视频修改须显式选择 `/video`，并使用实际 TSX 工程，不从先前答复猜测源码。
- 媒体下载在点击时直接请求现有鉴权附件接口，避免等待前端 Blob 后失去下载激活；原件、账户和不可变文件的服务端校验不变，预览与其他格式的客户端完整性检查保留。
- 账户隔离检查：所属账号取回相同视频哈希，另一个已就绪测试账号404，未登录303跳转 `/login`，没有泄露成片。新账号先走既有 workspace-ready 异步初始化协议；未就绪时的503保留为测试过程记录，不当成权限校验通过。
- 服务器 Node 全量1401通过、4跳过，相关Python103通过；PDF/OCR测试使用固定解析器动态库与语言目录。共享服务器的原生inotify额度曾耗尽；生命周期集成测试使用与正式服务一致的轮询环境后通过，生产保护未放宽。Linux/Windows CI以当前PR #118检查结果为准。

首次网页连接曾出现就绪超时和重连，后续已恢复，但尚未确定根因；保留观察项，不宣称已根治。长视频、4K及大规模渲染并发尚未在本轮验证。连续增量、跨对话和最终按钮下载结果在 PR #118 及私有验收报告中记录。


## 原生会话冷恢复反例与修复

真实并发验收中，另一个账号的两轮正常，但同账号的旧对话返回 SESSION_QUERY_PERSISTENCE_FAILED。独立复制该测试账号的原始日志，用同一安装版本的 DSH 持久化后端完整读取，确认两条私有分支含 geneloop/presented-proof 外部事件，未携带原生格式要求的兼容标记，故重启后的严格读回被拒绝；这与请求数量上限无关。另审计到 File 的投影摘要记录有同一问题。

后续交付证明改由 Cordis 内部通知进入原任务的 GeneLoop events.jsonl；File 的投影观察进入任务 projection-audit.jsonl，不再写入 DSH 原生会话。哈希、callId、任务时间窗、交付事件配对及文件归属校验保持不变，原生模型/工具循环与上游源码不改。
