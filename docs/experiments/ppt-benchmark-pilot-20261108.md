# PPT benchmark 小闭环：来源独立、真实执行与成本对照

## 问题与范围

检验从正常PPT轨迹学出的连续操作能否在独立任务中实际采用、进入成品并降低完整制作费用。本轮为公开benchmark材料的小样本适配实验，不声称官方全量榜单成绩。原服务、历史学习库、失败和账本保留，不PR，不改前端。

## 为什么调整2＋1

两个不同来源只支持发现候选，第三个独立来源验证实际执行；该数量不是科学事实、视觉质量或降费的充分证据。PPT用户常以相同提示词上传不同论文，新认证规则明确标为ppt_distinct_source_decision_v2：必须不同原始材料族、不同独立会话；提示词继续记录但不单独否决独立性。旧证书不静默升级。未提供PDF时，相同请求仍具有相同来源摘要，不能凑独立样本。

## 冻结任务与划分

固定抽样种子20261108。学习L01/L02、认证C01及科研留出E01来自DECKBench公开论文链接；原论文分别为ECCV2024条目816、1187、867_Q6p1jL2、744。普通中文6页汇报需求及一次指定两页修改为适配题面，顺序不由实验脚本指定。源PDF及其全部修订留在同一划分，参考作者幻灯片不提供给Agent。

通用留出E02使用PresentBench的talk/middle_school_presentation/13原题面及material.md，保留11–15页等原始要求。编辑留出E03使用PPTArena的Case 21: Title Case Titles原稿及原始指令，15页原稿保持其他内容。E02/E03不参与学习、候选调整或认证。未实现任务不得事后换题美化成绩。

## 执行与验收

- 仅2个学习来源＋1个认证来源；学习阶段正常baseline执行，认证阶段使用新材料正常执行后独立原生重放，明确不将C01混入训练。认证失败不自动加题或用其反复调候选后仍称留出。
- 最终3个来源各做B/O对照。B和O使用相同模型、公共基础工具、PPT适配Skill、模板、原始文件和验收要求；仅O加载认证的连续程序。测试请求learning_eligible=false。
- 学习与测试阶段通过显式GENELOOP_PPT_LEARNING_READONLY=1固定后台状态，操作轨迹正常捕获，发现/认证调用已有离线模块并绑定固定训练/认证ID。该开关不禁用已认证能力的读取，也不替代生产的默认持续学习。
- 本轮专测连续操作，关闭新增页面代码参数化的模型构造，避免每任务额外生成版式工具。导出、字体等固定脚本为B/O共同基础，不归因RSI。
- 验收包括需求覆盖、论文事实与数值、可编辑PPTX、实际Office PDF/PNG、指定页修改和其他页保持。质量按同一标准审阅；Judge单列，不触发无限修稿。
- 记录候选来源、独立认证、实际调用及最终成品来源，区分工具成功和最终采用。记录全部制作请求、缓存/未缓存输入、输出token、重试/恢复、耗时、配置估费及单位明确的上游费用；未知不当零或当实付。学习与Judge费用独立，人工修订时间未知则明确未知。

- Windows定向Python27项、Node23项、完整学习生命周期5项通过。Linux无模型完整Python3219通过／220跳过／49警告，Node1754通过／11跳过，smoke、motif:check、rsi:check均通过。不是实际质量或降费结论。

### L01改页保持性与质量边界

不可变交付指纹已核对。第1、2、4、6页的SVG和备注字节均相同，原生PPT页面XML规范化后也全部相同；第1、2、4页PNG像素相同，第6页有449／1167210个像素差异（约0.0385%），不把它写成完全逐像素一致。目标第3、5页内容和备注发生预期修改。已查看6页实际Office预览，并核对Table 3、4主要数字；内容仍偏文字化，未经独立Judge/真人质量验收。

### L02失败链与归因限制

1. 首次提交阻塞式读取19页PDF，私有测试客户端HTTP等待默认600秒。连接超时触发服务端请求取消；持久化原因虽为`user_cancelled`，此处是客户端断连，用户没有手动取消。该阶段已有19次PDF读取请求，未开始页面制作，不能省略费用。
2. 定位后只对原题恢复一次，使用相同冻结PDF／题面／模型，等待3600秒，另存`B-recovery1`，不覆盖初次失败。没有再更换论文、模型或模板。
3. 恢复中先通过`compose_ppt_page`写4页，又读取上游`executor-base`／`executor-notes`等规范，转为编写`build_pages.py`重做第2–6页，并反复收紧宽度阈值。最终草稿有6个SVG、仅4页备注，无PPTX/PDF导出，不是合格成品，也无最终采用证明。
4. 最终助手消息含DSML格式的编辑指令及思考结束标记，但没有相应有效`tool/call`，之后未调用`finalize_ppt`。Harness以`ppt_delivery_not_delivered`拒绝完成。现有原生事件能确认“调用成了文本”，**不能区分上游原始响应还是SDK转换层首次产生了格式问题**。不解析并执行这段普通文本来伪造修复或成功。
5. 当前证据不能把该失败归因于新Motif：本轮采集均是baseline，学习只读，新连续程序投放0。它暴露的是现有制作路径自由切换、上游参考规则回流和工具调用格式稳定性问题。

### 学习准入及停止决定

既有学习模块只接收L01两条完成轨迹，按同一原始论文／会话合为1个来源；L02失败不进入正样本。离线检查输出`blocked_before_discovery`：机械合格来源1、所需训练来源2，候选0、认证0、投放0。失败草稿与原文保留为后续诊断材料；C01/E01–E03内容未进入发现、认证或调参。已核对本实例4项任务全部终态、活跃任务0、未经认证选择0；不再自动恢复、扩跑或PR。

本轮支持“2＋1必须以合格独立来源计数，不能拿同论文改页或失败草稿凑数”；不支持“当前PPT Agent已稳定交付”或“新RSI能降低制作费用”。下一步优先核对模型工具调用格式的实际丢失层，以及为何内置页型后又回到上游手写／测宽流程；修复后继续原冻结题，不能凭改换成功题获得正结论。
