# PPT 连续程序继承与独立对照

目标是让新一批已认证程序加入同账号的学习库，同时保留环境、反馈版本和证据仍有效的旧程序。库满时保留已认证条目，记录暂缓加入的数量。本轮的 PresentBench 15 题仅用于历史学习和故障诊断。其制作和评分结果保留。

真实验证使用一份新 PDF 做整稿生成，另用一份新可编辑 PPTX 和更正说明做单页编辑。编辑对照两侧接收相同字节的原稿，生成失败也能独立测试编辑。导入 PPTX 与修改 Agent 自有原生项目的入口可能不同，按实际记录报告命中。普通组和优化组使用同一制作底座，优化组加载冻结的继承库。关闭本轮材料回灌和自动 Judge，制作结束后独立评审。每组每题一次提交。保留失败、恢复、未知用量和原累计账本。

配置使用 Kouri `deepseek-v4.1-flash`，推理关闭，模型输出容量 393216，原费用和请求额度为 `null`。制作预计配置估费 USD2–4，评审预计 USD0.1–0.5，均与实付分开。历史材料重认证使用零模型执行。正式服务与 PR 不涉及本轮修改。

## 已复现的学习库覆盖

旧编译器从空映射收集当前批次的认证程序，随后直接替换 `selected.json`。旧证据仍有效时，新批次也可能撤下已有能力。修复后的发布路径会核对原库摘要、账号和范围、环境、反馈版本及完整证据，再将新认证程序追加到原库，按程序 ID 去重。证据冲突时停止发布。两批真实历史材料按原规则依次重认证。第一批产生 `build_ppt` 整稿预览与 `patch_ppt` 单页预览。第二批保留这两条并加入两条 `patch_ppt` 多页预览，形成 4 条试用程序，新增模型请求 0。初次升级重新认证是因为编译器文件参与环境摘要。旧证书和指针保留在私有实验备份。

Judge 在全部制作终态后执行，仅接收有效成品。19 次未交付中，11 次触及评测时限，1 次因提交连接提前断开，6 次以缺少最终交付失败，1 次仅有素材图却被服务标为完成。出站指纹也表明，历史图片随连续请求反复进入网络，但任意单个包体内没有重复的图片 payload。下一次性能修复应优先验证附件先做本地结构解析、按所需页补视觉证据，再检查图像历史与制作回合。这个对照只改变学习库继承行为，耗时与缓存数据仍按实际计量报告。
