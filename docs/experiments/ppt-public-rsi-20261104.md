# PPT 公共 RSI 接入与 PR131 回归

## 问题与实施范围

PR131的Windows检查发现临时目录短路径误拒绝与Markdown测试换行差异。已保留目录链接守卫，将批准根目录规范化；回执测试分别覆盖LF/CRLF原始字节，原文读取仍保留全部内容。Windows本机还复现宿主配置子进程按GBK解码UTF-8的问题，调用已指定UTF-8。

本轮将PPT正常单路轨迹、原生Artifact认证材料与公共Capability机制衔接。页面提炼仍沿既有worker和Artifact认证。宿主显式配置公共计划后，复用公共发现、Builder、验证、Store发布、后继执行与费用反馈。公共程序调用继续通过原`create_ppt_page`，保留独立任务版本、账户与输出授权。

## 任务与验证划分

免费诊断覆盖普通单路准入、独立支持、账户隔离、holdout排除、证据失效、原生代码锁、取消、发布回执及未来任务加载。真实桥接验收复用正常任务学得的页面源码，重新运行当前版本原生认证，调用公共Builder后执行独立页面验证和后继复用。合成诊断、历史认证重放、真实模型构造与新任务使用分别记录。

独立验证固定源页SVG/PNG及参数输入，以原可见文字、画布和实际像素检查器复核。该门槛覆盖页面结构与渲染保真，科学结论、需求适用性、整份PPT质量和同质费用仍需另评。公共Store的认证范围沿其现有`local_experiment`协议。

## 有效配置

以main `690d234`整合后的PR131候选为基础，原冻结批量实验保持既有源码与数据。服务器使用独立检出、原有安装依赖与字体，沿原累计账本。真实构造使用DeepSeek Flash、reasoning off、393216最大输出容量，费用与请求不限，学习费用独立记录。私人题面、参数、论文、认证输入与原始轨迹留在私有`.local/`。

公共计划通过宿主环境`GENELOOP_PPT_CAPABILITY_PLAN`显式启用。默认普通任务只登记账户内结构证据与已认证材料，公共提案不自动付费。配置后以原生程序库版本与冻结计划摘要确定构造轮次，同一代普通任务不会反复提案，失败或中断保留现场。计划沿原`ledger_root`，不清账本。

## 验证与结果

- Windows本机相关回归23通过、6跳过。首轮本地沙箱临时目录权限拒绝另留私有诊断，采用正常Windows执行和工作区临时目录复核。
- Linux初步定向Python24通过、1跳过；Node7通过、1跳过。完整回归、真实构造与后继使用正在验证，暂不写成通过。
- 当前新增公共机制的净费用、质量和人工修订收益待验证，学习/认证/评审费用不混入制作对照。

## 复现入口

`npm run rsi:improve -- --plan <私有宿主计划>`预览，服务器使用同入口追加`--call-model`执行。计划用原字节`scene_adapter`引用`scenarios/ppt_master/capability_adapter.py`并固定`scene_dependencies`。PPT独立发布材料格式由该适配器验证，包含owner、libraries以及validation/followup的独立输入和SVG/PNG参考证据。

宿主`publish_capability.mjs`复用`completeCapabilityCycle`，叶执行交给`artifact_capability_runtime.ts`及原Artifact沙箱，模型不能改验证标准、授权或认证结果。已发布根在未来任务冻结加载，原页面工具按目录中的Capability ID执行；渲染仍沿`finalize_ppt`。

## 边界与回退

账户内保存原始页面、默认参数与证据，当前跨账户共享继续需要独立授权与脱敏准入。原生学习被撤回时公共根同步撤回，失效证据阻止执行；公共桥接失败时保留既有原生已认证程序。公共候选尚未作为生产部署验收，正式服务版本保持既有状态。
