## 当前瓶颈

同一策略要求执行模型临时生成字符扫描解析器，跟踪括号与引号后检查缺失字段；这不是已认证可执行解析能力。真实任务仍产生title/year误报，说明指令没有转化为可靠交付。反馈链路异常又掩盖了评价，Agent没有形成实质策略修订。当前证据支持“策略提案已进入真实任务，但可靠执行与失败后修正未闭环”；不能把重复提交算作成功进化。

随后逐条复核原始输入、两次候选的命令、解析输出和Oracle，定位到更具体的原因。`McMahan-et-al-2016` 原文第552–567行确有 `title` 和 `year`；作者名第556行含 LaTeX 转义引号 `Ag{\"{u}}`。第一次候选在`operation-0009`临时生成的扫描器把反斜杠后的引号当成字符串引号，错误地把该记录延长到第599行；中间记录只有`author`字段。`operation-0011`直接将这个错误的中间结果写入`answer.json`，独立Oracle在`operation-0017`拒绝。第二次评价生成的临时解析器先出现未终止记录，经过几次任务内修改后虽统计出50条记录，但`operation-0025`仍显示该条只有`author`，最终Oracle在`operation-0035`再次拒绝。这些是原轨迹可复核的解析错误；不能归咎于最终汇总或Oracle。两次提交的`strategy.json`字节内容相同，临时执行代码的修补也未产生合格结果。

针对重复提案，后继代码在同一作用范围内按实际`kind`与`proposal`去重。改写`burden`等解释文字不能再占用第二个真实评价名额；有意复测须另立记录。此项是对后续运行的控制修复，不追改003的原始提交、评分或费用。后继真实反馈修订与原 Oracle 评价已单独记录在[004 实验](paper-evolution-feedback-revision-20261105-004.md)，不追改003的结论。
