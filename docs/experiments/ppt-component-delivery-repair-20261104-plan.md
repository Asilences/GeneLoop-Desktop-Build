## 1. 审计结论

## 2. 共同交付底座，普通与优化组共享

### 2.1 有限的默认设计 profile

首版只支持一个可靠科研默认 profile，不同时增加许多模板。16:9、正文/标题/注释/脚注层级、边距、间距、颜色角色在公共版本化配置定义。建议初值：标题30–32pt、正文20–24pt、次级18–20pt、来源12–14pt；这些是待真实渲染校准的默认值，不是任意任务的硬限制。

字体必须在服务器实际运行沙箱探测并绑定字体文件摘要、常规/粗体和回退关系，不能仅写一个字体名称。对当前文本检查Unicode覆盖，同时核验实际Office渲染；cmap覆盖不能单独证明字形整形正确。优先选择已安装的中文字体，不默认安装新包，不把文字转曲规避可编辑要求。

主题参数使用成套语义角色，避免独立开放任意背景和文字颜色。对可确定的纯色背景检查正文对比度（拟用4.5:1门槛）；渐变、透明叠加、复杂图像背景标记待视觉复核。默认主题可按预认证策略选择深色文字；用户明确指定颜色或模板时不得静默改写。字体缺失且没有获准回退、内容放不下时返回明确不适用原因，不能无限缩字或截断科研内容。

### 2.2 实际导出与检查入口

新增小型 `ppt_delivery_pipeline` 适配层，复用只读官方 ppt-master 导出脚本、现有沙箱/broker、Office/font资源和present流程，不改上游技能或另写渲染引擎。普通组输入自产页面，优化组输入学习组件页面，均走同一配置和质量门。首版覆盖 Generate 自包含页面；Edit Native PPTX及复杂图表继续原路径，不宣称已统一。

入口输入为受限工作区内的来源 manifest、页序、备注、任务内容契约、设计profile。依次执行已闭合阶段内的官方检查、可编辑PPTX导出、实际PDF/逐页PNG渲染、机械检查。不得跨越官方设计批准或来源门禁。返回产物、逐页诊断、环境版本、SHA及来源关系；图片仍须由原生看图工具真实交给模型。

统一几何单位：SVG viewBox→幻灯片尺寸→PDF pt→PNG像素使用固定转换；明确区分字形墨迹、行框、文本框。字符框相交只报待审区域，不用其强制清零。可编辑对象、页数/备注/每页预览、当前任务明确的条目数量可作机器门；科学正确性及复杂视觉问题仍需独立评审。

## 3. 修复循环以证据收敛

为每次检查保存 `{source_hashes, artifact_hash, profile_hash, environment_hash, checker_version, findings}`。相同依赖再次检查复用报告；源文件、字体/工具、主题或检查器变化即失效。视觉评审还要绑定题面、页图和评审版本；不能用旧评审批准新任务。共享母版/主题变化使所有相关页失效；首版可整稿重导出，仅复用未变化且依赖相同页的检查，不冒称已有完整增量渲染。

问题分为明确缺陷、待视觉确认、已排除解释。每次修复必须引用缺陷ID、目标对象和预期改善，修后重新检查实际产物。同一缺陷/相同依赖无新证据时不重复启动相同修复；已证明无改善的修复不再重试。确认缺陷仍未解决时退出该组件路径并回普通制作，保留合格页面及资料；无法解决则如实标记未通过，不能强制交付通过。

此机制不是恢复请求或费用上限。原始Bash仍存在，不能声称可凭命令字符串可靠拦截任意重复诊断。首版对受管理交付路径执行状态守卫，工具生命周期提示重复证据；若模型仍通过自由Bash循环，记为未解决反例，不能只靠更严提示宣称完成。

## 4. 组件复用与认证调整

历史页复现检查验证“模型把一次性SVG抽成程序后，有没有丢文字、图件或版式”；它确实执行候选代码，属于后台回归，不是每个新任务重做历史页。它与普通/优化两份PPT无关。

分层认证：

1. 不变性/权限：输入来源、程序/依赖SHA、沙箱权限和内容归属继续严格保留。
2. 保真参数化：允许属性顺序、空白、等价SVG写法变化；文字/图件不丢失。当前源像素等价保留作该类局部回归，统一模型编译提示。
3. 有意改善字体、配色、布局：新候选另记录变换目标与质量契约，实际导出检查并独立评审，不要求旧图像像素一致，也不假称原保真证书适用。
4. 泛化边界：独立输入、长中文/英文、数量边界、粗体/特殊字符、颜色组合、容量超限拒绝及新输出目录；不能用两个输入执行成功推广到任意参数。

模型负责科学内容与适用版式选择。通过显式参数和适用域校验后，Harness执行组件→共同导出→检查，避免模型重新拼命令；不适用在执行前退出且返回精确原因，已失败版本在同一条件下不反复试用。模型查看真实渲染并可提出有具体位置的语义/视觉修订；不能用状态机禁止真实纠错。

统计至少分开 `component_attempted`、`component_executed`、`component_rejected`、`component_used_in_delivery`、`fallback`。由宿主记录组件输出→允许变换→导出输入→最终present的哈希链；自行重写后不能仍计组件最终复用，来源不完整记unknown。每页/每次调用分别标识，不能仅按程序ID去重累计。

## 5. RSI记忆范围

固定字体/配色、共同导出、缓存、收敛状态机先作为工程基础，不称新RSI。可学习内容包括：版式适用域和容量，当前环境中的字体/配色失败条件，缺陷→局部修复→实际改善证据，可复用的页面程序及其调用方式。

沿账户内既有 `harless_ppt_learning` / `ppt_program_learning` 私有库扩展证据，不另建学习系统，不跨用户复制内容。失败轨迹可学习拒用条件；成功轨迹学习参数程序。候选由模型提出，独立验证器认证；后继新任务实际应用才计继承，不能把模型反思文本当已生效规则。

学习样本准入不要求先省费；结构认证不等于质量通过；自动优先启用需后续质量/使用证据，无净收益或回退过多则降权/停用。模型不能改写验证器自行降低门槛。学习/生成/认证/Judge费用单列；前向尝试、丢弃、重做、修订和恢复仍计原组。提供另列摊销，不能用学习费用分列隐藏总投入。

## 6. 开发顺序、测试与成本判断

| 优先级 | 最小改动 | 重点验证 |
| --- | --- | --- |
| P0 | profile、颜色关系、字体覆盖、宿主输出目录；修正编译提示 | 复现浅底白字/缺字/路径错误；普通与优化配置一致；用户指定样式不静默覆盖 |
| P0 | 共同交付入口、结构化检查回执 | 实际Office导出与全部页预览，缺字、备注、内容数量、错误退出保留 |
| P1 | 缓存与停滞状态、最终交付来源链 | 无变化不重渲染；依赖变化失效；合法文字框相交不误报；弃用组件不得计成品复用 |
| P1 | 后台学习适用域/修复规则并在下一任务加载 | 不改当前任务冻结库；新任务实际调用、失败回退、版本变更和账户隔离 |

具体模块优先扩展上表现有文件；仅新增小型profile/交付状态模块及必要回归，不重写运行引擎。涉及共享Runtime后在服务器执行npm test、smoke、motif:check；全部日志留私有目录。源码和兼容库作为配套候选更新，原库及正式服务不动。

先无模型复现旧坏参数、字体缺失、长文本/条目数、缓存失效和合法相交负例，再做少量真实测试：

- 修旧组件的Attention任务作为开发回归，不算独立泛化；冻结后用两个不同论文/不同内容密度的后继任务。
- B：共同交付底座+普通写页；O：同底座+已认证组件。两侧保留相同既有Graph配置（或同关），只改变组件复用，清楚区别于前轮原始DSH B/O。历史原始基线仅作参考，不跨版本归因。
- 默认先两个独立配对（4次生成），不是立即重跑12题；先后顺序交替、串行执行。相同模型、Skill、材料、题面、字体、导出及质量条件。双方冷结果缓存，单列暖缓存诊断，防止材料互相泄漏。
- 沿用真实Flash/off、显式输出容量393216、额度/次数不限及原累计账本，运行前核对实际生效配置。学习和Judge单列，API估费与实付区分。
- 主要判据：双方交付均合格；O最终稿有可核验组件来源；无同版本无证据的诊断循环；后继两题分别报告请求/token/费用/耗时/回退/修订时间。内部目标为配对合计前向费用至少低10%，质量不下降；这是待验证目标，不是效果预测。
- 开发者盲化评审两组成品，记录所有页与明确题面要求；可另行真实LLM Judge十分制，不能替代人评。人工修订时间实际计时，未发生不伪造测量。任何一侧失败均保留费用且计完成失败，不删出总体报告。
- 两对均合格且出现降费，只支持小样本可行性；若一升一降、弃用、质量失败或总费用不降，停止扩展，按阶段费用定位后再决定。若需声称学习优于人工模板，另加同功能人工组件消融；本轮B/O不能证明这种额外优势。

回退：撤销候选profile/组件选择，返回原普通制作链；不得静默放宽验收。当前任务不动正式网站、不替换旧冻结测试、不提交或推送。

## 7. 可执行实施清单（2026-11-04补充，仍未实施）

### M0：冻结开发基准与负例

记录当前commit和未提交diff摘要，核对服务器源码与资源版本，在独立候选检出开发。保留旧组件、坏参数、旧SVG/PNG和事件证据只读。正式服务先查status/check，健康服务不重启。所有后续诊断通过项目环境在服务器运行并重定向保存完整日志。

完成标准：候选源码清单、环境摘要、旧负例清单和原累计账本定位齐备。没有这一检查不覆盖服务器文件，也不启动真实对照。

### M1：设计配置与参数预检

- 新增 `scenarios/ppt_master/design-profiles.json`，首版一个 `academic-readable-v1`，记录画布、字号角色、间距、配色角色和字体选择策略；实际字体文件版本由私有运行环境绑定，不写入公共机器路径。
- 扩展 `ppt_component_schema.ts` 校验设计profile和关系约束；字体覆盖、实际渲染预检复用或扩展 `ppt_component_render.py`。TS在线控制、Python离线检测/编译沿用现有分工。
- `ppt_component_tool.ts` 默认允许省略output，由宿主分配安全目录；旧显式output继续经过原守卫。参数不适用返回字段级诊断，不让模型猜哪一项错了。
- `ppt_component_learning.py` 统一编译提示；修复旧字体/配色生成新候选、重新认证，不篡改旧候选或证书。

完成标准：旧浅底白字参数不会再产出无诊断的坏预览；缺字被识别或使用已验证回退；用户指定风格不会被静默覆盖；条目数超限可解释地拒绝。所有判断记录适用范围，复杂背景不冒充确定性检测通过。

### M2：两侧共同的交付入口

新增小型 `src/adapters/ppt_delivery_pipeline.ts` 以及必要Python检测辅助，沿现有工具注册和broker提供 `finalize_ppt`。此为拟新增协议，不是当前已存在接口。普通与优化组均可调用，原官方生成流程和阶段门禁保持。

拟输入：

```json
{"project":"/work/projects/deck","manifest":"/work/projects/deck/delivery.json","profile":"academic-readable-v1"}
```

manifest包含按页排序的来源路径、备注、语义条目角色及任务要求。宿主重新解析实际文件并计算SHA，不信任模型填写的passed标志或伪造阶段回执；不能仅靠模型声明“2条边界”就证明实际成品有2条。结构化内容与渲染文字需关联，难以可靠识别则标为待评审。

拟输出：

```json
{"delivery_id":"...","mechanical_status":"passed|failed|unknown","review_status":"pending","artifacts":[],"page_receipts":[],"findings":[],"reused_checks":[]}
```

在工具内部依次完成官方门禁、导出、实际Office渲染和机械检测；模型仍通过真实图片评审当前版本。初版组件调用生成后自动准备交付清单，阶段条件具备才接续该入口；未闭合设计/来源条件时只返回下一必需步骤，不绕过技能审批。

完成标准：普通手写源与学习组件源均产生可编辑PPTX/PDF/所有页PNG；异常退出、缺预览、陈旧产物不报成功；页码/备注对应；任务取消能中止子过程；不增加独立服务或新Agent循环。

### M3：检查复用、局部修复和来源统计

- 新增小型 `ppt_delivery_state.ts`，扩展 `ppt_component_cache.ts` 相关共用摘要逻辑；源缓存与最终交付缓存使用不同命名空间和协议，不把源图命中冒充交付命中。
- 状态依次为 `source_ready → exported → rendered → checked → reviewed → delivered`；`checked`只表示完成检查，是否通过保存在单独字段。缺陷导致 `repair_needed`，无改善导致 `stalled`，不能跳到合格交付。
- 每个缺陷以规则/页面/对象/依赖标识，记录before/after证据。仅当输入、修复方式或新证据变化才再执行同一诊断。页面局部修订复核受影响依赖；共享主题变更全稿失效。
- 自动修复先只允许已认证的字体回退、受约束配色及布局参数调整；不得自动改科研数值、删内容或压低验收阈值。未改善时停止该修法，转向显式回退。
- `ppt_program_learning.ts` 与 `dsh_web_tasks.ts` 接最终present的来源核验，原program_reuses保留兼容并明确其为执行计数，新增成品复用和弃用事件。

完成标准：同版本重复入口不再重导出/重检查；任何关键依赖变化均失效；伪造回执与跨账号缓存拒绝；组件执行后重写不能计成品复用；进程重启只能恢复可核验状态，半成品不能当已完成。

### M4：最小RSI继承闭环

复用 `harless_ppt_learning.ts`、`ppt_program_learning.py/ts`、`ppt_component_learning.py` 和现有认证器。后台从M1–M3记录的真实失败/修复或成功页面生成一个候选。首个候选优先为当前组件的适用域/设计profile绑定，避免同时开发任意维修代码生成器。

候选记录程序/配置版本、适用条件、拟替代决策、支持与反例、独立认证结果。Python认证后以版本化私有库发布，TS在下一任务冻结加载并执行参数绑定/守卫。修复动作使用受限已支持协议，不能将任意模型表达式交给eval。

完成标准：无需手工修改active指针，真实任务结束自动产生候选、认证并进入后续可试用库；下一独立任务实际使用并留下事件。生成失败、认证失败、缺独立证据时明确停留候选状态；禁止把自动入库当作自动成功。任务成本下降不是样本准入前提，质量认证、适用性、前向收益分别报告。

### M5：小规模真实验收与交付

先执行负例/守卫/公共Runtime回归，随后冻结全部源码、profile、库和工具顺序。历史Attention失败题只用于开发；独立测评用一篇论文的一页结论任务和另一篇论文的三页汇报任务（结论页可命中既有组件），每题B/O各一次。测评论文和内容不得参与候选生成/选参；测评期间学习写入独立队列，不能改变冻结执行库。

两侧Graph保持同配置、均可用finalize_ppt，只有O获得学习组件。先做两对，全部费用、失败和修订保留；若两对未出现质量合格且费用降低的结果，不扩12题。10%是工程目标而非统计显著性阈值；只有两对不能声明普遍降本。

若需要证明新增适用域规则的作用，在同一输入的无模型守卫回放中对比旧/新条件；这只证明旧坏参数被可靠拦截，不作为真实LLM成本收益。更大人工组件消融推迟到本轮可靠性成立以后。

交付包含代码diff、必要自动回归、四份PPTX及逐页预览、逐阶段成本表、真实候选生成/认证/继承证据、失败与限制，以及更新后的场景交接。日志和论文仍留私有目录；无需为本设计运行新API或提交代码。
