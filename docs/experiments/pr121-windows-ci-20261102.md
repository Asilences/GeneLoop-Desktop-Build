# PR #121 Windows CI 修复

- 日期：2026-11-02；范围为现有PR的跨平台导入、文件锁及UTF-8读写兼容，不改变能力准入、研究结论或模型配置。
- 失败来源：[PR工作流41445895919](https://github.com/jingyio/GeneLoop/actions/runs/41445895919)，Windows job `125278760957`；相同head的Ubuntu校验通过。
- 根因：`capability_feedback.py`在模块顶层直接导入POSIX专有`fcntl`，Windows在测试收集时出现6个ImportError；不是上传ECONNRESET，也没有运行到模型验收。
- 修改：反馈写锁和提案累计账本锁复用已有`file_lock.exclusive_lock`。POSIX继续使用flock，Windows使用同一字节上的msvcrt锁，锁冲突明确拒绝；保留原锁文件和原子发布。新模块的中文JSON、schema、轨迹及Node文本桥接显式采用UTF-8，测试夹具采用相同编码。
- Docker启动参数诊断在Windows提供模拟uid/gid，只核对参数装配；没有宣称Windows能运行Linux容器。
- 新增回归：缺少fcntl时模块仍可导入；锁已占用时不得写入；中文反馈事实能够持久化并原样读取。
- 本地最小验证：59通过、1项Linux原生场景跳过；命令及后续Capability回归完整日志在私有`.local/efficiency-rsi-windows-20261102/`。真实Windows结果以[PR #121最新head检查](https://github.com/jingyio/GeneLoop/pull/121/checks)为准，不能以本地诊断代替。
- 没有API/模型调用或生产部署；工作区并行网关修改由其原工作保留，不纳入本次Windows修复提交。旧CI失败及旧上传问题记录不删除。
