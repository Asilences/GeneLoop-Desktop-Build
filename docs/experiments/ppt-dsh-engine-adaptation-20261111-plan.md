# dsh-ppt 能力吸收与 RSI 学习实施方案

- 日期：2026-11-11。
- 状态：已开始实施；整稿/patch、共同交付及可选桌面接缝已实现，固定输入实际Office通过并修复配色问题，完整Python/Node及smoke/motif/rsi通过，原失败保留。新引擎RSI正常材料及真实B1/O尚未启动，未部署或更新PR。详见[实施及失败记录](ppt-native-deck-engine-20261111.md)。以下保留设计及分阶段验收标准。
- 基础：当前隔离工作区PPT152/Paper154，分支`codex/ppt-managed-learning-20261104`；前轮稳定交付修复与失败记录保留。
- 目标：减少逐页编写及反复收尾的模型工作，改善通用PPT的图表/表格能力；随后验证RSI在共同工程底座上的额外收益。

## 一、总体数据流

```text
用户需求 / PDF / 现有PPT / 后续反馈
                  ↓
PPT Agent：理解内容、关联来源、选择表达方式、输出整稿计划或局部patch
                  ↓
PPT Agent执行层：参数预检 → 生成/修改 → 当前版本导出 → PDF/PNG → 返回成品
                  ↓
Harness：现有工具调度、授权、取消、会话和模型路由

交付后的不可变轨迹 → RSI后台发现/构造/认证 → 后继任务采用 → 效果反馈
当前成品与来源     → 内部可选Judge后台评审 → 反馈，不阻塞交付
```

模型仍负责内容、叙事、科学解释及有必要的视觉判断；本地执行层负责文件与绘制操作。Windows/Mac本地执行，模型按现有服务端路由调用。Judge和RSI沿前轮已经拆开的独立worker运行，不增加第二套Agent循环或常驻MCP服务。

## 二、吸收范围与兼容边界

本次复核上游`dsh-ppt`包版本0.20.5。实施时先固定准确commit及依赖锁，保留MIT许可和归属；本设计中的master链接不是安装锁。

|吸收能力|上游位置|GeneLoop用法|
|---|---|---|
|结构化整稿生成|`skills/dsh-ppt/scripts/deck-advanced.mjs:buildDeckAsync`、`deck-core.mjs`|接收当前任务的内容计划，统一生成原生文字、图片、表格及图表，减少逐页模型往返。|
|工程局部修改、稳定ID、撤销|`deck-advanced.mjs:editDeck/saveRevision/undoDeck`|按稳定页面ID提交字段patch，合并一轮修改并支持回退。|
|表格分页、原生图表|`deck-core.mjs:paginateTable`、`deck-advanced.mjs:exportPptx`|补充当前内置页型；不静默删行或改变数值，归一化后的页数重新核对用户要求。|
|来源指标与页面依赖|`deck-data.mjs`|为后续数据更新与影响页定位提供确定性操作。来源定位的正确性仍需上游内容判断。|
|按需加载|`src/execution.ts:getEngine`|首次实际使用才加载模块及必要依赖。基础模块可安装在本地，运行时不自动安装/联网取包。|

不安装上游整套插件/工作台，也不叠加其完整Skill。将需要的执行模块及短用法参考并入现有PPT Agent；不接入答辩演练、独立AI预审工作流及HTML放映/动画作为默认交付要求。

上游完整插件要求DSH>=0.2.1-rc.3，本工作区锁定0.1.5-rc.3。因此优先使用不依赖宿主插件ABI的生成模块，经本项目原生工具注册接入；不为本次吸收升级公共DSH核心。源码依赖及第三方依赖许可在实际引入时一起核查。

按项目固定一种源稿权威格式：

- `native_json`：新引擎支持的标准图文/表格/图表稿，以版本化JSON工程为源；默认尝试这一条简洁路径。
- `managed_svg`：现有复杂科研图、特殊版式或新引擎无法表达的内容，保留现有制作路线。
- `imported_pptx`：用户已有PPTX，小幅文字/字号/对齐修改沿现有`edit_ppt_native`；复杂重排沿既有能力。

一个稿件不在三种源稿之间来回自动转换。上游JSON编辑不导入任意外部PPTX，也不回收Office手工修改；检测到外部文件变化时保留原件，按用户意图继续原生编辑或另存工程副本。第一版不做任意PPTX转新JSON工程。

## 三、先收敛制作与改页路径

### 1. 模型只提交内容计划或语义patch

建议新增两个薄工具入口，名称在实现时与现有表统一：

- `build_ppt`：输入整稿内容计划（inline JSON，或本会话计划文件及版本）、主题、目标页数及是否严格页数；返回项目ID、revision、稳定页面ID、当前交付文件。
- `patch_ppt`：输入项目ID、expected_revision、目标页面ID和变化字段；返回新revision、影响页面和当前交付文件。支持将同一轮的多页反馈合为一次操作。

计划保留标题、正文、图件、原始数值、来源ID和可选文字备注；不要求模型填写像素坐标、字体文件路径或输出文件名。仅允许声明的内容/布局参数，不能提交任意脚本。现有页面SHA协议继续服务旧稿，新JSON工程使用revision，不把整数revision硬塞进当前仅接受64位SHA的学习协议。

### 2. 执行层直接接续固定操作

`build_ppt/patch_ppt`内部复用现有交付逻辑，完成资源准备、生成、保存、导出、实际PDF/PNG渲染及回执绑定。模型不必再逐个安排这些固定操作；这部分明确记作工程收益。

交付回执同时绑定项目revision、源稿摘要和最终PPTX/预览摘要。复用同版本已经通过的机械检查和预览；状态不变时不再安排模型检查。需要内容/视觉判断时向当前模型返回具体页面和具体问题，避免再读整份技能说明。Judge不作为下载前置条件。

不承诺第一版只渲染变化页：上游编辑会重新生成整套成品，Office可能仍需整稿渲染。先减少模型调用，增量渲染只在真实开支证明值得做后实现。

### 3. 组件准入和失败处理

选择前检查实际支持的页型、字体、颜色/对比、文字容量、图片格式、图表数据、页数及依赖。模型在本来就需要的内容规划中选择表达方式，不为选引擎再增加一次模型请求或Embedding服务。

- 能力明显不适用时，直接选择现有路线；不先调用、看坏预览、再整稿重做。
- 选定路径后继续使用当前项目及成功页面。只针对明确缺陷修改，不因主观建议重建全稿。
- 参数/版本错误返回具体字段和当前版本；传入的revision=0必须作为有效版本处理。
- 相同缺陷没有改善时停止原修复循环，至多进行一次适用的已验证修复，再局部回退；保留当前有效结果与全部失败成本。
- 整体后端回退只在安全提交前或明确的未完成状态发生，复用原内容计划和素材；不把旧稿/不完整稿冒充满足全部要求的新成果。

统一适配Skill中的页数与内容规则：上游5–12页大纲、3–60页门禁、1–120页工具范围不能同时照搬。按实际后端能力和本轮要求预检；超限返回具体问题或选择旧路线。长表自动分页后的页数必须核对；不静默截断单元格或删除科学信息来凑页数。对比度/损坏文件等机械错误与“标题建议更短”等软建议分开，软建议不反复阻断交付。

## 四、RSI具体学什么

正常使用 → 保存不可变轨迹 → 从高成本重复片段发现候选 → 构造参数化操作 → 独立执行认证 → 后继实际采用 → 晋级/修正/停用。

### 工程能力与学得能力分开

上游现成的生成器、分页器、工程patch，以及我们固定接续的导出流程，都是共同工程底座，不直接登记为学得Motif。已在一次函数调用内执行的步骤不产生虚构的“跳过模型调用”计数。不能为制造Motif故意拆成更多模型工具调用。

第一批只从正常任务中仍需模型反复安排的片段选择：

1. **数据到页面的重复绑定**：同类来源字段如何对应指标、表格/图表和页面；新数据来后如何更新受影响位置。科学含义、相关性和来源选择仍由模型确认。
2. **重复修订的参数化操作**：从反馈后的真实修改归纳目标页选择、字段映射、版本传递和依赖刷新。先选系统现有固定patch尚不能覆盖、且确实消耗模型往返的部分。
3. **明确失败→有效修复**：由工具的具体错误及成功修复学习适用条件，例如表格容量导致的拆分和页面关联更新；不学习反复猜字体/DPI等无改善诊断。

若“生成/改页→渲染→交付”尚有未被固定底座接管的重复调用，可由真实轨迹学习连续绑定；已经自动接管的部分不再单独宣称RSI收益。没有剩余模型工作可替代时，不为候选数量强行生成工具。

### 轨迹粒度与最小协议扩展

外层保留现有真实工具事件、LLM请求、原始用量和失败。引擎内部可记录必要的阶段/依赖事件，用于定位开支和失败，但标记为执行层内部事件，模型调用节省计数为0。不把完整用户内容写入公共学习记录。

当前`ppt_write_learning.py`及`ppt_write_runtime.ts`围绕逐页写入、页面SHA与导出绑定；不能只添加一个Skill名称就学会batch/revision工程。

实施时复用现有发现、Builder、认证、`executePptOperations`解释执行和后台调度。只有实际轨迹暴露出值得编译的整稿/patch片段时，增加有限的deck-operation IR分支，表达已注册操作、参数来源、结果绑定、版本类型及停止条件；不另造通用工作流平台，不允许候选指定任意代码或任意工具。旧页面IR与证书保留。

候选先进行类型/版本及独立执行认证，允许适用范围内试用；质量、后继采用和费用证据用于之后晋级，不再用缺少配对成本数据阻止收集正常学习材料。后续反例修正适用范围或停用，不能回写旧失败。固定底座内已有的行为不得作为“学习新增”重复晋级。

## 五、预计修改模块

以下均为拟修改位置，不代表代码已经完成。

|模块|最小改动|
|---|---|
|`scenarios/ppt_master/third_party/`或固定依赖目录|保存选用源模块、准确版本与许可；避免复制整套前端/模型评审模块。|
|拟新增`src/adapters/ppt_deck_engine.ts`|懒加载引擎、能力预检、计划及patch转换；隔离上游接口差异。|
|拟新增`src/adapters/ppt_deck_tool.ts`|两个薄工具入口，调用现有执行/交付接口，记录revision及稳定页面ID。|
|`ppt_delivery_pipeline.ts`与`ppt_execution.ts`|识别项目源类型，适配已有PPTX导出与预览回执，保持统一收尾/取消语义。|
|`ppt_authoring.ts`、`ppt_workflow_host.ts`|保护已采用页面，新增宿主能力按需提供；旧宿主不因未安装新引擎而整体失效。|
|`ppt_skill_opportunities.py`、`skill-sources.json`及短适配参考|登记审阅后的参考，指导候选搜索，不用Skill文本生成固定执行DAG。|
|`ppt_workflow_learning.py`、`ppt_write_learning.py`|筛选实际高成本片段；必要时增加deck/patch绑定发现，复用现有构造及失败历史。|
|`ppt_workflow_runtime.ts`及现有认证入口|为已发现的最小新IR分支增加运行校验/重放，执行仍通过现有宿主。|
|`harless_ppt_learning.ts`与现有Judge worker|沿既有独立后台运行；不新增前台等待或第二套费用账本。|

桌面侧不新增界面、不升级整体架构。Node模块本地运行，按既有宿主获取字体/Office/文件权限；避免硬编码Linux路径或依赖Bash来编排新引擎。学习可使用可选本地Python或既有服务端编译能力，不把Python安装变成普通生成的新启动条件。Windows/Mac分别验收文件路径、字体和Office；Linux或浏览器测试不能代替Mac实机。

## 六、实施顺序与最小验收

|阶段|实施与验收|费用/失败处理|
|---|---|---|
|P0：引擎吸收与整稿生成|固定上游版本；不接完整插件；一份混合文字、表格、图片、原生图表的内容计划可生成可编辑PPTX并经现有Office导出PDF/PNG。核对数字、表格末行及页数。|优先免费真实工具验收；不通过时停在适配层，不覆盖旧后端。|
|P1：同稿patch与稳定交付|指定页修改；验证稳定ID、非目标页内容/对象/备注、revision=0、冲突、原件保留、原子保存失败和重启恢复；同版本不重复检查。|实际必要的渲染保留；不为此扩跑15题。|
|P2：正常轨迹进入学习|确认每个节点来源和真实LLM请求；只有符合重复条件的片段才进入现有构造/认证。新能力必须在后继真正调用并进入交付。|学习/认证单列；没有候选时保留结果，不手工制造Motif。|
|P3：一组小对照|共同引擎无RSI与共同引擎+冻结学得能力，覆盖一次生成及同会话改页；相同来源/模型/提示前缀/工具顺序/预算/质量标准。|仅一组，不因负例补题或扩跑；Judge费用单列。|

必要的学习/认证材料按来源独立：先复用已有材料定位高成本片段，旧工具的成功轨迹不能冒充新引擎的执行认证。新片段可从两个正常独立任务归纳，并以第三来源做实际工具/Office认证；认证材料用于纠正后不再当最终留出。独立后继对照使用另一来源。若现有轨迹没有新工具的有效调用，需要补最少的正常学习任务，不能改写旧调用名称制造训练数据。

费用不在未取得新引擎运行数据前承诺美元数。默认先完成免费适配和现有材料分析；真实材料和对照开始前，按当时实际模型/路由及既有账本给出本批估费，持续授权及用户指定预算均保留。可计量制作、失败恢复、学习/认证和Judge分账，不清零累计账本。

对照口径：

- `B0`：当前PPT152，不含新增引擎。已有成绩仅作历史参考；只有需要量化引擎自身收益时再做同条件B0。
- `B1`：吸收引擎后的共同底座，关闭学得能力。
- `O`：与B1相同底座，启用冻结的RSI能力。首轮只跑B1/O，避免将工程吸收收益算给RSI。

成功标准：两侧满足相同交付及内容质量要求，修改只影响指定内容；O的学得操作真实进入最终稿，确实替代原模型决策，完整制作请求与可信口径费用均下降。请求数、缓存/未缓存输入、输出、重试、恢复、耗时和人工修订一并记录。上游币种/单位不明仍标未知，不能只因请求减少宣布费用下降。单组通过只支持这一类观察，不称普遍稳定降费。

保留失败和基线版本；若B1已消除了全部相应模型往返，就保留工程收益，不再为该片段声称RSI增量。若O试用后弃用/恢复更贵，停止推广该候选，依据原轨迹修正准入或参数，先不扩展更多候选。
