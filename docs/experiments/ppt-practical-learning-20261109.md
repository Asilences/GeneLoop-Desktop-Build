## 到底放宽了什么

1. 不再用相同提示词否决不同材料与会话的页面学习，来源/决定重复仍不冒充独立支持。两份来源就持久化发现的候选，不等第三份才开始发现；第三份记录可用于后续绑定重放。
2. 原严格源稿比较保留作诊断。仅因源稿差异或设计预检被拒的页面程序，可以对同一代码做零模型`functional_trial_v1`检查；实际渲染/隔离执行通过即可试用，标明`quality_deferred=true`，`source_equivalent`如实为false。其他场景的源等价要求不变。
3. 使用之前真实失败的程序验证了此通道：它保留错误副标题，仍能作为功能试用通过，且错误文字/源保真失败完整保留。因为其缺陷已知，未将它覆盖到当前可用组件上。这个检查证明标准实际放宽，不是只改状态名字；没有把试用当质量通过。
4. 写页流程本来已经在第三个正常决定中观察重放，发布器却排除了全部`observed_page_write_delivery`，强制再过一个不适合所有参数形态/单页修订的原生认证入口。现允许按运行时本就支持的`independent_observed_write_binding_replay`进入probation，标明后继效果待验证。流程不是按Skill文字或人工DAG生成。
5. 后续改页只挖掘`trace_start_index`之后的本轮操作；失败经验也按该边界采集，不把继承的旧失败再归因当前一轮。原完整事件和哈希不裁剪。

先试用不等于可任意运行外部代码：账号/原件隔离、受限代码、输入输出边界、不可读文件与当前版本检查继续保留。产品交付仍实际导出PPTX和预览；语义质量与成本由使用结果提供证据。原有负反馈、失败回退与停用路径继续适用。新增的只是候选试用入口，不另建RSI框架。
