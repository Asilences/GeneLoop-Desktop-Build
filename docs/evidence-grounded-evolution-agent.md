## 实现什么、为什么、怎么实现

1. 新增薄适配模块 `capability_evolution_agent.py`。由可信场景检查器提取执行/构造事实，按 scope、关联能力版本、问题关系分组。重试使用同一来源指纹，不能增加独立任务数。选择一个至少两份独立来源支持的问题，保留成功、失败、反例与未知费用；单例只记录为假设。原始引用和完整索引保存在私有目录。
2. 默认模型上下文只含能力接口、局部步骤及少量证据摘录，不含实现源码或完整历史。明确上下文容量与省略索引；不可通过截断丢掉“存在失败/反例”的事实。超过容量拒绝请求或缩小代表样本，不静默裁剪原始记录。需要更多材料时返回证据不足，下一次显式研究运行可调整选材；本轮不增加工具驱动多轮检索。
3. 复用 `capability_goal_proposal.py` 的 Harness 请求、原成本归属与落盘逻辑，增加可复用单次结构化提案接缝。固定 Evolution Prompt 要求候选说明剩余负担、来源、适用条件、后继行为、验证要求及失效条件；最多两个候选。模型输出没有认证/权限效力。
4. 边界候选交已有 `evolve_abstraction`：训练区域来自实际图，留出区域由宿主冻结，模型看不到留出答案。能力/构造候选交宿主审查和原 Builder。无法表达的策略标为 pending。不得仅保存反思后宣称闭环。
5. 论文隔离验收沿用原 Script Runtime、Store、冻结检查器与后继任务。逐项报告 proposed、compiled、published、actually used。发现证据与独立评价严格分开；完整生成/修复/验证支出与历史基线分开记录，无法公平对照就不报告净收益。

## 范围与运行约束

- 默认关闭，单次离线问题；不做前端、常驻后台、跨用户共享或自动资源再投资。
- 每次研究配置显式有限费用和实际请求上限，沿原累计账本；请求发出前归属固定。
- 真实研究使用服务器 DeepSeek `deepseek-flash`、`reasoning_effort=off`、输出容量393216。每个显式单次批次最多 USD3、1次请求；边界编译及原论文验收不调用模型。修复后的另一次批次须保留原结果并重新说明配置，不能自动重试。未知费用保留 null，超时/失败不重置预算。
- 不预写 D，不强制调用 C，不改变原始实验资料。成功历史、失败、no_change 都保留。

## 验收顺序

先检查证据来源/独立性、上下文上限、候选越权、留出隔离与关闭开关；再检查原 Builder/边界入口接线及真实后继行为。单元诊断不替代模型验收。

真实批次必须保存输入来源哈希、能力版本、Prompt、模型原答、原请求账本引用、候选决策、原认证/执行回执及失败。模型未提出可执行候选时如实记录，不以人工候选补成功。

回归包括相关 Python/Node、原 Motif 与 RSI 检查；共享提案传输改变后运行全量回归。交付独立 PR、实验记录与主线交接，分别说明实现状态、实际观测与研究边界。

## 已实现与真实运行后的收敛

- 模型外发上下文使用单独的匿名结构视图：不包含原任务名、路径、代码、输入输出、字面值或描述/示例。完整私有索引仍逐项校验。接口字段名保留语义，原认证仍使用完整契约。
- 实际调用图明确标注 `runtime_internal`，显示它已被哪些能力封装；运行步骤数不等于模型决策数。缺少计量时 `model_decision_count` 与节点费用均未知。
- 可执行边界走原学习器、Store 与 followup；普通新能力／可表达的构造方式提供 `construction_handler`，要求可信宿主将候选转换为带原验收计划的正常 job，再调用原 `run_improvement`。没有这种宿主准入就 pending。论文单次 CLI 当前只配置边界路径，未声称任意新目标都有自动验收器。
- 原始观察记录可由可信场景 inspector 扩展；当前内置读取有文件版本证据的 Capability 图，包含 `role=builder`。不会凭不含费用的 Runtime 回执伪造构造成本或语义错误原因。
- 完成两轮真实提案：首次建议重复封装已有组合能力；修正容器覆盖信息后返回 `no_change`。没有真实新能力认证/后继采用，也没有净收益结论。详情见[实验记录](experiments/evidence-evolution-20261104.md)。这轮成果是有界证据提案与既有执行机制接通；真实有效演化仍待具有剩余负担证据的任务流验证。
