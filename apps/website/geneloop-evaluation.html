GeneLoop: Evaluation & Methodology

Type: Technical Report

摘要
本报告记录 GeneLoop 在真实任务批次中的评测方法、配对实验结果、真实复用核验与学习开销核算。在相同模型、对称工具与独立自动验收条件下，我们在论文书目核查（50 题）与程序化视频剪辑（45 题）两个场景中，分别衡量任务执行阶段的效率与交付质量，以及计入后置学习与认证成本后的净时间收益。关于 GeneLoop 的研究动机与核心思想，请参阅 Launch Article。

1. Overview

本评测旨在在相同语言模型与底层工具条件下，系统评估 GeneLoop 的在线能力学习机制（Motif）能否产生可核验的实际程序复用，并在不降低交付质量的前提下改善执行效率，同时如实核算能力学习与认证带来的额外开销。

为避免将局部执行收益与系统整体开销混淆，本文严格区分以下三个阶段与概念：

  • Task Execution（任务执行阶段）：从任务启动到交付完成的全部在线过程，包含模型调用、工具执行、代码运行、视频渲染、任务内核验及失败重试。
  • Capability Learning（能力学习阶段）：任务交付之后触发的离线轨迹提取、程序参数化、独立认证及版本化能力库发布。
  • Verified Reuse（经核实的实际复用）：并非仅依据检索命中或程序入库，而是通过底层执行日志或交付产物哈希回执确认学出程序在后继任务中真实参与了计算或交付。

2. Evaluation Setup

对照关系与对称原则
每个场景均设置 Baseline 与 GeneLoop 两个实验臂。两侧使用相同的语言模型（deepseek-v4.1-flash，关闭思考请求配置）、相同的输出与时长上限（论文 8,192 tokens / 300 秒；视频 6,000 tokens / 900 秒）、相同的执行环境以及对称的底层工具集（论文两侧均提供完整终端与 44 项工具；视频两侧共享源码写入与渲染融合工具及源画面比对工具）。Baseline 臂同样可以自由编写脚本或源码完成任务，但不加载、不学习在线生成的 Motif 能力库。

配对任务与在线学习流
实验采用固定任务清单的配对设计，两臂面对完全相同的输入文件与题面要求（视频主批同时平衡两臂先跑顺序）。在 GeneLoop 臂中，任务按顺序依次执行：每次任务开始时锁定当前已发布的能力库快照，任务完成后将合格轨迹送入后置学习流程，通过认证的新能力进入下一版本库，供后续任务自主选择与调用。运行时回放产生的轨迹不充当独立正常样本自证。

Motif 认证与独立任务验收的分离
本评测将 Motif 认证 与 最终任务验收 严格区分为两个独立过程。前者发生在能力上架之前，在隔离环境中检验参数化程序能否在原输入上等价复现并在预设跨输入测试中满足行为边界；后者发生在每次任务交付之后，由独立验收程序依据客观标准判定交付是否合格（论文场景使用独立 bibtexparser 1.4.3 与条目头计数核对全部五项核心 JSON 字段并校验源文件完整性；视频场景核验全片解码、分辨率、帧率、帧数、指定源帧区域误差、音频窗口电平与波形一致性，并辅以绑定成片哈希的固定选帧审阅）。

统计指标与成本边界
除验收通过数与配对交付中位用时外，报告分别统计任务执行阶段的累计时间、模型请求数与已知模型估费，并单列后置学习的模型请求、估费与计算时间。主跑汇总保留所有上游超时、传输中断与额度失败，不筛选剔除失败尝试。模型估费仅依据已记录的可计价用量按固定代理单价估算，不代表供应商实际账单，也不涵盖本地 CPU、渲染及认证所需的完整硬件货币成本。

4. Verified Reuse & Learning Overhead

4.1 Verified Reuse

在 Agent 自进化评测中，检索命中（候选能力被展示给模型）、程序入库（候选通过认证发布）与实际复用（能力在后继任务中被真实执行并贡献于交付）是三个性质完全不同的事件。仅报告程序入库数量或命中次数，无法证明系统的执行路径确实发生了改变。

本评测依据两个场景的产物特征，采用两种强度不同的核验标准，且不将二者混作同一个指标：

  • 论文书目核查（执行级证据）：核查运行时审计日志中的真实执行回执，确认程序在当前文件指纹上实际运行并返回结果。在通过独立验收的 36 个交付中，有 25 个（25/36）实际执行过在线学出的程序。
  • 程序化视频剪辑（产物绑定级证据）：除检查程序调用记录外，进一步比对任务最终交付的源码文件与 MP4 视频哈希是否与在线学出程序的执行回执完全一致，以排除“先调用程序、后又手写源码覆盖”的虚假复用。在 45 个合格交付中，有 38 个（38/45）满足这一强一致条件。

5. Findings & Limitations

从当前两组评测中可以归纳出两项主要观察，以及两项明确的方法局限：

  1. 减少重复推理与临场写代码，与交付稳定性提升相一致：在论文核查与视频剪辑中，GeneLoop 的独立验收通过数均高于 Baseline（31/50 → 36/50 与 38/45 → 45/45），同时执行阶段的模型请求分别下降 33.8% 与 21.1%。这一现象与减少临时脚本编写、语法调试及返工的机制相一致。由于缺少配对统计显著性检验，本文不对通过率差异作统计学显著性宣称。
  2. 收益幅度受限于任务固有的不可省略计算：尽管两场景累计执行时间降幅接近（−21.7% 与 −20.0%），但双方均通过时的单题交付中位时间降幅差异明显（论文 −34.8%，视频 −11.1%）。论文任务的瓶颈主要集中在模型串行编写与调试脚本的往返等待；而在视频任务中，即便复用已学程序减少了渲染次数（75 → 51）与模型往返，新参数下的实际视频编码渲染与画面核验依然构成难以跳过的物理时间下限。
  3. 程序认证不等于普遍语义正确性，且学习摊销仍有待长程验证：独立认证只能验证程序在源输入及预设跨输入测试下的确定性与边界行为，无法保证对一切未见输入格式都语义完备，因此模型仍须承担冲突诊断与最终判断。同时，学习与认证具有明确的前置成本（如论文场景 1,502.4 秒的本地认证开销使净时间降幅从 21.7% 收敛至约 5.8%）；在任务分布更稀疏、复用率更低的真实工作流中，能力学习开销能否有效摊销仍需进一步检验。最后，当前实验验证的是效率驱动的在线能力复用，并不构成对 Recursive Self-Improvement 的实证证明——后者仍是下一阶段的研究目标。
